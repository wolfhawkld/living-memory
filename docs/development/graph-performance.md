# 固定合成图谱性能采样

开发版本的独立入口为 `/performance`，例如服务运行于默认地址时打开 `http://127.0.0.1:4317/performance`。页面直接使用确定的 300 个合成节点、1000 条唯一关系和初始布局，不经过账号、实例或学习 API，也不加载私人知识库。点选与布局变化只在本页内存中保留。

## 操作

选择 3D／2D、发光开关、标准／节能档和深浅主题，然后手动开始：

| 方式 | 每轮预热 | 每轮正式采样 | 轮数 |
| --- | --- | --- | --- |
| 快速采样 | 2 秒 | 10 秒 | 3 |
| 完整采样 | 2 秒 | 30 秒 | 10 |

采样不会在后台自动开始。运行期间配置锁定，可以停止；图谱仍允许手动旋转、缩放和点击节点。工具不判断交互次数，也不把人工操作完成当成自动验收。为了比较不同配置，应保持窗口尺寸和操作方式大致一致，分别导出报告。

每轮结束会销毁当前图谱，再创建新实例。表格及 JSON 记录销毁前、销毁后和重建后的资源对象快照及 Canvas 数量。停止、切换到后台、图谱暂停、WebGL 上下文丢失或卸载，会把正在进行的采样标记为未完成；已有报告保留。尚未形成样本时不编造结果。

## 指标含义

提交频率由当前图谱实例的真实 `composer.render` 正常完成次数与实际采样时长计算，不使用 `requestAnimationFrame` 回调数估算。CPU 提交耗时是这次主线程调用的墙钟耗时，可能包含驱动同步等待；它没有测量 GPU 内部执行时间。调用抛错不计为正常完成。

采样期关闭 renderer 的自动逐 pass 重置，在每次 composer 调用前清零计数，因此 draw calls、三角形、点和线覆盖该次 composer 的各个 pass；采样结束恢复原设置。报告提供提交间隔、CPU 耗时和绘制计数的 p50／p95，以及预期时间和实际计时时间。中断样本不伪装成零帧率的完整结果。

G／T／P 分别是 `renderer.info` 中几何体、纹理和程序的对象数量。它们不是显存字节数，也不能单独证明没有 GPU 泄漏。销毁后快照和重复重建帮助定位资源生命周期问题，真实设备的驱动、GPU 内存及视觉效果仍需独立观察。

每份报告包含视图、主题、渲染档位、光效、DPR、窗口和 Canvas 尺寸等上下文。报告不包含私人知识正文、账号、凭据或原始 User-Agent。测试期间窗口尺寸或设备环境不同，会限制两份数字的可比性。

## 导出与验证边界

「导出采样 JSON」保存 `format: living-memory-performance-benchmark`、`version: 1`，包括合成数据标识、固定规模及每轮采样／资源快照。单次探针报告的格式为 `living-memory-graph-performance`。这些文件用于排查渲染与生命周期，不属于学习备份、活动记录或[完整实例迁移](instance-migration.md)格式。

纯函数和注入式测试核对实际 render 计数、异常保留、分位数、停止与清理、合成图关系唯一性及端点有效性；页面 SSR 只检查默认不自动运行和入口配置。本轮最终自动回归进行中，结果见 [develop CI](https://github.com/wolfhawkld/living-memory/actions/workflows/check.yml?query=branch%3Adevelop)，目标设备验收单独保留。当前没有凭这些检查宣称已经采到本人桌面的 GPU 性能、通过全部视觉验收或验证长期记忆收益。

实现入口为[探针](../../src/web/graph-performance.ts)、[合成数据](../../src/web/performance-fixture.ts)和[手动采样页](../../src/web/PerformanceBenchmark.tsx)。实际知识查询与复习仍使用[查阅记录](activity-tracking.md)和原学习流程，性能页面不向其中写入事件。
