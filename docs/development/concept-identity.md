# 概念改名与移动后的历史衔接

更新：2026-09-27。对应 LM-005 的人工身份衔接子集。

## 使用

真实记录模式顶部新增「历史衔接」。此入口用于概念文件改名或移动后，将新路径上的节点与原来的学习历史对应起来。

1. 先同步待写入记录，并继续或结束未完成的复习。
2. 在知识库中改名或移动 Markdown 文件，打开「历史衔接」。系统刷新知识源，列出缺少来源文件的旧概念。
3. 选择旧概念，再搜索、选择当前的新节点。版本相同的候选优先排列，但不会自动选择或绑定。
4. 点击「预览绑定影响」，核对新旧路径、内容版本、历史数量和布局处理方式。
5. 勾选确认是同一概念，提交绑定。成功后沿用旧节点 ID，重新读取图谱、布局与复习安排，并定位该节点。

只改正文标题而不改文件路径时，ID 本身不变，无需衔接。内容变更仍按现有来源版本规则处理。

## 保留什么

- 重温、回忆观察、长期保持、应用/总结的事件 ID、原发生时间、记录时间、来源版本和冻结指标均不改写。
- 单纯移动且内容版本相同时，原时间起点继续生效；衔接不会产生一次“今天重温”。
- 内容版本不同时，保留旧证据，当前时间起点按已有版本规则显示待确认。已经人工设置的长期保持仍有效，只有手工解除才恢复衰减。
- 原概念的重点/暂缓安排保留。原布局优先；没有原布局时采用新节点布局，并清理新节点的临时布局键。
- 后续查询、节点详情、CLI 与学习记录接口统一使用投影后的稳定 ID。连续移动可以再次确认，新路径会继续指向原身份。

## 冲突和一致性

不会按名称相似度自动合并。目标已经有学习事件、非默认复习安排或另一套稳定身份时，阻止绑定，不混合两套学习历史。

若旧文件和已绑定的新文件同时存在，多个文件会指向同一身份。系统暂时隐藏这些冲突节点及连线，在知识源诊断中列出路径；学习数据保留。核对重复文件并在知识库中处理后刷新即可。

`GET /api/identities` 返回当前账号的旧概念、候选与绑定记录；预览、提交分别为 `POST /api/identities/preview`、`POST /api/identities/commit`，要求当前登录会话、写入令牌及知识空间标识。预览与提交都会重新扫描来源，提交在事务内校验预览；文件、学习记录或布局变化会要求重新预览。

每次确认使用固定 operationId，服务端持久化回执。响应丢失后可以重试同一请求，不重复绑定或备份。绑定表和概念元数据目录均按私人知识空间隔离。

## 备份与恢复

写入前备份当前账号的学习数据到数据库目录下的 `identity-backups/<空间摘要>/<文件>.json`，文件权限为 600。备份失败则不写入；数据库失败则事务回滚。界面成功回执包含备份标识。

学习数据导出附带 `identityBindings` 审计信息。导入文件中的绑定信息不具有授权作用，不会自动创建身份对应关系。本机已确认的历史路径可以参与同 ID 的备份校验；新机器仍遵守唯一「相对路径＋版本」匹配规则，可能重新分配本机概念 ID。完整保留本机绑定登记需要备份 SQLite 数据库；学习 JSON、知识库正文和附件是不同的备份范围。

## 当前边界与验证

- 此功能不改写 Markdown、双向链接或附件路径。文件移动后的引用应由知识库工具维护；这里会重映射已解析的图谱边端点。
- 不包含概念拆分、已学习节点合并、跨账号融合、撤销绑定界面或外部 frontmatter 稳定 ID 协议。
- 系统从本版本启动后开始记住概念路径。升级前已移动、且没有可恢复元数据的历史只能显示原 ID 与未知路径，需要人工核对。
- 当前稳定身份由本地登记维护；同时复制文件不等同于移动，路径复用为全新概念也需要后续更完整的身份管理。

自动检查使用临时数据库和合成知识源，覆盖版本变化、原历史不变、连续移动、冲突、事务、备份、重试和账号隔离。浏览器验证由用户进行，未对个人知识文件执行改名或绑定。

本轮 395 项 Node 测试、`npm run build` 和 `npm run check:theme-build` 通过。本地服务升级前已备份 SQLite 数据库；原有学习事件保持不变。未运行浏览器或 Playwright。
