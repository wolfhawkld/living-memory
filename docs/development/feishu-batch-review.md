# 飞书少量批次复习

日期：2026-10-07。对应 FEISHU-03B，承接[单条脑中回忆](feishu-single-review.md)。软件实现与全量回归已完成；连接器仍默认关闭，真实飞书应用、按钮往返和客户端体验待本人集中验收。本轮没有启用个人服务或发送真实消息。

## 开始与续做

| 入口 | 行为 |
| --- | --- |
| `知识 复习 3` / `知识 复习 5` | 从本人全局合格候选开始最多 3 / 5 项；已有未结束会话则恢复原会话 |
| 待复习卡片的「开始本轮 3 / 5 项」 | 使用该张原卡片的领域与 3 / 5 项设置；按钮只携带服务器动作标识，不能自行指定另一领域或数量 |
| `知识 复习` / 候选「回忆 N」 | 保留单条入口，不隐式改成批次；旧单条会话继续按原事件 ID 恢复 |
| `知识 继续复习` | 继续当前项，按原请求恢复待写操作；不替换队列 |
| `知识 暂停复习` | 保留当前项、阶段、页码和快照；暂停不重试写入 |
| `知识 结束复习` | 无待写操作时结束；有待写操作先恢复，收敛后需再次明确结束 |

批次由已有知识节点组成，不要求维护题库，不调用 LLM 出题或评分。候选复用重点、暂缓、长期保持排除、资料版本和每日预算。实际数量不超过启动时合格候选和服务端剩余预算，可能少于所请求的 3 / 5 项；没有候选时不创建空会话。

启动后固定领域、队列、顺序及每项资料版本。暂停、跨日、重启或继续不会补位、重排或把新候选加入本轮。聊天只看到服务端已保存的完成数，看不到浏览器待同步或草稿；日界仍采用 `LM_FEISHU_TIME_ZONE`，默认 UTC。

## 每项流程

正面只显示概念名和回忆引导。先在脑中解释，再主动查看资料；每项第一次翻卡才冻结观察时间、配置版本 / H 与对应资料版本的起点。未来项目尚未冻结，过去项目的快照不改写。正文使用安全文字分页，平台接收卡片不证明本人已经阅读。

核对后选择脑中回忆清楚、模糊或想不起，保存 `evidenceMode: mental` 的本人自报；没有伪造书面答案，也不计为独立成功或信心校准。自评保存后可单独点击「确认已重温，更新时间」。只有这项明确确认建立新的时间起点；不自动改 H 或解除长期保持，详见[证据边界](observation-evidence-mode.md)。

| 操作 | 学习记录与队列变化 |
| --- | --- |
| 自评保存后点击「下一条」 | 明确推进一个位置；最后一项显示「完成本轮」。自评保存本身不自动推进 |
| 「确认已重温，更新时间」 | 独立保存重温事件；无需为了进入下一项而确认重温 |
| 未保存自评时「跳过本条」 | 不生成观察或重温事件，不扣每日完成预算；已翻卡的快照仍保留在本轮状态中 |
| 正面资格发生变化时「跳过资格变化项」 | 本人明确略过该项，下一项仍来自原固定队列；不自动补位 |
| 「略过冲突项，继续」 | 保留终态冲突及已经保存的观察，明确推进；不覆盖失败请求或撤销已保存记录 |
| 暂停 / 继续 | 保留当前位置、快照和事件 ID；24 小时寿命不续期 |

首次翻卡前再次核对该项资格和剩余预算。本人在 Web 设置长期保持、暂缓、完成回忆、确认重温或减少预算后，原正面可能变得不合格；只有显式略过或结束，不自动替换。已翻卡的观察继续使用原冻结请求，不用后续安排重算它。

## 保存与中断

同一绑定与知识空间仍只允许一个未结束会话。24 小时绝对会话寿命与 30 分钟卡片寿命分开；卡片清理不删除队列或学习待写操作。

批次中的观察事件 ID 为 `feishu-observation:<sessionId>:<itemId>`，确认重温为 `feishu-review:<sessionId>:<itemId>`。同项同类只有一份不可改写请求；旧单条 ID 保持 `feishu-observation:<sessionId>` / `feishu-review:<sessionId>`。观察和重温仍写入原学习 Store，Web、CLI 和飞书共享记录。

点击回执、卡片消费、会话版本 / 位置更新及固定待写请求在同一账号库事务完成；每项日志分别结算，旧项的结算不推进或覆盖当前项。任一待写操作未收敛时，不能跳过、结束或插入另一份不同的写请求。

继续、重试或下一条操作遇到 pending 时，先恢复原请求；即使这次恢复成功，也停留在当前项，需本人再次点击下一条或结束。未知保存错误继续保持待写，确定性冲突保留终态；没有启动时自动扫描写入、隐式重新确认、自动补发新卡或后台队列推进。

资料变化或会话过期后，不再揭示旧正文、首次写入或推进队列。可查看保存状态、暂停或结束；原已提交事件只允许用精确 duplicate 核对收敛，不能把旧请求插入当前资料版本。来源变化不会把既有学习记录删除。账号停用、撤销重绑、访问版本变化、转发上下文或旧会话版本仍会拒绝操作。

## 结束汇总

汇总显示本轮实际数量、已保存脑中自评的清楚 / 模糊 / 想不起分布、明确确认重温数，分别显示自评未保存 / 重温未保存的冲突数，以及主动跳过、资格变化、冲突、提前结束和未开始的项目。

这些是本轮自报和操作状态，不是掌握率，也不是今日完成数。提前结束只标记当前未完成项，未来项保留未开始；不为未操作项目生成学习事件。若观察已保存而独立确认重温冲突，观察仍计为已保存，该项同时保留冲突标记。

## 迁移与备份

批次队列存于可选 `state.batch`；旧单条会话 JSON 不重写。启动按 `PRAGMA table_info` 检查操作表，在事务锁内复核后，为旧 `feishu_review_operations` 重建增加 `item_id NOT NULL`，唯一约束改为 `(session_id, item_id, kind)`。旧行的 item ID 取原 session ID，原事件 ID、原始 intent JSON、状态、时间及 session JSON 保持原样。外键检查保持开启，失败整事务回滚。

学习 JSON 仍为 `schemaVersion: 1`，不包含飞书会话、队列、操作日志、授权或知识正文。完整备份需同时保留匹配的账号库、学习库、私人数据目录与知识源。迁移后的账号库不保证可由旧 FEISHU-03A 程序写入；回退使用匹配版本的完整备份，不能只替换程序或用学习 JSON 代替账号库恢复。见[版本兼容](../releases/versioning-and-compatibility.md)与[升级恢复](../releases/upgrade-and-recovery.md)。
