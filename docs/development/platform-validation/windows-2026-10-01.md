## 隔离与复现

实际源码准备在 WSL 仓库中执行：

```bash
git archive --format=zip --output=/tmp/lm-windows-native-source-c8cd557.zip c8cd5572ea3057242f8328259b2c7fdb00655faa
```

归档不包含 `.git`、未跟踪数据或 `node_modules`。将它和已校验的 Node zip 解压到新建的 Windows TEMP 目录，再保存 helper 的副本。以下为等价复现命令；`$repo` 是已解压的 c8cd557 源码目录，`$helper` 是当前 develop 的 `windows-smoke.mjs`，二者路径仅作示例：

```powershell
$work = Join-Path ([IO.Path]::GetTempPath()) ('living-memory-wincheck-' + [guid]::NewGuid())
$repo = 'C:\path\to\clean-c8cd557-source'
$helper = 'C:\path\to\develop\docs\development\platform-validation\windows-smoke.mjs'
$nodeRoot = 'C:\path\to\node-v22.23.1-win-x64'
$node = Join-Path $nodeRoot 'node.exe'
$npmCli = Join-Path $nodeRoot 'node_modules\npm\bin\npm-cli.js'
$npmLogs = Join-Path $work 'npm-logs'
New-Item -ItemType Directory -Force -Path $npmLogs | Out-Null

@(Get-ChildItem Env: | Where-Object Name -match '^(LM_|NPM_CONFIG_)') |
  ForEach-Object { Remove-Item ('Env:' + $_.Name) }
$env:Path = (Split-Path $node -Parent) + ';' + $env:Path
$env:NPM_CONFIG_USERCONFIG = Join-Path $work 'npm-user.npmrc'
$env:NPM_CONFIG_GLOBALCONFIG = Join-Path $work 'npm-global.npmrc'
$env:NPM_CONFIG_CACHE = Join-Path $work 'npm-cache'
$env:NPM_CONFIG_REGISTRY = 'https://registry.npmjs.org/'
$env:NPM_CONFIG_AUDIT = 'false'
$env:NPM_CONFIG_FUND = 'false'
$env:NPM_CONFIG_UPDATE_NOTIFIER = 'false'
Set-Content $env:NPM_CONFIG_USERCONFIG ''
Set-Content $env:NPM_CONFIG_GLOBALCONFIG ''

$ci = Start-Process -FilePath $node `
  -ArgumentList @(('"' + $npmCli + '"'), 'ci') -WorkingDirectory $repo -Wait -PassThru `
  -RedirectStandardOutput (Join-Path $npmLogs 'npm-ci.stdout.log') `
  -RedirectStandardError (Join-Path $npmLogs 'npm-ci.stderr.log')
if ($ci.ExitCode -ne 0) { throw "npm ci failed: $($ci.ExitCode)" }

$build = Start-Process -FilePath $node `
  -ArgumentList @(('"' + $npmCli + '"'), 'run', 'build') -WorkingDirectory $repo -Wait -PassThru `
  -RedirectStandardOutput (Join-Path $npmLogs 'npm-build.stdout.log') `
  -RedirectStandardError (Join-Path $npmLogs 'npm-build.stderr.log')
if ($build.ExitCode -ne 0) { throw "npm run build failed: $($build.ExitCode)" }
```

实测安装和构建也是通过 `Start-Process` 执行 `node.exe npm-cli.js ci` / `node.exe npm-cli.js run build`，等价于便携运行时的 `npm ci` / `npm run build`；stdout/stderr 保存到隔离日志。准备完成后，以全新的 smoke 工作目录调用 helper；helper 自己用 `npm start`、loopback 空闲端口和 `process.execPath` 启动检查：

```powershell
$smokeRun = Join-Path $work 'smoke-run'
New-Item -ItemType Directory -Force -Path $smokeRun | Out-Null
& $node $helper $repo $smokeRun
if ($LASTEXITCODE -ne 0) { throw "Windows smoke failed: $LASTEXITCODE" }
Get-Content (Join-Path $smokeRun 'smoke-result.json')
```

入口参数必须是 `<native-source-dir> <fresh-run-dir>`。helper 清除继承的 `LM_*`，只在 `run-dir\data`、`run-dir\cli`、`run-dir\logs` 写入，使用仓库的公开 `fixtures\demo-kg`，创建随机合成管理员并读取自己的设备会话文件；口令、设备凭据和完整日志不写入公开报告。服务由 helper 自己的 `npm start` 子进程启动，停止时只对自己生成的 `cmd`/npm 进程树执行 `taskkill`，结果摘要写入 `smoke-result.json`。

## 停止、重启与保留

helper 用 `taskkill` 强制停止自己 spawn 的 `cmd`/npm 进程树，然后在相同隔离环境、相同 loopback 端口重启。重启后：

- admin 重新登录 HTTP 200；
- sourceId 保持一致，图谱仍为 16 concepts / 32 links；
- anchor 的 event ID 和上述 `occurredAt` 均保留；
- CLI 对同一 event 执行 `retry` 返回 `duplicate`，receipt 仍为 `succeeded`；
- 最终仍为 1 anchor、0 observations，没有新增记录。

最终停止后，另从本次 `server-restart.stdout.log` 读取测试端口，用 `TcpClient` 连接失败确认 `finalServiceStopped: true`；这项额外检查不在 helper 内置断言中。Ctrl+C 的优雅停止路径没有测试。

报告中的 PowerShell 示例通过原生 PowerShell 5.1 parser 检查；保存的 helper 与实际执行文件逐字节一致，Node 语法检查通过。完成后删除了本次新建的 Windows 验证临时目录，包括合成账号、设备凭据、数据与依赖；仅保留不含凭据的检查摘要用于整理报告。
