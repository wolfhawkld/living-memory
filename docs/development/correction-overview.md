# 知识修正待办总览

更新：2026-09-27。接续 LM-014 的人工修正跟进，把分散在不同概念、不同应用/总结记录中的建议集中为可定位的待办。

## 使用

1. 在真实学习记录、实时时间下打开「知识薄弱点总览」，切换到「知识修正待办」。
2. 默认查看「待跟进」，包含尚未处理的建议，以及曾确认纳入、但资料版本后来发生变化的建议。可按知识域、概念标题、概念 ID 或原记录 ID 搜索。
3. 状态筛选提供全部、待跟进、待处理、版本待复核、当前已纳入、暂不采用；计数随领域和搜索条件变化。列表每批显示 50 条，优先待跟进项，再按最近决定或原记录的发生时间排序。
4. 点击「定位原记录」，会切换领域、选中节点，并在学习历史中只显示指定的应用/总结。较早的记录也可直接定位，无须逐页翻找。
5. 正文仍保持折叠；主动展开后查看建议、使用原有人工复核功能。点击「查看全部学习历史」恢复普通时间线；存在未提交的复核说明时会先提示。

空待办不代表没有应用/总结记录；只有填写过非空「知识修正建议」的记录才进入此视图。原建议可以来自旧资料版本，仍保留待处理资格。

## 状态与记忆的边界

- 修正状态取自显式处理链，不因补记日期较新或较旧而重新排列决定。
- 「版本待复核」表示最近一次确认纳入时的版本与当前版本不同。原来的确认决定仍保留，系统不会自动新增「重新打开」事件。
- 「当前已纳入」表示本人曾针对当前资料版本确认纳入，不代表系统已核验内容正确，也不代表已经记住。
- 概念不在当前索引中的建议显示为整个知识空间的不可定位数量；不因领域筛选而归入某个领域，不静默算作已完成。
- 总览和跳转只显示概念、领域、时间、状态及版本等信息，不展示原建议、回答、业务场景或说明。主动展开历史正文仍沿用已有的资料曝光标记。
- 本项只读，不调用 LLM、不写 KG、不新增学习事件，也不改变重温起点、H、长期保持或复习安排。未同步记录不计入已保存待办。

## 接口与兼容

`GET /api/learning-overview` 增加 `corrections: { items, unavailableCount }`，使用当前账号的完整知识索引和学习记录，不受图谱显示数量限制。旧服务没有这个字段时，界面提示暂不支持，不把缺失字段当作零条记录。

`GET /api/concepts/:conceptId/history?applicationEventId=<id>` 定位同一知识空间、同一概念内的一条应用/总结，返回 `focusedApplicationEventId`、单条 `entries`、`total: 1` 和 `nextCursor: null`。不能与分页游标混用；格式不合法返回 400，不存在或不属于该概念返回 404。普通历史分页保持原样，未增加数据库表或迁移。

跳转前重新读取索引并核对知识空间、概念和资料版本；资料变化时要求刷新。加载器校验服务确实返回指定记录，切换概念、关闭任务或取消请求后丢弃迟到响应。
