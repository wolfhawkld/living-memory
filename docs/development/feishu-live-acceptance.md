## 2. 服务端配置

服务直接读取 `process.env`，**不会自动加载仓库中的 `.env` 文件**。由本人在实际启动服务的环境中配置以下变量；值不填入验收记录或仓库文档。

| 变量 | 所需值 / 检查 |
| --- | --- |
| `LM_FEISHU_ENABLED` | 真正启用时精确为 `1`；缺省或 `0` 关闭 |
| `LM_FEISHU_APP_ID` | 新专用应用 ID；符合 `cli_` 加 16 位十六进制字符 |
| `LM_FEISHU_APP_SECRET` | 新应用的服务端密钥，原样传给 SDK |
| `LM_FEISHU_TENANT_KEY` | 目标租户的 tenant key，与收到事件中的租户字段匹配；按下方官方路径获取，由本人配置实际值 |
| `LM_FEISHU_TIME_ZONE` | 建议按本人日期习惯配置 `Asia/Shanghai`；缺省 `UTC`，需与 Web 对照的日期一致 |

完整长度限制和固定配置错误码见[配置规则](feishu-connector.md#配置与启用条件)。保持现有账号模式，不设置 `LM_AUTH_MODE=local`；飞书绑定需要已登录的 Web 浏览器会话。

获取 tenant key：按官方[自建应用 tenant_access_token 接口](https://open.feishu.cn/document/server-docs/authentication-management/access-token/tenant_access_token_internal)取得新应用的 token，再使用它调用[获取企业信息](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/tenant-v2/tenant/query)的 `GET /open-apis/tenant/v2/tenant/query`，取响应 `data.tenant.tenant_key`。官方 SDK 的[请求定义](https://github.com/larksuite/oapi-sdk-go/blob/v3_main/service/tenant/v2/resource.go#L27)与[响应模型](https://github.com/larksuite/oapi-sdk-go/blob/v3_main/service/tenant/v2/model.go#L209)区分 `tenant_key` 和企业编号 `display_id`；此处需要前者，不填 token 或企业编号。实际初始化在本人配置 `tenant:tenant:readonly` 后已通过；token 未写入仓库或验收记录。

当前使用的消息应用权限为 `im:message.p2p_msg:readonly` 和 `im:message:send_as_bot`；初始化获取企业信息另需上述 `tenant:tenant:readonly`。权限名称与审批以平台当前后台为准。卡片按钮还需要单独配置回调：同一应用的「事件与回调 → 回调配置」选择使用长连接接收回调，添加新版 `card.action.trigger`（卡片回传交互），保存并发布包含变更的新版本。它与「事件配置」中的消息订阅是两处设置。官方[卡片回调说明](https://github.com/larksuite/cli/blob/main/skills/lark-im/references/lark-im-card-action-reply.md#setup-required)确认未启用时消费者也可能正常启动但收不到回调；启用后使用已有 WebSocket，不需要额外公开回调 URL。

启动时沿用既有 `LM_KG_ROOT`、`LM_DATA_DIR`、`LM_KG_LIMIT`、端口和账号目录。未指定知识根目录会使用仓库演示知识，未指定私人数据目录会使用 `data/local`；漏掉显示上限可能截断图中节点及连线，不能误当作个人数据丢失。成员使用其现有私人知识空间，不能借管理员身份代替成员绑定。运行方式见[首次运行](first-run.md)和[私人账号](private-accounts.md)。

实际启用由本人确认应用、事件接收归属和上述配置后进行；若已有服务运行，先核对它的启动环境及受控更新方式，避免另起进程竞争端口。仍保持桌面 `127.0.0.1` 访问与现有认证，不通过公开监听或放宽 CORS 完成此验收；飞书私聊长连接不要求手机能打开桌面网页。

## 3. 集中操作顺序

### A. 连接与本人绑定

1. 在桌面 Web 登录本次选定的账号，打开顶栏「飞书绑定」。确认服务日志出现 `Living Memory Feishu: connected`；Web 未绑定时应可生成确认指令。弹窗不直接展示 `connected` 状态文字。
2. 点击「生成飞书确认指令」，用本人飞书账号把**完整指令**发到新应用机器人的私聊；不手填 `openId`。
3. 在 Web 看到「已绑定飞书账号」。指令约 10 分钟内有效，且不超过发起浏览器会话寿命；过期需重新生成。绑定成功以 Web 状态为准，不依赖机器人另发确认消息。

`connected` 只说明 SDK 已报告连接就绪，不表示绑定、消息权限或按钮往返都已通过。若本人尚不能看到机器人或生成指令，先按下方分诊核对，完整规则见[账号绑定](feishu-account-binding.md)。

### B. 浏览与新卡往返

1. 私聊发送 `知识 卡片`，确认收到本人知识列表；再发送 `知识 卡片 领域`，选择一个已有领域。
2. 点击「阅读」及正文翻页，确认操作提示后出现**新卡**，长正文可读。搜索可发送 `知识 卡片 搜索 概率`，将关键词替换为自己已有的概念名或别名。
3. 对照 Web 的节点历史：只浏览、搜索、阅读和翻页，不应新增回忆或重温记录，不应改变时间起点。

正文在飞书中采用安全文字分页，图片、公式、Mermaid 和来源链接的原生展示不在本轮保证范围；按实际排版记录可读性。只在本人选定的私聊中操作，不以转发私人正文到群聊测试权限。

### C. 待复习候选

发送 `知识 待复习` 或 `知识 待复习 量=5`，核对领域、日期、时区、已落库完成数和剩余预算。需要域内候选时从领域入口选择，或发送 `知识 待复习 域="Math" 量=3`，其中目录域替换为领域列表给出的实际标识。

**没有候选不等于接入失败。** 没有时间起点、近期重温、人工长期保持、暂缓、来源版本不符、当天已完成或预算耗尽，都可能得到零项。先在 Web 核对安排和现有记录；不为凑出 3 / 5 项伪造历史学习日期、撤销长期保持或自动写测试起点。确实没有合格候选时，将下一组复习项目记为「未覆盖」，待真实学习后再测。刚确认重温的节点也不会立即进入较久未重温候选。

聊天只计算服务端已落库记录，看不到浏览器待同步项和草稿；比较两端时先核对各自日期和同步状态，见[候选规则](feishu-card-browsing.md#候选与记忆规则)。

### D. 单条 / 批次与 Web 核对

有合格候选时，先以一条真实知识核对保存语义，再按剩余候选执行小批次；不要求为了验收而重复练习同一概念。

| 操作 | 本人核对的结果 |
| --- | --- |
| 候选「回忆 N」或 `知识 复习` | 正面显示概念名和回忆引导，无正文、摘要或历史答案 |
| 先脑中解释，再点击「查看资料」 | 进入该概念正文；按刚才真实回忆选择清楚 / 模糊 / 想不起 |
| 保存脑中自评 | Web 对应节点新增脑中自报记录，无伪造原答；记忆时间起点尚未更新 |
| 确实完成重温后，另点「确认已重温，更新时间」 | Web 新增明确重温记录并更新起点；全局 H 和人工长期保持决定保持原值 |
| `知识 复习 3` / `知识 复习 5`，或候选卡「开始本轮 3 / 5 项」 | 全局命令从本人全库取项，候选按钮沿用该卡原领域；实际少于请求数时如实显示 |
| 「下一条」 / 最后一项「完成本轮」 | 显式推进；自评和重温保存本身不自动推进，不强迫确认重温 |
| 「跳过本条」 | 进入原队列下一条，未写该项自评 / 重温，不增加完成预算 |
| 「暂停复习」后发送 `知识 继续复习` | 恢复原队列、位置和已保存状态，不补位或重排 |
| 「结束复习」 | 汇总真实已保存自评、明确重温、跳过 / 资格变化 / 冲突和未开始数；不将自报分布当掌握率 |

可以分次完成，不为覆盖所有按钮而修改真实记忆判断。自评会计入当日已落库概念回忆数，应按真实表现操作。已完成概念不应被同日自动重复推荐；批次需要从剩余预算取项。具体流程和中断语义见[单条说明](feishu-single-review.md)与[批次说明](feishu-batch-review.md)。

### E. 安全地核对重复与恢复

只重点击本人已经处理过的同一张旧卡，核对 Web 没有重复事件；后续继续使用最新卡。未知发送结果不自动补发，无新卡时主动发送 `知识 继续复习` 查看复习状态，浏览入口则发送 `知识 卡片`。

遇到待保存状态时保留原请求，显式继续 / 重试；待写收敛前不能推进或结束，即使本次恢复成功也要再次明确操作。卡片 30 分钟到期不结束 24 小时会话；整批寿命从创建起计算，不因暂停、翻页或下一条续期。

转发上下文、其他账号、数据库故障、失控断线、来源变更和跨库崩溃已由隔离自动检查覆盖，不在私人数据上人为制造故障。真实使用若自然遇到这些情况，记录固定状态及脱敏现象，保持「尚未覆盖」与「已失败」的区别。

## 4. 固定状态与现象分诊

| 状态 / 现象 | 下一步核对 |
| --- | --- |
| `disabled` | 服务启动环境是否启用连接器；仓库 `.env` 不会自行生效 |
| `invalid-enabled` / `invalid-app-id` / `invalid-app-secret` / `invalid-tenant-key` / `invalid-time-zone` | 对照变量规则修正服务端配置；不把密钥或完整环境打印进验收记录 |
| `starting` / `reconnecting` / `error` | 等待就绪；核对固定错误码、网络、应用配置和事件接收归属，不把启动返回当连接成功 |
| `sdk-init-failed` / `sdk-start-failed` / `sdk-connection-error` | 根据实际阶段核对 SDK 启动环境或平台连接；固定码本身不能定位唯一原因 |
| Web 无法生成绑定指令 | 核对浏览器登录、账号模式及 `connected`；接口可能返回 `FEISHU_UNAVAILABLE` |
| Web 仍显示待确认 | 核对本人是否在正确机器人私聊发送完整、未过期指令，消息订阅和接收归属是否正确 |
| `card callback isn't configured for this app yet.` | 在回调配置单独启用长连接和 `card.action.trigger`，保存并发布；重新发送领域命令，点击新卡。已绑定无需重新绑定 |
| 有操作提示，但没有新卡 | 提示只确认接收；核对最新卡、绑定、卡片寿命、资料变化和投递状态，使用对应恢复命令 |
| 待复习为零项 | 先核对时间起点、安排、完成数和剩余预算，不当作权限或连接失败 |
| 自评已保存、重温未保存 | 两种记录独立；对照当前保存状态，不撤销已保存自评或重复生成事件 |

不复制 SDK 原始错误、正文、应用密钥、用户标识或绑定指令到公开 issue。排查时优先提供固定 code、步骤编号及预期 / 实际现象。
