# 逐概念学习历史

日期：2026-09-22。属于 LM-006/008/010 的后续子集，服务于时间基线的真实试用，不引入新的遗忘参数。

## 在页面中使用

1. 关闭“示例状态”，点击节点或搜索并选择概念。
2. 在右侧“学习历史”查看确认重温、估计补记与回忆观察。最新发生的事件排在前面；“记录于”保留实际写入时间，便于辨别补记或延迟同步。
3. 时间起点摘要标出当前使用的重温事件，即使该事件还不在已加载的历史页内。来源版本发生变化时保留旧历史，起点显示待确认，不回退到更早的匹配版本。
4. 观察显示当时的自评、资料曝光、Δt、D、H 和配置版本。点击“展开原始回答”才显示旧答案，同时标记本次已查看资料；这不会确认重温或改变曲线。
5. 历史较多时点击“加载更多历史”；失败可以重试。浏览器里尚未同步的学习记录只显示数量，成功同步后才进入服务端历史。

回忆任务期间整个历史面板卸载，旧答案不在页面 DOM 中。查看标记按知识源、概念和内容版本隔离；旧版未区分来源的会话标记不继承，缺少标记时保持“不确定”，不据此认定未看过资料。示例模式不请求真实历史；未来时间预览可以查看真实历史，但历史的当前起点始终以服务端真实时间判定。

## 读取接口

`GET /api/concepts/:conceptId/history?limit=20&cursor=…`

- 概念 ID 作为单个路径段编码；客户端发送 `x-lm-source-id` 核对当前知识源。
- `limit` 默认 20，允许 1～100 的整数。`cursor` 是返回的不透明游标，绑定来源与概念；不要自行构造或跨概念复用。
- 返回当前来源/概念/来源版本、真实 `asOf`、现有投影规则生成的 `state`、`entries`、总数 `total` 和 `nextCursor`。
- 每个 entry 区分 `anchor` 或 `observation`，保留事件原有字段；不返回写入请求载荷。观察数值来自存储，不使用今天的参数重算。
- 按发生时间（`occurredAt` / `observedAt`）、记录时间、事件 ID 依次倒序，使用游标分页。接口从数据库中按来源和概念查询，不下载全库导出后再筛选。
- 响应设为 `Cache-Control: no-store`。沿用 Host、Origin 与来源核对；读取不创建学习事件、不修改 H、不重置时间起点。

前端取消失效请求并校验响应来源/概念/版本。普通时间刷新保留已加载页；分页中发现记录总数变化会重读第一页，防止并发补记漏在游标之前。历史是实时读取，不提供跨请求的数据库快照事务。
