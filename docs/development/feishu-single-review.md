# 飞书单条脑中回忆与独立确认重温

日期：2026-10-07。对应 FEISHU-03A。复用默认关闭的[飞书连接器](feishu-connector.md)、[本人账号绑定](feishu-account-binding.md)及[待复习卡片](feishu-card-browsing.md)。本轮只做单条，不自动推进 3 / 5 条批次，不添加人工题库、LLM 出题或评分。软件实现与本轮回归已完成；真实应用、按钮往返和客户端体验仍待本人验收。

## 使用

本人机器人私聊发送 `知识 待复习`，点击候选的「回忆 N」开始单条；也可直接发送 `知识 复习`，选择当前全局首个合格候选。已有未结束会话时恢复该条，不覆盖原会话。

| 入口 | 行为 |
| --- | --- |
| `知识 复习` | 开始一条；已有会话则继续 |
| `知识 继续复习` | 恢复本人原会话，包括原自评待写请求 |
| `知识 暂停复习` | 暂停，不隐式重试学习写入 |
| `知识 结束复习` | 无待写操作时结束；有待写操作先尝试恢复，保存成功后需再次结束 |

正面只显示概念名和固定回忆引导，不传正文、摘要或历史答案。先在脑中尝试解释原理，再点击「查看资料」。正文沿用飞书安全文字分页，不保证公式、Mermaid、图片或附件的原生渲染。

核对后，选择「脑中回忆清楚 / 脑中回忆模糊 / 脑中想不起」保存本人自评。卡片分别显示自评和确认重温的保存状态；收到按钮提示不代表已保存，保存成功不代表后续新卡一定投递成功。

自评保存后才出现独立的「确认已重温，更新时间」。仅本人主动确认才建立新的重温起点。翻卡、翻页、暂停和自评均不等同重温；不自动改变全局半衰期 H，不解除本人固定的长期保持。

结束后可返回待复习查看。没有自动下一条、批次进度或跳过汇总，这些属于 FEISHU-03B。长目录域会减少重复导航按钮，但保留候选文字、首条阅读与回忆入口；保留的引用和返回范围不截断。

## 回忆证据

翻卡动作在显示正文前冻结观察时间、配置版本 / H 和当时对应资料版本的起点。暂停、重开服务、后续修改 H 或补记另一个历史起点，都不重算这份快照。

自评保存为 `evidenceMode: mental`、空原答和明确的脑中自报。先前资料接触条件为 `unknown`，不因本流程尚未翻卡就声称未曝光；后续正文投递也不回写先前的回忆条件。无事前信心预测，学习证据保持概念任务、未知提示条件和未验证结果。记录不计入独立场景成功或信心校准，见[作答方式边界](observation-evidence-mode.md)。

平台接收正文卡仅代表投递结果，不证明本人看过资料。自评按钮表达本人对先前回忆的报告；确认重温按钮表达本人主动确认。卡片所显示的时间状态仍是管理提示，不是实测记忆概率。

合格候选、重点 / 暂缓、长期保持排除及每日预算沿用原规则。已落库概念观察进入同一账号的每日完成数；日界使用 `LM_FEISHU_TIME_ZONE`，默认 UTC。聊天仍看不到浏览器未提交 / 待同步草稿。

首次翻卡前再核对本节点资格与剩余预算；若期间本人在 Web 设置长期保持、暂缓、重温、完成回忆或减少预算，则正面显示不再合格，不展示正文或生成新快照。这里只检查该节点资格，不因排名移出全局前五而拒绝。已翻卡的观察继续沿原冻结请求保存，不用后续安排重算它。

## 持久状态与恢复

`accounts.sqlite` 加法增加 `feishu_review_sessions` 和 `feishu_review_operations`。会话保存身份代际、来源指纹、单条阶段、页码、暂停标志、冻结快照及版本；待写操作仅保存固定学习请求和安全状态码，不保存知识正文、凭据、原消息或投递 outbox。

同一绑定和知识空间只有一个未结束会话。会话有 24 小时绝对寿命，与 30 分钟卡片寿命分开；卡片清理不会删除会话或待写操作。过期或资料变化时隐藏正文，展示原保存状态，允许结束；不能首次执行失效快照的学习写入。

点击领取、卡片消费、会话版本更新和固定待写请求在同一 Accounts 事务完成。随后写入现有学习 Store，再结算操作状态：

| 断点 | 本人继续 / 重试时的行为 |
| --- | --- |
| 待写请求已保存，学习库写失败 | 复用原事件 ID、参数、时间和请求，不生成替代记录 |
| 学习库已写，操作状态尚未结算 | 以原请求核对 Store 的精确 duplicate，确认相同事件后收敛状态 |
| 保存成功，新卡发送失败或结果未知 | 保存结果保留；新消息重建状态卡，不补发原投递请求 |
| 资料变化 / 会话过期且原事件尚未写入 | 标为未保存冲突；保留原请求供检查，不套到当前版本 |
| 资料变化 / 会话过期但原事件已写入 | 仅精确 duplicate 核对已存在事件，不展示旧正文或再插入旧事件 |

自评事件 ID 固定为 `feishu-observation:<sessionId>`，确认重温为 `feishu-review:<sessionId>`。同一条同一类只有一份不可改写请求；相同 ID 对应不同类型或载荷时保留冲突，不能仅凭 `hasEvent` 判断保存成功。

没有启动时自动扫描写入、后台投递重试或自动重新确认；恢复由本人的新命令 / 有效按钮触发。暂停不重试保存。待写未收敛时不能结束并丢弃它；发送结束命令可先恢复保存，再由本人再次结束。

## 身份、通知与备份

所有按钮仍只携带服务器生成的随机卡片 ID 和动作 ID。没有新增公开原始回调或匿名学习写入 HTTP 接口。学习写入前、卡片点击及实际发送前复核账号 UUID、启用状态、访问版本、绑定 UUID、app / tenant / openId、原私聊上下文、知识空间和资料指纹。

继续 / 暂停都会推进会话版本，即使新卡投递失败，旧会话按钮或等待 token 的旧正文也不能继续发送。撤销后重绑相同外部身份不能恢复旧会话。已投递到聊天历史的正文不在本项目可撤回范围内。

学习事件进入现有 Store，保存后通知 Web 重新读取，历史、时间状态及学习 JSON 使用同一份数据。新会话和待写 journal 不包含在学习 JSON 中；完整备份仍需匹配的账号库、学习库、私人数据目录和知识源，见[升级与恢复](../releases/upgrade-and-recovery.md)。部分数据库或不同备份时点的恢复不保证完整会话或去重；恢复时保持连接器关闭并先核对。

## 软件与人工验收

自动检查仅用临时合成知识、账号、SQLite 和假投递，不启用个人连接器、不发送真实消息、不重启个人服务、不做本地浏览器视觉验证。检查覆盖首卡隐藏内容、分页、冻结快照、独立确认、账号隔离、旧卡、迁移、断点恢复及冲突。

真实验收可集中核对：本人私聊进入待复习→回忆→翻页→自评→独立确认重温；暂停后重新继续；重复点旧卡；对照 Web 历史与时间起点。需先完成应用发布、consumer 归属、权限和真实 SDK 往返验证。软件检查不证明个人记忆收益或平台已经接入。

本轮全量 **799/799** 命名测试通过（新增 38 项），生产构建、8 项编译后主题场景与本地文档链接检查通过。实际固定 SDK / 合成私聊验证了成员自评及确认重温可从 Web 的历史导出 / 快照读取，管理员学习记录保持原样。审查补齐了翻卡资格、暂停恢复入口、未知错误保持待写、结束总结优先、账号库内来源指纹以及旧复习卡整体版本检查；均有相应回归。

最终架构审查通过，以上软件范围可按开发分支交付；真实平台与 FEISHU-03B 的未完成边界保持不变。
