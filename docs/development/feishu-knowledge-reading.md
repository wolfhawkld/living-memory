# 飞书知识列表与正文阅读

日期：2026-10-02。对应 NEXT-06 / FEISHU-02A，当前 `develop` 的文本浏览软件链。先在已有 Web 账号完成[本人飞书绑定](feishu-account-binding.md)，再通过机器人私聊查看本人知识。连接器仍[默认关闭](feishu-connector.md)，本轮未启用个人服务的飞书连接或发送真实消息；应用发布、权限、接收和投递的真实往返尚待验收。

## 使用方式

只处理本人发给机器人的私聊文本，以「知识」为前缀。群聊、机器人消息和无关内容不处理；未绑定、账号停用或绑定失效时不读取知识，也不回退到管理员或 CLI 身份。绑定确认仍使用原来的 `确认绑定 LM-…`，不改变其一次性规则。

| 指令 | 作用 |
| --- | --- |
| `知识` | 全部知识，按有效的距时间起点天数从大到小排序 |
| `知识 帮助` | 显示指令与只读规则 |
| `知识 领域`、`知识 领域 2` | 列出目录知识域及可复制的切换指令 |
| `知识 搜索 log-sum-exp` | 搜索名称或别名，支持大小写及兼容字符归一化 |
| `知识 列表 域="Math" 查="概率" 序=名称 页=1` | 组合领域、搜索、排序及页码；域以实际领域列表中的目录标识为准 |
| `知识 阅读 <节点引用>` | 阅读列表项给出的概念正文 |

参数值可用不含空格的裸字串，或 JSON 双引号字符串；未知参数、重复参数和错误语法显示帮助。命令最多 4096 字符，领域参数最多 512，查询最多 120，页码为 1～100000。阅读引用由当前账号概念 ID 的 SHA-256 前缀生成；发生短前缀冲突时使用完整摘要，不选择第一个匹配节点。

列表每页 5 个概念，领域每页最多 10 个，较长领域按消息大小自动减少当页条数。每条显示名称、目录域、时间状态、距起点时间和最近真实确认重温时间。无有效起点的节点放到时间排序末尾，估算起点明确标为估算，长期保持仍可查看。这是全部知识的排序，**尚未提供待复习推荐、重点 / 暂缓筛选或预算消费**。

每项附完整阅读指令，页尾附完整下一页指令。正文第二页起带资料版本摘要；若服务中资料已刷新且版本变化，要求重开第一页，不把旧分页套到新正文。该校验针对服务当前缓存，未刷新的磁盘变化不在检测范围内。

## 内容与记忆边界

使用本人知识源的全量索引，不受图谱展示节点上限限制，也不加载 Three.js 或图谱页面。正文按纯文本 Markdown 分页，保留后文；中文、emoji 不会从代理对中间切断。尖括号改为全角以免消息内容触发飞书文本标记；当前不渲染图片、公式和 Mermaid，不提供手机可访问本机 `127.0.0.1` 的承诺。

领域与列表可缩短显示标题和路径，但保留可复制的操作指令。正文每页最多 3000 UTF-8 字节；各回复同时限制文本为 8000 字节、双层 JSON 转义后的包络为 11000 字节，发送前再校验完整消息 data 不超过 12 KiB。正文还会根据转义后的大小减小分段，避免大量引号或反斜杠使一页无法发送。

浏览、搜索、排序和翻页均不写重温起点、回忆观察、应用 / 总结或长期保持记录，不调用 LLM，不要求维护新题库。时间状态沿用 `time-only-v0` 的管理提示，不能解释为实际掌握概率。「最近确认重温」只取当前资料版本、不晚于查询时间的真实 `review`，不把 `estimated` 称为确认。

知识回复会进入**本人飞书私聊历史**。解除绑定会阻止之后的新查询和尚未发出的回复，不能撤回已发出的 HTTP 请求或已有聊天历史。机器人使用已核验的 `open_id` 直接创建私聊文本，不依据任意消息 / 群 ID 推导目的地，也不在失败时切换到其他发送接口。

## 授权、去重与停止

只有官方认证 SDK 的消息回调可调用内部阅读能力，没有新增原始事件 HTTP 接收路由。读取前按 `(appId, tenantKey, openId)` 解析有效账号；发送前复核账号 UUID、访问版本、绑定 ID 和知识缓存快照。撤销后即使重新绑定同一身份，旧回复也不能重新获得授权。

SDK 可能先获取 tenant token 再发送正文，因此实际消息请求发出前还会再检查授权与停止状态。每个 token / 消息 HTTP 请求注入 10 秒超时，不改变 SDK 全局 defaults；这不是严格的整体墙钟截止，也不能撤回已经发出的消息请求。停机拒绝新处理、关闭长连接并等待已接纳处理记录结果，然后既有生命周期再关闭账号数据库。

`accounts.sqlite` 加法创建 `feishu_read_receipts`，仅保存操作摘要、用户 UUID、时间和状态，不保存命令、正文、凭据或原始错误。操作摘要按应用、租户、身份和**原消息 ID**生成；事件 ID 改变的重投递仍命中同一记录。首次发送前事务占位并再次核验当前绑定；已有任何状态均不再次发送，重启后仍有效。

`platform-accepted` 仅表示 API 的业务码为 0 且返回有效消息 ID，不表示用户已经查看。业务失败、网络失败或结果未知记为 `failed-or-unknown`；崩溃或结果无法落库可能保留 `attempted`，也不自动补发。需要再查看时，由本人主动发送一条新的指令。该表不是 outbox，无后台重试或当前自动清理；保留策略在 FEISHU-04 继续设计，也不包含在学习 JSON 导出内。

进程最多处理 4 个知识请求，每个身份最多 1 个在途请求、接纳间隔至少 1 秒，身份节流槽最多 256。超出限制不排队且可能无回复；本人可稍后发新命令。固定错误与静默 SDK logger 避免输出正文或凭据，发送失败不被误报为 WebSocket 断开。
