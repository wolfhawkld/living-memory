# 关系建议待办总览

更新：2026-10-13。LM-014C 接续[结构化关系建议](relation-suggestions.md)和[单项关系复核](relation-reviews.md)，集中查看已保存的关系建议，并定位原应用 / 总结继续处理。

## 使用入口

1. 在真实记录模式下打开「知识薄弱点总览」，切换到「关系待办」。
2. 按主概念的知识域筛选，或搜索主概念、关系双端名称 / ID、原记录 ID。
3. 默认查看「待跟进」，也可切换全部、待处理、依据待复核、当前已采纳、暂不采用。每批展示 50 条。
4. 点击「定位原记录」。页面重新核对当前来源和处理决定，跳到对应主概念及指定应用 / 总结；正文保持折叠。
5. 展开原记录，使用已有「关系建议复核」面板处理。总览本身只读。

每条含关系建议的已保存应用 / 总结只占一行，跨域关系按主概念归属，不在两个领域重复计数。文字修正待办与关系待办分别维护；只填关系建议、没有文字修正的记录也可出现。

## 状态含义

| 提示 | 含义 |
| --- | --- |
| 待处理 | 尚无人工决定，或本人最近重新设为待处理 |
| 当前已采纳 | 最近人工确认已采纳，且当前依据与当时相同 |
| 依据待复核 | 曾人工确认采纳，但双端身份 / 资料或精确关系依据已变化；原决定保留 |
| 暂不采用 | 保留最近人工决定；即使依据变化，也不会自动重新加入默认待跟进 |
| 处理链异常／无法判定 | 决定链存在分叉、循环、断链等，无法安全确定最近决定；列入待跟进 |
| 符合建议结构，待本人核对 | 当前结构与增改删建议相符，仍需本人确认，不代表已采纳或建议正确 |
| 端点缺失，结构未知 | 至少一个关系端点不在当前索引中，不能据此判为删除成功 |

默认「待跟进」包括待处理、已采纳后的依据待复核及异常处理链；先展示这些项，再按最近决定 / 原记录时间及稳定事件 ID 排序。当前依据按方向、类型和完整描述精确核对，覆盖全量知识索引，不受图谱显示节点上限限制。

主概念仍在但另一端缺失时，保留可定位的行。主概念也缺失时，计入当前知识空间的不可定位历史数量；该数量不随领域和搜索筛选缩小。历史不会被删除。异常处理链可能使单项复核接口拒绝读取，定位会显示错误；本项不提供异常链修复工具。

## 刷新与隐私

`GET /api/learning-overview` 增加可选 `relations` 元数据，由当前账号的完整知识源、应用和关系决定批量构建。仅包含身份、版本、操作、时间、状态及结构存在性，不返回关系完整描述、应用正文、答案、处理说明或完整历史。旧服务缺少字段时显示「暂不支持」，不把未知显示为零条。

仅统计已经落库且发生时间、记录时间均不晚于总览时刻的记录；浏览器待同步记录未计入。刷新失败保留明确错误提示并禁止定位；可刷新数据后重试。

定位前同时读取当前完整快照与原记录的关系核对结果，检查知识空间、主概念、关系双端、当前依据及最近决定 ID。即使主概念正文版本不变，另一端或关系有变化也会要求刷新。关闭总览、取消或切换知识空间后，迟到响应不会重新选中节点。

本项不新增数据库表、学习 JSON 字段或写接口，不写知识源；查看、筛选和定位不改变重温起点、H、回忆记录、信心统计、预算或本人长期保持。不调用 LLM，不新增人工练习维护流程。

## 检查与试用

自动检查使用合成知识和隔离账号，覆盖完整索引、精确关系、缺端、异常链、未来记录、状态独立、隐私、账号隔离、导航变化及只读数据不变。远端浏览器回归覆盖筛选、依据变化后的拒绝、刷新恢复及指定旧记录定位；不运行本地浏览器。

本轮本地 Node / HTTP 回归 960 / 960、TypeScript、生产构建、8 项新产物主题检查及文档文件链接检查通过；远端浏览器执行结果以精确提交的 CI 为准。

本人可用已有关系建议查看总览，检查跨域查找、处理状态与原记录跳转。真实关系正确性、外部 KG 更新流程、实际视觉体验及记忆收益仍由本人验收。飞书卡片样式优化继续暂停。
