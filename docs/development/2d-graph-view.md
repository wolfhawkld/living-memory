# 2D 阅读的坐标与镜头

日期：2026-09-20。

用户反馈切到 2D 后看不到节点，点击图谱后黑屏。代码检查确认：当前 `three-forcegraph` 在运行时切换为 2D 时删除节点的 `z/vz`，而原标签投影必须有有限的 xyz；此外，应用只在初次进入图谱时做全景定位，切换维度仍沿用先前 3D 相机和 Trackball 旋转手势。平面可能不在视野内，标签也会被过滤。未将该问题归因为已证实的 NaN 或 GPU 故障。

## 修复行为

- 3D 和 2D 使用独立的图谱实例生命周期，切换模式重新初始化引擎、镜头、标签层和首次定位，不在旧实例上变更维度后重新加热。学习状态和选中概念继续由 App 维护。
- 2D 初始坐标及读取时统一投影为 `(x, y, 0)`。标签、点击聚焦和节点的屏幕尺寸计算使用相同的坐标规则，即使引擎省略 z 也可正常工作。
- 2D 镜头正对图谱平面，up 为世界 Y 轴；关闭 Trackball 旋转，背景左键拖动用于平移，滚轮可缩放。切回 3D 使用新的三维控制器。
- 无效 xy 不传给聚焦或标签层。3D 仍要求 xyz 有限，避免把真正的无效三维位置误作二维处理。
- 2D 是临时阅读布局，拖动和模拟结果不写回已保存的 3D 坐标。返回 3D 时从已有布局初始化；若没有已保存坐标，则沿用既有默认位置和力导向布局。维度切换本身不会生成重温或回忆观察记录。

## 验证范围

使用 Node 与 Three.js 验证平面坐标、缺失 z 的标签投影、聚焦位置与布局收集；结合本地实际力导向引擎检查二维节点及三维数据隔离。运行逻辑测试、类型检查和生产构建。浏览器、鼠标实际操作及 GPU 画面由用户复验，不以 Node 检查代替浏览器验收。
