# 知识修正建议的人工跟进

更新：2026-09-27。LM-014 的后续子集，把应用/总结中的修正建议与外部知识库更新后的人工核对连接起来。

## 操作流程

1. 在节点上保存一条应用或总结，填写「知识修正建议」。
2. 在「学习历史」展开该记录，可看到「知识修正复核」。没有修正建议的记录不显示这个区域。
3. 沿用原有复制整理材料的入口，经 progressive-kg 更新知识正文，等待成功收尾钩子刷新，或手动刷新知识源。
4. 阅读当前资料，选择「确认已纳入当前版本」，勾选已核对并保存；也可以记录「暂不采用」，或将先前决定「重新打开」。处理说明可选。
5. 在原应用/总结下面查看处理记录。原建议、处理时的资料版本、发生时间和保存时间都保留。

资料内容版本与原应用记录不同时，才允许确认纳入。版本变化本身只提示待核对，不代表建议已落实；界面不会自动替你确认。已确认之后资料再次变化时，显示上次决定针对旧版的提示，原决定继续保留。

## 与记忆状态的关系

处理修正建议是知识维护行为，不推断回忆成功或应用能力，不改重温起点、H、回忆统计、复习资格或长期保持状态。需要重温记录时，仍单独使用「确认已重温」。本功能不调用 LLM，也不直接改写或发布 progressive-kg 内容。

复核入口只在主动展开应用/总结正文后出现，沿用查看历史答案时的资料曝光标记；回忆任务期间仍隐藏历史。

## 保存、并发和恢复

- `POST /api/corrections` 沿用当前账号、写入令牌与知识空间校验。新决定必须对应当前资料版本，并引用当前账号内同一概念的一条非空修正建议。
- 每次保存追加独立事件，包含原应用事件 ID、前一决定 ID、当前资料版本和说明（最多 4,000 字符）。不会覆盖原应用记录或过去的决定。
- 多页面同时处理同一建议时，仅允许接在当前决定后面追加。另一页面已经保存新决定时，旧表单须重新核对，不能静默覆盖。
- 提交时冻结请求 ID、时间和前序事件。网络失败或超时后原样重试；已保存的相同请求返回重复确认，即使此后又有处理决定或资料更新，也不会重复新增。
- 待同步记录按知识空间保留，不转交其他账号，也不当作已保存结果。同步详情中类型为「知识修正复核」。
- 因资料版本或处理前序冲突而被明确拒绝的待同步复核，可在左侧选择「保留备份并撤回请求」。确认后先在当前浏览器保留完整原请求，再移出同步队列；随后可在原应用/总结下重新核对。该操作不撤销服务器已保存的决定，网络超时等结果未知的记录仍需先原样重试。
- 历史最多展示每条建议最近 50 次处理，导出保留全部事件。整份学习数据 JSON 增加可选 `corrections`，旧备份保持兼容。
- 导入预览检查应用引用、概念对应、事件冲突及处理链；缺少父记录、分叉、环或不合法时间会阻止整批导入。恢复沿用原发生/保存时间和资料版本，先恢复应用记录，再按前序依赖恢复处理决定。

尚未提交的说明仅在本次页面内存中。自动更新会在编辑期间暂缓；主动切换节点、收起记录或刷新页面前请先保存。源版本或处理状态冲突时可保留说明，重新读取并核对后再提交。

撤回请求的浏览器备份位于 localStorage 的 `living-memory.correction-recovery.v1.<encodeURIComponent(sourceId)>`，保留原请求及撤回时间；不属于服务端学习数据导出。清空站点数据会清除这些本地备份。

## 检查范围

467 项 Node 测试、构建及主题构建检查通过。自动检查仅使用临时数据库、合成知识源、HTTP 接口与组件静态输出，不向个人知识库写入测试数据；浏览器验证由用户进行。

本地服务更新前已备份账号及学习数据库，更新后与备份逐条核对原学习事件、参数历史、复习安排和布局保持不变。新复核表为空，未替用户创建修正决定。

建议试用一条含修正建议的记录：先暂不采用，再重新打开；经原 KG 流程更新内容并刷新后，核对并确认纳入，查看历史及节点记忆时间是否符合预期。

完整 LM-014 仍保留结构化关系修正、跨概念传播和真实 KG 工作流的人工验收；本项只提供逐建议的处理记录。
