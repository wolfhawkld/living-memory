# 场景调用、信心校准与长期保持

日期：2026-09-22。用户选择这三项为当前优先范围，并明确：**长期保持固定显示，只有本人手动操作才恢复衰减**。

## 使用流程

关闭示例状态、回到实时时间后操作。时间预览只读。

### 从场景想起知识

1. 点击顶部「场景调用练习」，输入一个业务、研究或工作场景。开始后，图谱和概念列表隐藏。
2. 可选填事前信心：独立想起一个适用概念并说明理由的把握，0%～100%。开始作答后固定预测。
3. 写下想到的概念、建模办法及适用理由；允许留空。提交后固定原始回答和时间。
4. 搜索并关联一个概念，查阅摘要或大窗资料，再记录独立作答、额外提示、查阅/AI 帮助或不确定。
5. 核对适用性，保存成功、部分成功、未成功或尚未核对，并说明依据是自己对照资料还是实际应用。核对后的补充说明另存，原始回答保留。

一次记录关联一个目标概念；候选概念可以有多个合理答案，不以某个预置标准概念排除其他方案。首版使用本人提供的场景、关联与核对；自动生成场景、多概念一次归档和独立评分留待后续。

2026-10-02 新增[已保存场景回访与总结交接](scenario-revisit.md)：从题面重新作答，持久标记同场景回访；观察保留后可主动进入学习总结草稿。场景来源、辅助条件和结果继续分别记录，不自动认定新场景迁移或实际应用成功。

如果先前已看过目标资料，页面已知的曝光标记会保留；用户还需说明额外提示和其他渠道查阅情况。页面无法证明用户在别处没有看到答案。

### 日常查询前先想一下

2026-10-16：在搜索框下点击「先想一下再查」。普通搜索仍可直接使用，此入口适合遇到实际问题时，先保留自己想到的概念和理由，再借助知识库核对。

1. 写下「要解决的问题 / 场景」；已有搜索词会带入，但不作为原回答。可选填事前信心。
2. 开始后先写原始想法，允许留白或说明没有方向。此时工作区、概念列表、图谱和历史均遮蔽，候选尚未显示。
3. 本轮沿用进入窗口时冻结的知识版本；提交后固定回答与回答时间，再搜索全库的名称、别名或摘要，选择一个概念并按需打开资料。核对后的适用性说明另填，不回改原回答。
4. 可以查询后关闭而不保存；若要留作学习观察，再确认提示条件、结果和依据。切换核对概念会清空上一概念的判断与适用性说明。

进入时保存本页面已显示的领域列表 / 图谱名称、右侧跨域关联名称及当前搜索组件已展示的结果名称。已知名称提示会限制「独立想到」，但名称出现不等于正文已读；正文和关系查阅仍沿原会话曝光规则。空白原回答或已知提交前看过资料，也不能选「原回答已想到，且提交前未得到提示」。其他记录默认线索与曝光不确定，仅在本人确认原回答确已想到且未获提示后才保留相应自报。

页面无法完整追踪此前所有浏览、其他标签页或外部资料；这是一条保守记录已知提示与本人自报的工作流程，不是完整的查询 / 章节曝光账本，也不证明新场景迁移。只读查询和关闭不写学习事件。自愿保存沿用 `task=scenario` 的原观察、幂等与待同步流程，初始搜索词不标记成旧场景回访；不自动确认重温或改变 H、长期保持和复习安排。预算为 0 时仍可主动使用此入口。

本入口不需要题库或模型调用。查询模式不显示旧场景列表；顶部原「场景调用练习」和已有场景回访保持原用途。实际页面体验与延迟记忆收益仍由本人试用。

### 概念解释与信心比较

原有「先想一句，再查看资料」增加事前预测步骤。任务目标是解释核心原理和关键条件；作答前预测、作答后核对分开。

节点详情展示两种任务各自的样本数、平均事前信心、核对成功率和差值。统计使用当前概念、当前资料版本的全部已保存观察，不受历史分页影响。

可比较记录须同时满足：

- 有作答前固定的信心和时间；
- 独立作答，明确未先看资料，且页面没有相反曝光记录；
- 结果明确为成功或失败，有核对依据。

部分成功、借助提示、查阅后作答、未核对、曝光不确定的记录仍保存，但不计入此比较。旧记录没有新字段时保持未记录。

差值 = 平均事前信心 − 核对成功率，单位为百分点。正值表示本组记录的信心平均高于核对成功率，负值相反；样本量和任务条件应一起看，不据此给个人贴标签。底层另计算 Brier 分数 `mean((confidence/100 - outcome)^2)`，仅作后续分析。

结果由本人核对，不能视为独立测量的记忆概率。场景调用统计与时间模型分别展示，尚不自动调整全局 H 或节点颜色。

### 本人确认长期保持

节点详情点击「设为长期保持…」，阅读说明并确认。节点固定为淡紫色，标为「长期保持（本人确认）」；时间曲线停止在该节点详情中展示，D 和间隔为 null，不伪造 100% 记忆概率。

该设置跨刷新、服务重启、普通重温记录、回忆结果及资料内容更新保留。资料更新时给出说明，仍保持本人设置。只有「恢复时间衰减…」并确认会解除。

恢复时沿用已有重温起点和当前 H；没有起点则回到尚未评估，旧版本起点则按已有规则待确认。切换本身不新增复习记录。重温操作仍可单独使用。

这里的半自动流程是系统管理状态、投影和留痕，本人作出最终确认。不会根据几次成功自行锁定节点为永久记忆。

## 数据与接口

- `Observation.learning`：可选结构，含 `task`、`scenario`、`applicability`、整数百分比 `confidence`、`confidenceAt`、`cue`、`outcome`、`basis`。
- SQLite 在原 observations 表增加可空 `learning_json`，旧记录和幂等请求载荷保持兼容。
- `POST /api/retentions`：新增切换事件，包含事件 ID、概念和来源版本、发生时间、`active` 与 `previousEventId`。沿用本地会话和知识源校验。
- 独立 retentions 表记录切换历史。通过前一事件 ID 检查并发，延迟到达的旧操作不能覆盖更新的人工决定。
- Snapshot 的 `state.retention` 保留最近一次切换事件，包括已解除事件；`retained` 是管理状态，时间模型仍为 `time-only-v0`。
- 概念历史包含保持/解除事件、场景与信心记录，返回当前版本的 `learning` 汇总。导出包含 `retentions` 及观察中的场景/信心字段，保留原知识资料外部引用方式；现已支持[学习数据导入恢复](learning-data-import.md)，恢复不新增重温或自动解除长期保持。
- 写入通过原有幂等和待同步通道。失败后重试原载荷；成功或已加入本地队列后结束当前表单，队列等待服务确认。场景练习期间切换知识源时，提交的记录保留在原知识源的本地待同步队列，重新连接原来源后再同步；不向新来源写入。
