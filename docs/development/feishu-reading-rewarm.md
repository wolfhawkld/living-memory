# 飞书阅读后的明确重温

对应 FEISHU-05。在已绑定机器人的私聊里，用 `知识 卡片` 或搜索找到概念，打开阅读卡，确实重温后点击「确认已重温」。无需先创建自评或加入复习队列；没有时间起点的概念也能通过这次明确确认建立首次起点。

阅读、翻页、返回列表和平台接收回复不会自动确认重温。按钮只保存当前明确确认的时间；不表示已读完全文、答对题目或掌握了概念。保存后，Web 同账号同节点的历史会新增一条明确重温记录，时间状态按该起点计算。

## 与复习安排的关系

- 与「清楚 / 模糊 / 想不起」自评分开，不创建观察记录，也不增加当天的概念自评完成数。
- 每日预算为 0、节点暂缓、近期已重温或处于长期保持时，仍可自愿记录实际重温。手动长期保持不会因此解除，H 也不会改变。
- 正在进行的三项复习，其队列、当前项、评分和冻结条件保留。新卡会沿用既有规则使旧卡按钮失效，可通过 `知识 继续复习` 返回原会话。

## 确认结果与恢复

| 情况 | 页面或指令行为 |
| --- | --- |
| 显示已确认重温 | 记录已保存；不要为确认回复而重复创建重温 |
| 显示写入结果待确认 | 可能尚未保存，也可能已保存但回执未结算；点击「重试原操作」 |
| 卡片过期、回复丢失或服务重启 | `知识 重温状态` 查看最近操作；`知识 重试重温` 只重试原有待确认操作 |
| 另一概念仍有待确认操作 | 展示原操作对应概念，并说明本次没有创建新记录；先处理原操作 |
| 资料或来源已变化 | 未写入的旧操作停止处理，重新核对资料；若原事件已写入，只核验原请求并补回执 |
| 实例从备份恢复 | 原待确认操作失效，不自动继续；查看现有学习历史核对，不能据此认定此前未保存 |

重试保持原事件 ID、概念、资料版本和确认时间。状态查询、启动服务及普通导航不会自动重放。没有待确认操作时，重试命令只显示已有状态，不创建新重温。

查询与重试只处理当前账号授权代际、绑定、知识空间及原私聊内的操作。解绑重绑或切换知识空间不会迁移、重放旧操作。

## 开发与兼容边界

阅读重温意图保存在账号库独立的 `feishu_rewarm_intents` 表中，不依赖会过期或清理的卡片行。账号授权、卡片消费、回执去重和首次意图写入在同一账号库事务中完成；之后写学习库并结算状态。两个数据库不承诺跨库原子提交，未知结果保留为可恢复的 pending。

复用 v2/v3 的明确重温记录，学习格式不增加新版本。完整实例备份包含新表；旧归档缺少此表仍可恢复。新表存在时必须通过结构和请求校验，恢复将 pending 标为 `INSTANCE_RESTORED`，保留冻结请求和已写入的学习事实。新版账号表由正常初始化建立，旧程序或旧恢复工具不承诺理解新增意图。

合成验证覆盖明确确认、状态与原请求恢复、账号和知识空间隔离、正在进行的批次保持，以及新旧归档恢复。真实飞书客户端显示、按钮往返与个人记忆收益仍需实际使用验证；本轮不以合成数据代替本人学习记录。
