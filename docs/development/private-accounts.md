# 私人账号与知识域

更新：2026-09-22。用户已确认：**每个用户拥有自己的知识域，后续再设计知识融合与共享。** 本轮提供本机多账号原型，继续沿用 Markdown 知识源与独立学习记录。

协作任务：[Issue #24](https://github.com/wolfhawkld/living-memory/issues/24)。

## 使用方式

1. 启动服务并打开 `http://127.0.0.1:4317`。首次运行显示“创建第一个账户”，由本人填写用户名和密码；项目没有默认密码。
2. 第一个账户成为管理员，接管 `LM_KG_ROOT` 指向的现有知识库及原有学习记录。没有配置时沿用仓库合成知识源。原有 sourceId、概念 ID、重温、观察、长期保持和布局不迁移、不重建。
3. 顶部“账号管理”可创建成员、停用/启用成员和重置密码。第一个管理员不能被停用。重置密码或更改启用状态会撤销该用户已有会话。
4. 新成员从空的知识库和学习记录开始。新建账号后，在管理面板复制其账号 ID；将 Markdown 放入 `data/local/users/<账号 ID>/knowledge/`，由该成员登录后点击“刷新知识源”。使用 `LM_DATA_DIR` 时，以该目录替换 `data/local`。
5. 成员目录可自行组织 `Math/`、`AI/` 等知识域；例如 `knowledge/Math/条件概率.md`。概念 Markdown 仍需 `type: concept`，关系、图片和资料引用沿用现有格式。当前没有浏览器上传/编辑知识库功能。

用户名使用 3–32 位英文字母、数字、点、下划线或短横线，服务端统一小写；密码为 12–256 个 Unicode 字符。管理员可重置自己的密码，此时需要重新登录。

不同用户可拥有相同领域名和概念标题，其节点身份和记录各自独立。管理员界面只管理账号元数据，没有切换查看成员知识库的入口。服务所在机器的文件拥有者仍可读取本地文件，这不是端到端加密方案。

## 隔离与数据位置

| 对象 | 当前实现 |
| --- | --- |
| 账号 | `accounts.sqlite` 保存 UUID、用户名、角色、启用状态与访问版本 |
| 凭据 | 单独加盐的 scrypt 密码摘要；数据库不保存明文密码 |
| 会话 | 随机不透明令牌，服务端只保存摘要；浏览器 Cookie 为 HttpOnly、SameSite=Strict，12 小时绝对有效期 |
| 原有知识源 | 仅首个管理员绑定原 `LM_KG_ROOT`，保留既有 namespace |
| 新成员知识源 | 按用户 UUID 分配私有目录，根目录生成独立 namespace |
| 学习数据 | `living-memory.sqlite` 中重温、观察、长期保持、模型配置、布局按 namespace 分区 |
| 浏览器本地记录 | 待同步队列、来源曝光、示例与领域偏好按私人 sourceId 区分；切换账号不会重放其他空间的写入 |

服务端先验证账号，再绑定知识源和 Store；完整索引、领域投影、历史、附件、导出、配置、布局、刷新和 SSE 均经过此边界。写入同时核对会话 CSRF token 与来源 ID。登出撤销当前会话，其他已登录会话可继续使用；账号停用/密码重置撤销该账号所有会话，已有 SSE 会在下一次会话检查（约 1 秒）关闭。

浏览器退出时卸载旧图谱；多标签页通过不含账号信息的变更通知重查身份。待同步内容仍保留在原浏览器中，方便同一账号重新登录后补交。共用设备需要浏览器配置文件隔离，退出登录不等于清除本机离线数据。

密码参数采用 Node 内置异步 scrypt（N=2^17、r=8、p=1），限制并行哈希，并对登录失败进行限流。选择依据见 [OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。服务端鉴权及会话约束参考 [Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) 和 [Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

## CLI 与 progressive-kg 钩子

完成第一个账号创建后，服务为原有本机 CLI/钩子生成管理员设备凭据 `data/local/cli-session.json`（权限 600），有效期 30 天。重启服务会替换旧设备凭据，管理员密码重置也会替换它；浏览器退出不影响这条本机通道。它代表服务所在系统用户的原有私人知识库，不能用于成员账号切换。

CLI 自动读取此文件，只向其中完全匹配的 `http://127.0.0.1:<端口>` 发送凭据，不打印令牌。服务端和 CLI 的 `LM_DATA_DIR` 应一致；也可用 `LM_CLI_SESSION_FILE` 指定凭据文件。首次创建账号前 CLI 会收到 `AUTH_REQUIRED`，应先在页面完成初始化。安装在 progressive-kg 的刷新钩子无需重新安装，默认目录和端口保持兼容；自定义目录需要让调用进程知道凭据位置。

设备文件、账号数据库、学习数据库和成员知识目录均是私有本地数据，不提交 Git，也不通过 HTTP 下载。现有 JSON 导出仅覆盖当前知识源的学习快照，不是账号/密码或完整多用户备份；备份需同时保留整个数据目录与外部知识源。

## 当前边界与后续扩展

服务仍只监听 `127.0.0.1`，保留回环 Host/Origin 检查，当前 Cookie 适用于本机 HTTP。这一轮未开放局域网或公网。在线协作部署还需落实 HTTPS/Secure Cookie、部署 Origin、注册/邀请与恢复流程、运维备份、容量和滥用控制，不能仅修改监听地址便视为完成。

启动时检查知识源、私人数据和已启用的网页静态目录边界，拒绝目录重叠（包含符号链接路径），防止成员知识被误扫描或凭据被静态服务暴露。请将三个目录分别放置。

显式 `LM_AUTH_MODE=local` 可运行旧的单用户兼容模式；如果数据目录已有 `accounts.sqlite`，服务会拒绝免登录启动，单用户调试必须使用另一个独立数据目录。自动化服务测试可通过 `accountsEnabled` 显式选择模式。

账号 UUID 与用户名分离，未来可增设认证提供方映射，不需要重写学习事件。当前仍是“一位用户对应一个私人知识根目录”，尚未引入独立 workspace 表；知识源身份仍依赖规范化根目录路径，迁移目录需要既有 namespace/节点身份的专门迁移，不能直接搬目录后假定历史会自动关联。

未来共享与融合建议按独立任务推进：

- 引入稳定知识空间 ID、成员关系和显式读写授权，让个人空间与共享空间并存。
- 分享或合并内容时保留原作者、来源概念、内容版本、冲突与合并记录，不能按相同标题自动认定同一知识。
- 学习事件继续绑定个人与内容版本。共享一个概念不共享“掌握程度”、答题信心或长期保持状态。
- 共享源可能有多位学习者，届时需将当前 namespace 分区扩展为个人学习分区，并同步迁移浏览器待同步键、导出和 CLI 身份。

## 验证

使用临时合成知识库检查未登录拒绝、首账号接管旧记录、同名领域/节点隔离、跨账号附件/历史/布局/写入拒绝、独立配置和长期保持、重启保留、CLI 设备身份、登出和停用撤销会话/SSE。账户模块另检验密码摘要、限流、过期、设备轮换及异步验证期间停用的竞态。浏览器视觉和实际操作验收由用户进行。

最终 230 项 Node 测试及构建通过。已更新本地服务，确认登录入口可访问、未登录图谱请求被拒绝，原有学习记录条数保持不变；没有代替用户创建实际账号或写入测试学习事件。

登录后全屏布局跟进：用户反馈大小图谱均应固定占用全屏工作区，不能随节点数量拉伸纵向 UI。修复账号外层容器只有最小高度、导致长概念列表撑高画布的问题，恢复从页面到图谱工作区的明确高度约束。侧栏列表内部滚动，节点数量只影响镜头适配；此修复不修改保存坐标或学习记录。构建检查通过，实际布局与居中效果由用户刷新后确认。
