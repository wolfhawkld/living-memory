# 飞书知识卡片与待复习查看

日期：2026-10-02。对应 NEXT-06 / FEISHU-02B。点击式领域、列表、正文分页与待复习候选的软件链已实现，连接器仍[默认关闭](feishu-connector.md)。真实应用发布、权限、按钮回调、新卡投递与客户端排版尚待人工验收；本文不将软件实现标为平台接入成功。先完成[本人账号绑定](feishu-account-binding.md)，文本入口仍见[知识阅读](feishu-knowledge-reading.md)。

## 入口与操作

在应用机器人**本人私聊**发送：

| 指令 | 行为 |
| --- | --- |
| `知识 卡片` | 全部知识的卡片列表 |
| `知识 卡片 帮助` | 卡片帮助 |
| `知识 卡片 领域`、`知识 卡片 领域 2` | 目录知识域及分页 |
| `知识 卡片 搜索 概率` | 名称 / 别名搜索 |
| `知识 卡片 列表 域="Math" 查="概率" 序=名称 页=1` | 组合范围、搜索、排序和页码 |
| `知识 待复习` | 最多 3 个当前候选 |
| `知识 待复习 量=5`、`知识 待复习 域="Math" 量=3` | 数量或目录域范围 |

领域以实际列表给出的目录标识为准。带空格参数使用 JSON 双引号字符串；未知 / 重复参数显示帮助。卡片命令不支持手写正文阅读参数，应从列表点击「阅读」。按钮支持领域切换、前后分页、阅读正文、返回原列表 / 待复习范围及查看候选；较长字段或包络会减少当页条数，不能假定每页永远同样数量。

按钮先返回「已收到操作；无新卡时请发送『知识 卡片』」提示，随后异步向同一已授权身份投递**新卡**，不在原消息中更新正文。提示只确认收到结构有效的操作，不代表授权、发送或平台展示成功。只允许当前绑定最新的有效卡片操作；新卡成功激活后旧卡不可继续点击，点击被接纳后原卡也被消费。卡片从创建起最多有效 30 分钟。

旧卡、资料变化、重复按钮或发送结果未知时，可能没有新卡。主动重新发送 `知识 卡片` 或 `知识 待复习` 恢复入口；正文再从新列表打开。不自动补发，不把未知结果当作可以安全重试。收到新卡后使用新卡按钮。

## 候选与记忆规则

待复习视图复用既有 `selectBriefReviewCandidates`：按本人重点、暂缓、长期保持、资料版本、近期重温等规则筛选，合格候选内优先重点，再按距时间起点天数和稳定 ID 排序。全库候选使用本人完整索引，未限制目录域时跨领域选取，最多 3 / 5 项且受剩余每日预算限制。

每日完成数来自服务端已接受落库的概念回忆观察；场景调用记录不算完成数。自然日按 `LM_FEISHU_TIME_ZONE` 计算，缺省 `UTC`；例如本人希望按中国本地日期对照 Web 时可配置 `Asia/Shanghai`，并核对 Web 的日期时区。卡片显示日期、时区、已完成数与剩余预算。非法时区使飞书配置返回固定 `invalid-time-zone`，不阻止本机 Web。

聊天读取不到浏览器的待同步记录、当前草稿和本轮已访问集合，因此候选与 Web 未提交状态可能不同；不能声称两端候选完全一致。已落库完成记录、重点、暂缓及每日预算共用服务数据。

查看列表、候选、正文或翻页**不扣预算、不保存回忆 / 来源曝光 / 重温事件**，不改变时间起点、长期保持或全局 H，不调用 LLM。候选与颜色 / 文字时间状态只是管理提示，不能当作实测掌握概率。本轮没有自评、脑中回忆证据、独立确认重温、跳过 / 暂停会话或学习写回；这些属于 FEISHU-03。

## 阅读与内容边界

卡片采用 V2 Markdown 排版和导航按钮，正文按 Unicode 字符安全分页，保留后文。正文不是 Web 阅读浮层：当前不原生渲染公式、Mermaid、图片或附件，不保证飞书原生 Markdown 的全部语法效果。方括号、尖括号改为全角，使链接、图片与标记成为可见惰性文本；不承诺自动打开原文 URL，也不承诺手机可访问桌面 `127.0.0.1`。

正文页最多约 3000 UTF-8 字节，并按转义包络进一步分段；卡片 JSON 预算 20 KiB，发送包络另受限制。资料来源指纹覆盖当前缓存中的节点、内容与身份相关元数据；资料刷新后旧卡不能继续导航。尚未刷新到服务的磁盘变化不会被自动检测。

实现采用官方 [V2 卡片结构](https://github.com/larksuite/cli/blob/main/skills/lark-im/references/card/card-2.0-schema.md)与[按钮 callback behaviors](https://github.com/larksuite/cli/blob/main/skills/lark-im/references/card/components/button.md)。本文的消息、导航和存储尺寸是项目保守预算，不代表飞书平台配额；正文支持范围参照[官方 Markdown 组件](https://github.com/larksuite/cli/blob/main/skills/lark-im/references/card/components/markdown.md)，仍需真实客户端验收。

知识正文会进入本人飞书聊天历史。撤销绑定阻止后续读取和未发出的回复，不能撤回已有消息或已发出的网络请求；平台接收成功也不证明用户读过内容。

## 授权、存储与恢复

仅经过认证的官方 SDK 卡片事件进入内部能力，无公开原始事件 HTTP 路由。按钮只携带固定 `kind`、随机 `cardId` 和有限 `actionId`；目标视图由服务器已保存的动作决定，不能通过按钮传 userId、namespace、概念正文或权限声明选择知识。

点击时事务重新核对 app / tenant / openId、启用账号 UUID、访问版本、绑定 ID、平台消息及聊天 ID、原始可信私聊上下文、TTL、namespace 和资料指纹。撤销后重绑相同身份也不能让旧卡恢复权限。发送前以及 SDK 获取 token 后实际发消息前再次核验授权与停止状态。

`accounts.sqlite` 加法新增 `feishu_card_views`：只保存授权代际、范围、视图 / 动作、来源指纹、时间及平台消息上下文等 metadata，不保存渲染正文、凭据、原始错误或 outbox。视图 metadata 限制 16 KiB，每用户最多 32 条未过期卡片记录；创建新草稿时清理到期记录及本用户已消费卡片。

按钮操作以 cardId / actionId 生成稳定摘要，事务内写 `feishu_read_receipts` 的 `attempted` 并消费卡片；事件 ID 改变也不会重复发送。该持久回执不随卡片清理。API 成功且返回有效消息 ID / 可信聊天 ID 后，才记 `platform-accepted` 并激活新卡；否则记 `failed-or-unknown` 或保留 `attempted`，均无后台重试。

卡片与回执不包含在学习 JSON 导出内。完整恢复需备份账号数据库、学习数据库、整个私人数据目录及外部知识源，见[账号备份边界](private-accounts.md#cli-与-progressive-kg-钩子)。恢复账号库仅恢复备份时点已记录的回执；备份后记录不会自动保留，不能保证这些操作仍被去重。恢复时保持连接器关闭，核对授权及回执 / 卡片状态后再启用，详见[完整回退与核对](../releases/upgrade-and-recovery.md#5-需要回退时恢复匹配的一套)。不能只恢复学习 JSON 就声称聊天状态完整恢复。

## 软件检查与平台待验

合成临时数据库检查迁移、TTL、容量、授权代际、上下文、资料变化、元数据预算、点击持久去重与事务回滚；离线 SDK / 假发送器检查导航、候选与学习记录不变。没有向私人知识库写测试记录，没有发送真实消息或运行本地浏览器视觉测试。

本轮全量测试 **745/745 通过**，生产构建、8 项编译后主题场景与本地文档链接检查通过。真实固定 SDK 配合假 HTTP 验证 interactive 消息格式、消息 / 聊天双 ID、token 等待期间撤权与关闭后的零发送；真实 EventDispatcher 验证先返回回调提示、下一轮事件循环再开始准备。长中文领域与查询的实际草稿落库、正文完整分页、账号隔离、重启去重和浏览前后学习记录不变均有合成回归覆盖。

最终架构审查通过；导航与完整草稿预算差异、回调准备时序、结算失败不激活及备份时点去重说明均已复核。通过范围仅为默认关闭的 FEISHU-02B 软件实现，未把离线验证等同真实平台接入。

真实验收需核对应用发布 / 可用范围、消息与卡片订阅权限、consumer 归属，确认 toast、新卡、翻页、过期恢复及实际客户端排版。FEISHU-03 学习写回和 FEISHU-04 集中平台验收仍待开发，完整范围见[飞书 TODO](../planning/feishu-review-channel-todo-2026-10-02.md)。
