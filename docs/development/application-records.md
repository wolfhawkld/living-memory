# 实际应用与总结记录

更新：2026-09-27。LM-014 的首个可用子集，为真实工作与阅读后的总结留痕，并把选定内容交给现有 progressive-kg 整理流程。

## 如何使用

1. 切换到「真实学习记录」，恢复实时时间，选中一个概念。
2. 在右侧点击「记录应用 / 总结」，选择实际应用或总结类型。
3. 填写自己的使用过程或总结。实际应用还需填写场景；可补充使用方式、结果、适用条件/局限、insight、知识修正建议及参考资料。
4. 保存后，在该节点的「学习历史」中展开记录。历史默认折叠正文，展开会标记本次已查看，避免后续回忆任务把旧答案曝光误记为未查看。
5. 需要修改知识库时，选择整理材料包含哪些字段，预览后复制，交给原有 progressive-kg 工作流。默认仅选 insight、知识修正建议和参考资料；原始业务场景、过程和结果需要主动勾选。

保存与复制是两件独立操作。复制不会保存学习记录，也不会自动调用 LLM、编辑源 Markdown 或发布内容；材料仍需本人核对。progressive-kg 完成更新后沿用现有成功收尾钩子或手动「刷新」，重新读取概念来源版本。

2026-10-02 增加[场景核对后的交接入口](scenario-revisit.md)：先保留观察，再预填场景与核对说明到学习总结草稿。错误原答、信心和观察结果不自动复制为应用结论；确实用于工作时再手动切换实际应用、说明辅助方式与结果。两类记录仍独立保存，目前按概念关联。

## 记忆语义

- 这是实际使用/总结证据。即使自报成功或选择独立使用，也不能据此推断曾在没有提示时想起概念。
- 不进入独立回忆成功率、场景练习统计或信心校准，不改变 `observationsCount`。
- 不创建重温起点、不改 H，不改变本人确认的长期保持；如确实重温过，仍需单独点击「确认已重温」。
- 这里只记录本人报告，不提供自动正确性评分；基本保存流程已获用户试用确认，异常路径的验收范围见下方记录。
- 旧来源版本的记录继续可查，显示版本变化提示；不会改写成当前版本的应用证据。

## 保存与恢复边界

`POST /api/applications` 使用既有账号/本地会话鉴权和知识空间校验。请求包括事件 ID、概念 ID、来源版本、发生时间、类型、文本、使用方式及结果。内容最多 12,000 字符，其他文本各最多 4,000 字符；实际应用的场景与两类记录的正文必填，时间不可晚于服务端当前时间。

独立 `applications` 表按私人知识空间隔离。事件 ID 与重温、回忆观察、长期保持和修正复核事件共同防冲突；同一请求重试只保存一次。历史接口按发生时间、记录时间、事件 ID 与其他事件一起分页。学习数据导出在现有 schemaVersion 1 中增加可选 `applications` 数组，旧数据不受影响；现已接入[整份学习数据的导入恢复](learning-data-import.md)。

首次提交会冻结时间、事件 ID 和完整请求。网络不可达时沿用浏览器待同步队列；重试不改写原始请求。知识空间变化时记录留在原空间，不转交新账号。待同步的应用/总结不会改变图谱时间颜色或少量复习的候选资格。

草稿目前只存在本次页面内存中；关闭有未保存提醒，刷新页面仍可能丢失草稿。来源内容在填写期间更新时，新记录会被服务端拒绝，可使用失败提示下的「先保留当前材料」选择字段并复制，再基于新版本重新记录；不会悄悄归到新来源版本。

浏览器验证由用户进行：

- 保存一条实际应用和一条总结，检查历史内容、结果、使用方式及时间。
- 确认保存前后重温起点、曲线及长期保持不变。
- 检查复制预览仅包含勾选字段，并试用深浅主题、长文本及弹窗滚动。
- 断网保存后恢复服务并重试，确认只有一条记录；关闭未保存表单时确认提醒有效。
