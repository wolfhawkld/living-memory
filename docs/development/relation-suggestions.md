# 结构化关系建议与知识整理交接

更新：2026-10-07。LM-014A 在应用 / 总结中保存一个有方向的关系建议，保留提出建议时的两个概念和关系快照，再生成交给 progressive-kg 核对的材料。

## 使用

1. 切到真实记录与实时时间，选中概念，打开「记录应用 / 总结」。只想记录关系理由时，可选择学习总结并填写理由。
2. 展开「关系建议」并启用，搜索、选择另一个概念。候选来自当前账号的完整知识目录，包含名称和路径，支持跨领域，不受图谱显示上限限制。
3. 选择方向，核对显示的来源 → 目标。新增填写建议类型和描述；修改 / 删除从该方向已有连线中选择原关系。同一对概念的不同类型或描述分别选择。
4. 修改仅更改类型和描述。若想改变方向，先记录删除建议，再另记一条反方向新增建议。每条应用 / 总结最多附带一个关系建议。
5. 保存后，在主概念的学习历史展开应用 / 总结，查看当时的两端、操作与前后关系。
6. 复制整理材料时，可单独勾选或取消「关系建议」。材料标出双端 ID、名称、路径和版本，以及原关系 / 建议关系；这些是记录时快照，整理前须核对当前知识源。原始业务场景、正文和结果仍需要主动勾选。

关系编辑启用后，缺少目标、原关系或建议类型会阻止保存；关闭该选项才表示放弃附加关系建议。来源变化导致保存失败时，可沿用现有材料预览保留内容，再刷新核对。

保存和复制均不调用 LLM、不直接改源 Markdown。经 progressive-kg 核对、更新来源后，再由既有成功收尾钩子或手动刷新显示真实连线。本项保存的是建议，尚未验证知识源已采纳。

## 记录与记忆语义

关系建议附在原应用 / 总结上，仅由该主概念的历史承载，不为另一端复制应用记录或学习事件。它不构成独立回忆成功，不进入信心校准，不改重温起点、全局 H 或本人长期保持决定。

原文字「知识修正建议」继续使用原人工处理链。关系建议不会单独进入文字修正待办；若一条记录同时包含两种建议，界面说明下方处理结果只针对文字，不表示关系已纳入。关系采纳核验、独立处理队列和跨概念传播仍属后续范围。

## 保存与校验

`ApplicationRecordRequest` 新增可选 `relationSuggestion`。其 `source` / `target` 保存概念 ID、资料版本、名称和相对路径；方向由两端顺序表达，不依赖可能变化的边 ID。`before` / `after` 分别保存关系类型和描述。

| operation | 必需关系字段 | 首次保存的真实来源前提 |
| --- | --- | --- |
| `add` | `after` | 相同方向、类型和描述的关系尚不存在 |
| `change` | `before`、`after` | 精确原关系仍存在，新关系与原值不同且未另行存在 |
| `remove` | `before` | 精确原关系仍存在 |

两端必须不同，主概念必须是其中一端且版本一致。首次写入核对当前账号完整索引中的双端 ID / 版本 / 名称 / 路径及关系前提，使用全量连线而非显示投影。端点不在当前账号返回 `CONCEPT_NOT_FOUND`；资料不符返回 `SOURCE_REVISION_MISMATCH`，关系前提变化返回 `RELATION_SOURCE_CHANGED`，后两者为 409。

首次提交复制并冻结双端、前后关系、时间和事件 ID。离线队列原样保留请求；已接受请求的重复提交不因之后资料或关系变化而失效，同事件 ID 的不同内容仍冲突。只读历史使用冻结信息，不用当前概念名称覆盖旧建议。

ID / 版本最多 512 字符，名称 1,000，路径 4,096，关系类型 256，描述 4,000；描述可空，其余非空。嵌套字段严格校验，缺字段、非法操作、额外字段、自关系或无变化修改均拒绝。原应用场景 / 总结正文的必填与长度规则保持不变。

## 备份、导入与兼容

学习 JSON 仍为 schemaVersion 1，关系建议随 `applications` 导出。缺失端点的概念元数据从冻结快照补足，不覆盖现有身份目录、导入元数据或当前来源。导入预览把两端纳入身份映射，仅映射 ID；当时名称、路径和版本继续保留为历史快照。

两端映射到同一 ID 会以 `RELATION_ENDPOINT_MAPPING_COLLISION` 阻止导入。旧资料版本或无法定位的历史端点按原历史规则提示并保留；导入不要求原关系今天仍存在。预览、重复事件分类和提交共用相同映射，事务失败整批回滚。

SQLite `applications` 增加可空 `relation_suggestion_json` 列。旧行保持 NULL，读取时省略新字段，不重写原请求载荷；旧记录仍可原样重试。升级前保留数据库备份，回退按[完整恢复步骤](../releases/upgrade-and-recovery.md)。含关系建议的新备份须用本轮或更新程序恢复；旧程序不了解此字段，不能保证保留它。网页与后台应同步更新。
