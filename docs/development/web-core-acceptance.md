## 证据基线与读法

原 23 行矩阵及本节固定基线是历史记录，请按日期阅读；新增软件证据见[2026-10-18 交付增补](#2026-10-18-增补查阅引用迁移及性能的交付证据)及[2026-10-20 自评修订接线](#2026-10-20-增补自评修订的服务与兼容接线)。旧行中的「未实现」不覆盖其后已明确交付的子范围，增补也不表示整项 AC 或 v0.1 已验收。

固定代码基线为 [`07f289fb1e9e8573179d31436e84e8715214d2f4`](https://github.com/wolfhawkld/living-memory/tree/07f289fb1e9e8573179d31436e84e8715214d2f4)。对应 [CI 38341506451](https://github.com/wolfhawkld/living-memory/actions/runs/38341506451) 已成功，步骤包括 Node / HTTP 测试、TypeScript / 生产构建、主题产物检查和远端 Chromium 回归；工作流见 [check.yml](../../.github/workflows/check.yml)。该基线已有 960 项本地 Node / HTTP 回归和 8 项主题产物场景的通过记录。本轮仅阅读实现与断言、整理文档，不声称重新运行了这些检查。

下表的「有软件证据」只适用于所列子范围；「原 AC 差距」描述完整条件尚缺的实现或验证。测试名称可在链接文件中查找。单元、合成 HTTP 和远端浏览器证据不能替代本人客户端、知识正确性、设备性能或延迟记忆收益验收，也不能把一条测试的断言扩展到整项 AC。

当前模型仍是 `time-only-v0`：明确确认重温建立起点，全局 H 决定时间提示；回忆、自评、信心、应用和修正记录独立保存，不自动改变起点或 H。本人固定长期保持只由手工解除。四类目标的独立间隔、自动巩固及参数拟合不属于已实现模型。
