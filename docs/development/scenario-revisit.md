# 场景回访与应用 / 总结交接

2026-10-02，本轮补齐[核心记忆流程](../planning/core-workflow-goal-2026-10-02.md)中的两个入口，沿用既有[场景练习](scenario-confidence-retention.md)与[应用记录](application-records.md)。

## 如何使用

1. 在真实记录、实时状态下点击顶部「场景调用练习」。新问题直接填写；要复习旧问题，点击「回访已保存场景」，选择一道题。
2. 重新填写事前信心，再开始回忆。提交前不展示候选概念、资料摘要或旧答案；允许空白回答。
3. 提交后搜索和选择概念，阅读资料并核对当次原答，说明适用条件，标明是否借助提示 / 查阅、结果与依据。
4. 只记观察时点击「保存这次场景观察」。想继续整理时点击「保存观察并写应用 / 总结」。
5. 后者先保留观察，再打开可编辑的学习总结：预填场景与核对说明，原答保持在独立的观察中。结果默认「暂不判断」，辅助方式默认「不确定」。真正用于工作时，主动切换「实际应用」并重新确认。

选择旧题不会继承旧概念、答案、适用性、信心或核对结果。每次回访使用新事件编号和作答时间；失败重试复用这次新请求。编辑旧题仍按同场景改写保存；「新场景」清空旧题并取消回访标记，但不据此保证题目对本人全新。

回访入口不通过概念历史打开，减少开始前看见关联概念的提示。题面由本人编写，本身可能包含概念名称或其他线索；遇到这种情况仍要如实标注辅助条件。同场景回访只用于再练习，不能证明新的业务问题也能想到适用概念。

## 保存与失败处理

- 未保存的场景和回答关闭前会提醒丢弃；未提交的草稿仍只在当前页面，刷新不保证恢复。
- 观察保存失败时保留原请求，不进入总结。观察已确认写入或保存在浏览器待同步队列时，才允许继续。
- 总结交接会重新核对当前知识空间和资料版本。连接、空间或版本变化导致交接失败时，观察仍保留；可以重试打开入口，或保留核对内容后从原空间的节点入口继续。
- 待同步的场景尚未进入已保存场景列表，成功同步后再回访；不会把本地待同步显示为服务器已保存。
- 总结仍须本人编辑和保存；不会自动生成应用记录、自动采用修正、调用 LLM 或修改 progressive-kg。

## 数据与计算

`LearningEvidence.scenarioRevisit?: true` 是 `schemaVersion: 1` 中可选的观察字段，只用于场景任务。省略表示未标记，不表示新场景；其他值或概念任务携带该字段会被拒绝。它在本轮版本的保存、历史、导出与导入恢复中保留，无 SQLite 表结构迁移。旧版本服务不认识此字段，不应依赖降级导入来保留标记。

学习历史、薄弱点总览和回忆变化追踪显示回访标记。两次观察的回访标记不同时，变化追踪会提示所报条件不同。场景计数可包含回访，符合原有独立作答、事前预测、明确核对等条件的回访仍可进入当次信心比较；这些百分比不表示新场景迁移能力。

应用 / 总结与场景观察仍为独立记录，当前按概念关联，没有新增事件之间的外键或同场景自动分组。H、重温起点、长期保持与复习预算沿用原规则；阅读题目、核对、保存观察或总结都不自动确认重温。

现有曝光标记按浏览器学习会话保守保留。隔时再练习时请留意练习开始前是否已查看目标概念；本会话已查看的记录会按看过处理，不会仅因修改下拉选项而抹去。真实延迟试用可以在新的浏览器会话中开始，同时如实报告其他来源的近期接触。

## 只读接口

`GET /api/scenario-prompts?limit=20&cursor=...` 返回当前私人知识空间内、完整概念索引对应的已保存场景，允许旧资料版本的题目。它沿用既有登录和知识源校验，设置 `Cache-Control: no-store`。

响应为 `{ sourceId, asOf, items, total, nextCursor }`。每个 item 仅含 `eventId / scenario / observedAt`，不带关联概念、领域、资料版本、原答案、核对说明、信心或结果。按作答时间、记录时间、事件编号稳定倒序分页；默认 20、上限 50，页面每次加载 8 条。只读取记录，不创建曝光或学习事件。
