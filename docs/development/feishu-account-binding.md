## 使用流程

1. 在本机 Web 登录自己的账号，点击顶栏「飞书绑定」。普通成员和管理员均可管理自己的绑定，不替其他用户绑定。
2. 通道显示已连接、且本人尚未绑定时，点击「生成飞书确认指令」。指令形如 `确认绑定 LM-<22 位 base64url>`；复制完整文本。
3. 用本人飞书账号把完整指令发送到对应应用机器人的**私聊**。发送此指令本身就是主动确认，不另要求机器人回复或点击确认卡片。不要把指令发给他人或发送到群聊。
4. 保持 Web 弹窗打开查看结果。页面可见且请求未到期时，每 2.5 秒查询一次；成功后显示「已绑定飞书账号」，清除指令。隐藏页面、关闭弹窗、到期或正在执行绑定操作时停止自动轮询；仍可主动刷新状态。
5. 可取消待确认请求，或解除已有绑定。重新生成待确认指令会立即使旧指令失效；已经绑定时必须先解除，不会静默替换已有账号关联。

指令仅在生成响应和当前组件内存中出现，不保存到 localStorage、sessionStorage 或 URL。刷新或重新打开弹窗可查看待确认状态，但不能找回旧指令；可显式重新生成，或先取消。复制失败时提供可选中文本供手动复制。网络失败不会自动重发生成请求，应先刷新状态确认服务器结果。

默认未启用或当前未连接时，页面说明不可生成指令；查看已有绑定、取消待确认请求和解除绑定仍可用。当前 Web 只监听桌面本机 `127.0.0.1`，不承诺手机或远程浏览器能够打开该地址。

## 一次性请求与身份边界

指令由 16 个随机字节生成，具有 128 位随机性；使用 `LM-` 前缀和 22 位 base64url 编码。到期时间取「发起后 10 分钟」与「发起浏览器会话到期」中的较早者，界面以服务器 `expiresAt` 为准。服务器只保存指令摘要，状态读取不返回原指令。

发起请求绑定现有用户 UUID、浏览器 session、账号访问版本及 `(appId, tenantKey)` 范围。管理接口需要有效浏览器会话；写操作还需要既有 CSRF token。CLI / progressive-kg 的 device 会话不能生成、查询或管理绑定，也不能被连接器当作管理员回退身份。

SDK 只在认证后的长连接内处理 `im.message.receive_v1`。输入必须为平铺的对应事件，应用、租户与服务端配置一致；发送者为 `user`，会话为 `p2p`，消息类型为 `text`。若带 sender 租户，也必须一致。文本 JSON 解码后须匹配完整确认指令；非私聊、机器人消息、其他消息类型、错误形状或其他指令直接忽略，不记录正文或原始事件。

确认时把 SDK 提供的 `(appId, tenantKey, openId)` 关联到发起请求的用户 UUID。指令不能跨应用或租户使用；用户名、概念 ID、sourceId、消息附带的权限声明不能选择账号。结构投影函数自身不提供鉴权，不能作为公开 HTTP 回调入口。当前没有新增消息接收 HTTP 路由。

每个用户最多一条有效绑定，每个应用 / 租户 / openId 身份也最多一条有效绑定。跨范围或换账号时必须显式解除已有绑定。重复的本人确认不重复创建绑定；取消与解除按原请求 / 绑定 ID 幂等处理，迟到的旧操作不能取消或解除后来的新关联。

重置密码或改变账号启用状态撤销已有绑定并使待确认请求失效。浏览器登出使该会话发起的待确认请求失效，已完成的绑定保留；确认时会重新核对发起会话、账号启用状态和访问版本。停用、撤销或版本失效后的身份不能解析为有效账号。

## 存储与兼容

沿用私人数据目录中的 `accounts.sqlite`，以加法方式创建 `feishu_bindings`、`feishu_binding_requests` 两表。部分唯一索引约束每个用户和每个飞书身份只有一条有效绑定；一次性请求、确认与撤销在事务中完成。

不修改 `living-memory.sqlite`、知识节点、JSON 学习交换格式、时间模型、重温起点或长期保持记录。飞书关联属于账号数据，不包含在当前学习 JSON 导出中；后续读取回执及卡片 metadata 同样保存在账号库，不属于学习导出。完整恢复须按[私人账号备份边界](private-accounts.md#cli-与-progressive-kg-钩子)保留账号数据库及其私人目录。旧版本没有绑定管理能力，回退不能当作已撤销这些关联。

## 平台配置与待验项

继续固定 `@larksuiteoapi/node-sdk@1.74.0`。真实启用前需核对机器人能力、本人是否在应用可用范围内、目标版本发布以及 `im.message.receive_v1` 事件订阅，并确认对应应用 / 租户凭据。平台控制台的权限名称与申请要求应在实际配置时核对，本轮没有声称已验证具体权限组合。

同一应用多个官方长连接客户端的事件由其中一个随机消费者接收，不能作为广播使用。优先使用独立 Living Memory 应用，或先确认既有 Hermes / OpenClaw 消费者归属。本轮不改动它们的配置、订阅或定时推送。

FEISHU-01C 的首轮连接器只获得狭窄账号确认能力；后续 FEISHU-02A 增加经绑定授权的只读知识能力和本人私聊文本发送，详情见[阅读边界](feishu-knowledge-reading.md)。当前仍不调用 LLM、不建立投递 outbox、不写学习记录。FEISHU-02B 后续导航只读取固定 kind / cardId / actionId，实际账号来自 SDK 身份与当前绑定；卡片内容不能选择账号。点击先回执、再核验并投递新卡，详见[卡片边界](feishu-card-browsing.md)。

软件验证使用合成账号、临时数据库、注入 driver 和合成消息，覆盖范围隔离、过期 / 替换、撤销、会话与账号状态、重复事件及 UI 异步边界。真实 SDK 的 EventDispatcher 离线解析测试将原始消息转换为平铺输入，经连接器确认能力写入临时 Accounts，再由 Web API 查询绑定结果；不构造或启动 WSClient。`needCheck: false` 仅验证离线结构转换，不提供平台鉴权证据。
