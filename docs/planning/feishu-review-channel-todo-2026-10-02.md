## 目标与入口

用户希望在飞书里通过排序列表查看知识节点，用类似背单词应用的卡片完成少量复习。本通道聚焦知识查看和回忆，界面不加载图谱可视化。

用户补充：本机 OpenClaw 或 Hermes 已有「学术英文定时推送飞书聊天窗」流程，飞书操作可参考该实现。优先评估复用已有聊天窗投递通道，增加排序列表和交互卡片；需要单独确认翻卡、按钮回调与写回能力。若现有通道只能推送内容，则保留「飞书工作台网页应用 + 项目内轻量列表 / 卡片页面」作为备选。

首轮架构审查选定机器人私聊 + V2 卡片 + 官方 SDK 长连接为后续首选：新官方模块有长连接与按钮事件接线证据，旧 README 的不同说明及真实应用待验边界在[接入说明](../development/feishu-offline-probe.md#官方证据与文档差异)中记录。生产接入前确认事件接收方，避免与同一应用的既有 OpenClaw / Hermes 接收器竞争；本轮不改现有机器人配置。

两种入口均复用知识源、个人账号、记忆投影及学习记录。定时推送只是可选提醒，不替代主动查看入口，不要求每天定时复习；具体是否启用、时间与数量留待本人设置。

本机只读核对结果：学术英语日报任务实际在 Hermes，由任务脚本进入项目 `run.py`，获取飞书 tenant token 后调用 `/open-apis/im/v1/messages`，当前主流程发送 `msg_type: text` 的私聊消息。可参考这条调度与服务端投递链路，但没有发现交互卡片、按钮事件接收或独立投递重试；任务状态记录不等于用户已查看。此次没有运行任务、发送消息、修改调度或复制凭证 / 收件人配置到仓库。

卡片直接来自已有知识节点：正面是概念名称与固定回忆引导，背面是现有知识正文及来源。不要求本人另建题库、编辑题干或维护参考答案。已有摘要可以展示，但首版不增加 LLM 摘要、自动出题或模型评分；后续自动练习可作为另一种卡片来源，遵守[自动生成与维护方向](automatic-practice-backlog-2026-10-02.md)。

## 必要的核心功能

| 功能 | 首版行为 |
| --- | --- |
| 私人知识列表 | 领域切换、名称 / 别名搜索；每行显示名称、领域、时间状态、最近确认重温时间，长名称折行。支持「全部知识」与「待复习」视图 |
| 排序与推荐 | 默认复用当前时间候选、重点、暂缓和每日预算；可切换最近确认重温时间 / 名称排序。显示推荐理由，未知起点单列，不伪造到期日期 |
| 查看知识 | 点击列表项，阅读渲染后的正文和来源链接；展示原有长期保持标记。查看、搜索和翻页不更新重温起点 |
| 卡片回忆 | 本轮默认 3 个，可选 5 个；正面只显示名称与「用自己的话回忆核心原理」引导，用户主动翻卡才显示资料。可脑中回忆，也可自愿留一句回答 |
| 核对与记录 | 翻卡后选择「能解释 / 模糊 / 想不起来」，保存本人自评；自评与确认重温分开。只做脑中回忆时标明本人自报，不宣称有可核对的书面回答 |
| 少量复习控制 | 下一条、跳过、暂停 / 继续、结束；显示本轮进度和保存回执。聊天卡片的会话 / 待提交记录需由服务端保留；网页方案复用当前客户端草稿。失败重试沿用同一事件 ID；待同步与已保存分别显示 |

每条保存自评后，提供独立的「确认本条已重温」按钮。仅在本人确实完成重温并主动点击时更新起点；不默认勾选，不把翻卡、浏览或自评结果等同于重温。

网页方案复用现有阅读组件。聊天卡片使用飞书支持的文本排版，长正文分段 / 分页；公式、附件与复杂图示可进入项目既有阅读页，但该页面必须在客户端可达，不能承诺手机可打开本机地址。具体卡片排版和阅读链接在 FEISHU-01 / 02 验证，不把全部 Web 渲染组件当作可直接嵌入消息卡片。

## 最小使用流程

浏览路径：进入飞书应用 → 选择领域 / 搜索 → 打开知识正文 → 返回列表。

复习路径：查看待复习列表与理由 → 开始 3 / 5 张卡 → 先回忆 → 翻卡核对 → 保存自评 → 按需单独确认重温 → 下一条 / 结束。

正面不显示摘要、正文、历史答案，也不通过隐藏 DOM 或卡片字段泄露它们；资料实际展示后才记录本次资料曝光。若此前是否接触资料无法确定，标为未知，不宣称独立且未曝光的回忆。列表已经显示概念名，因此本流程是内容回忆，不能用来证明工作场景中自发想起概念的能力。

## 排序与记忆规则

- 待复习视图复用当前候选规则：排除长期保持、仍在暂缓、资料版本不符、近期确认重温及本地待同步的节点；同一自然日已保存 / 待同步的概念观察不重复自动推荐，受本人每日预算限制。
- 合格候选先排本人标记的重点；同组按距离确认重温的时间从长到短，最后按概念 ID 稳定排序。重点不强行加入原本不合格的节点；显示「较久未重温」等真实理由。
- 全部知识仍可查看上述节点。没有起点的节点显示「尚无时间记录」，可主动查看并在真实重温后建立起点，不自动混入到期复习队列。
- 已有记忆状态色配合文字标签展示，未知与长期保持明确区分；衰减值是时间管理提示，不是实测掌握概率。
- 自评复用 `clear / partial / blank`，记录资料版本及当时的参数 / 起点 / 接触条件。脑中回忆的记录方式与实际回答区别在 FEISHU-03 落实，不能填入系统生成的假回答。
- 不改变全局 H，不根据一次自评延长间隔，不自动解除本人长期保持。资料变化时保留草稿并重新核对，旧记录不套到新版本。

## 数据与接入边界

知识正文仍由 progressive-kg / 用户知识源提供；学习与安排仍存项目服务，同一账号在 Web、CLI 与飞书访问同一份个人记录。飞书页面属于新增入口，不复制一套知识库、记忆模型或复习数据库。

当前已有账号、概念 / 正文查询、记忆状态、观察、确认重温、历史和复习安排能力。候选选择由现有前端调用核心纯函数完成，待同步和复习草稿主要在浏览器本地；聊天卡片不能直接复用浏览器存储，需要通道会话、固定操作 ID、投递回执及失败恢复边界。飞书身份映射和上述适配尚未实现；优先复用现有接口和纯逻辑。

飞书身份需要由服务端验证并显式关联现有账号 UUID，按应用 / 租户范围区分外部身份；不凭前端传来的用户名或概念 ID 决定访问谁的知识。未绑定时进入绑定流程，停用 / 撤销后拒绝访问；既有用户名密码入口继续可用。飞书应用密钥只存服务端。

当前服务仅监听本机 `127.0.0.1`，并有本机 Host / Origin 与会话限制。聊天桥若在同一机器运行，可以评估授权后调用本机接口，不预先要求把私人服务公开；飞书按钮事件如何进入本机仍需验证。网页方案则需确认客户端能否连接现有环境；手机或远程直接读网页必须先设计可达的 HTTPS 地址与认证部署，不能把手机的 `127.0.0.1` 当作桌面服务，也不能只放开监听或 CORS 就标为接入完成。首版设备范围与连接方式在 FEISHU-01 确定。

## 首版验收重点与后续范围

验收重点：已有知识自动进入列表；没有图谱和题库维护前置操作；候选与现有 Web 规则一致；正文在翻卡前隐藏；浏览 / 自评不改时间起点；明确确认重温后其他通道可读到相同状态；重复提交只保存一次；账号与知识空间隔离；中断时回答不会静默丢失。

自动检查只使用合成资料与隔离存储，不向私人知识库写测试学习记录。飞书客户端操作、手机连接、视觉与真实回忆效果留给本人验证，软件检查不代替这些结论。

定时提醒配置、签到 / 排行榜、社交、自动评分、个体化间隔及不同通道间的草稿接续留在后续范围。聊天卡片本身的必要会话恢复在 FEISHU-03 内处理。场景调用练习和自动生成的细节 / 比较卡，待自动设计与维护方案恢复后再接入，不恢复手工题库的维护负担。
