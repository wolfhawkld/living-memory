[需求 FR](../requirements/v0.1.md) · [技术设计](../design/technical-design-v0.1.md) · [验收 AC](../requirements/acceptance-v0.1.md)。以下 ID 可直接用于分支、PR 和后续 GitHub Issues，不在本轮批量创建 Issues 或指派同事。

## 1. 交付顺序

**当前小范围试用 P0**：LM-003 的单参数时间模型 → 少量概念/来源与重温记录 → 随时间改变的图谱 → 可选一句话回忆观察 → 短期试用。具体五步及最小验收见[时间原型第 7 节](../design/time-first-prototype.md#7-实现顺序与验收)，运行方式见[P0 运行说明](../development/p0-running.md)，检查证据见[P0 验证记录](../development/p0-validation.md)。先不要求分目标评分、成功升级间隔、场景任务或语音接入；实际 GPU 性能和真实延迟试用仍待完成。

P0-1～P0-3 的软件实现已完成；P0-4 的回忆观察流程已实现，但短期试用尚未完成；P0-5 等待实际使用反馈。42 项模型/模拟数据/KG/服务/镜头/标签测试与 9 条真实 Chromium 交互检查已通过，完整 v0.1 的任务状态不因此整体改变。

下表 M0～M3 是 P0 之后的完整 v0.1 路线，依据试用结果逐步启用：

| 阶段 | 任务 | 阶段完成后可以检查什么 |
| --- | --- | --- |
| M0：定义与风险验证 | LM-001～LM-004 | 真实运行路径、语音访问证据、记忆属性/规则轨迹、共用契约和样例；语音受限可登记阻塞而继续核心工作 |
| M1：记忆闭环先跑通 | LM-005～LM-008、LM-010 | 导入少量真实概念，完成一次解释/细节尝试，保存提示与反馈，重启后得到可解释的记忆/再访状态 |
| M2：日常使用与动态展示 | LM-009、LM-011～LM-014 | 查询/生成隐式刷新、场景与辨别任务、少量复习、真实 3D、应用/总结推动知识修正 |
| M3：通道与试用验收 | LM-015～LM-018 | 原生语音访问同一资源、性能与异常验证、完整验收报告和首轮个人试用记录 |

完整版本的关键路径是记忆目标 → 有效证据 → 可解释估计 → 学习行动 → 延迟检验。P0 先验证其中的时间变化和日常重温体验，不等于 M1 或完整版本已经完成。完整 v0.1 需要真实语音验收；P0 不以语音为门槛。

## 2. 分工方式与规模

建议设置两条责任线，具体人选由协作成员认领，不在文档里替同事承诺时间：

- **A：记忆与数据**——领域规则、KG 适配、事件存储、服务、CLI。
- **B：学习体验与 Web**——任务面板、场景卡、状态解释、动态图谱、可用性。
- **共同**——记忆属性/评分条件、跨通道验证、端到端验收与试用。

规模是拆分提示，不是工期承诺：S 为单一模块/验证，M 为有明确边界的一项能力，L 含跨模块集成，实施前宜拆成 2–3 个 PR。每项先认领，再基于实际开发者经验和验证结果估时。

## 4. 每项交付与验收

### LM-001 — 本地运行验证

- 交付：记录浏览器/OS/GPU/屏幕、Node 版本、知识库与服务所在环境；用最小 Web/API 验证访问目录、重启、桌面/WSL 连接；验证并选择 SQLite 驱动、事务与备份路径，写一份决策记录。
- 完成：本地同源页面和 CLI 访问同一服务，数据库只由服务打开，不需公网或跨系统共享数据库。明确安装/启动方式和受支持环境。
- 检查：AC-18、AC-21 的部署前置条件；不借此实现完整功能或 Obsidian 插件。

### LM-002 — 原生语音可行性

- 交付：真实 ChatGPT 客户端/账户/host 能力记录、项目访问路径、一次真实资源查询及章节引用、修改测试材料后再查的结果；可分享材料使用脱敏记录。
- 完成：明确哪条路径能读真实文件并调用项目工具；无法满足时记录具体限制与缺少的能力，不能仅凭官方介绍标为通过。
- 检查：AC-13 的资源访问前半部分。先在独立测试材料上改版本，不为验证随意修改私人知识正文。

### LM-003 — 时间衰减基线先行

- **当前交付**：定义 `time-only-v0`，以距离最近一次确认学习/重温的时间为输入，采用统一 `D = 2^(-Δt/H)`；所有概念暂用一个全局 H。明确时间起点、未知状态、刷新/重温区别、图例和测试时钟。
- **当前完成条件**：0/H/2H 对应 1/0.5/0.25；同时间重复计算相同；查询不重置起点；复习后只重设起点，不按次数或回答增大 H；状态不冒充实测记忆概率。
- **当前效果观察**：可选的一句话核心解释及简单自评，暂不影响模型。先看时间提示能否帮助管理重温，再决定增加哪种变量。详见[时间先行原型](../design/time-first-prototype.md)。
- **后续扩展**：四类目标、提示等级、争议、信心、场景和 `rules-v1` 的成功升级等规则，待 P0 试用后再展开；AC-22/AC-23 等完整要求仍保留，不作为 P0 完成门槛。

### LM-004 — 契约与开发基础

- 交付：最小 TypeScript 工作区、领域/接口联合 schema、固定时钟入口、合成 KG/题目/事件轨迹、mock API、基本检查命令与 CI。
- 完成：A/B 可独立使用同一 fixtures 开发，事件 ID/操作步骤/版本/错误码无歧义，源代码没有私人路径或资料。React 和 Three 的对象不进入领域契约。
- 检查：至少覆盖未知、首次基线、延迟成功、提示、争议、版本变化、重复递送；为后续语义测试打基础，不以快照数量验收。

### LM-005 — KG 导入与身份

- 交付：概念/章节/别名/来源解析器、语义关系、ID 注册表、内容版本、坏引用报告、增量刷新；对真实 KG 做只读导入演示。
- 完成：中文、同名、别名、循环、自引用、未知关系类型均可解释；纯移动保留身份，歧义移动/拆分/合并暂停映射，不静默继承学习史。
- 检查：AC-06、AC-11、AC-15；正文修改使受影响任务待复核，内容成熟度不进入人的记忆指标。

### LM-006 — 可靠学习记录

- 交付：单写入 SQLite、schema 迁移、幂等回执、追加更正、事务失败处理、导出/恢复、清除指定回答/学习数据的入口。
- 完成：相同事件重发不重复，同键不同载荷报冲突；一个操作允许多个合法步骤；备份恢复保留身份/任务/政策版本与可重放性。
- 检查：AC-01、AC-02、AC-11、AC-12、AC-18、AC-21；写入失败不能被称为记忆失败或保存成功。

### LM-007 — 记忆与遗忘投影

- 交付：纯函数投影器、分目标再访安排、状态解释、巩固动作选择、规则版本与时间依赖缓存处理。
- 完成：固定时间反复刷新相同；跨过到期点即使无新事件也变化；查询/提示成功不升级；根据缺口选择补学、比较或换场景，预算零不出强制任务。
- 检查：AC-03、AC-04、AC-06～AC-09、AC-12、AC-19、AC-22、AC-23。使用行为轨迹断言，不能只测函数返回字段存在。

### LM-008 — 本地服务与即时查询

- 交付：启动命令、Web 静态托管、搜索/fetch/子图/目标/任务/事件/状态/复习接口、管理接口、知识变化检测与结构化错误。
- 完成：同源且鉴权，知识目录可配置；结果带来源版本/索引时间，状态带事件水位/计算时间。知识操作与学习记录失败分别处理。
- 检查：AC-02～AC-04、AC-10、AC-18、AC-21；基础查询不依赖 AI Key。

### LM-009 — CLI 与隐式触发

- **2026-09-17 先行子集**（[Issue #3](https://github.com/wolfhawkld/living-memory/issues/3)）：已实现当前加载范围的 CLI 查询/正文/邻域/状态、明确确认重温与冻结请求重试，提供 progressive-kg Agent 成功收尾钩子和 Web 变化通知。沿用 `time-only-v0`，查询与生成不创建学习起点。详见[运行与验收说明](../development/cli-and-kg-triggers.md)。历史时间线、多维事件和语音适配尚未实现，本任务不整体标记完成。
- 交付：查询、读正文/子图/状态、记事件、刷新索引的 CLI；现有 Agent 的 Ingest/Query/Consolidate 接入说明与示例 wrapper。
- 完成：操作成功边界明确；保留操作 ID；内部读取、呈现、主动回答分开；绕过 wrapper 的文件修改只更新内容，不伪造学习记录。
- 检查：AC-01～AC-04、AC-10、AC-11；失败/重试不会丢查询结果或重复延长间隔。

### LM-010 — 内容保持闭环

- 交付：独立 Web 页面、目标选择/创建、题干/回答、可选信心、提示、来源核对、自评/争议/更正、具体补学动作与保存回执。
- 完成：用户可直接查询，也可自愿先想；核心解释与选定细节分别保存；刷新/重启后能解释状态为何变化。自评标签清楚，不伪称外部客观测量。
- 检查：AC-05、AC-07、AC-11、AC-12、AC-22、AC-23。M1 演示需真实持久化，不能仅用前端内存。

### LM-011 — 场景提取与条件辨别

- 交付：小型人工场景卡编辑/录入、案例族/版本、隐藏候选的任务面板、结构提示→名称提示→查阅、候选和适用理由分开评价、概念比较/反例任务。
- 完成：允许合理替代答案，保留不同提示阶段的用户表述；图谱/搜索/无障碍树不泄题；同案例或近期同批次曝光不能证明新场景迁移。
- 检查：AC-05、AC-07～AC-09、AC-12、AC-22、AC-23；先用少量经过来源核对的场景，不自动批量生成全库题目。

### LM-012 — 记忆管理与复习

- 交付：分维度证据、提示依赖、再访时间、覆盖范围、缺口/混淆对象、可选信心与实际表现对照；轻量复习队列、目标暂停/优先级/预算设置。
- 完成：根据当前工作缺口和到期目标选少量动作，解释为什么选择；不会把会解释等同于会调用，也不会要求清空欠账。
- 检查：AC-06、AC-12、AC-19、AC-22、AC-23。证据不足明确显示，不输出未经校准的记忆百分比。

- 检查：AC-16、AC-22；性能/阅读质量的 AC-17 由 LM-016 完成。建议拆成引擎/交互、状态/布局、真实数据接入三个 PR；静态预览不能作为完成证据。

### LM-018 — 试用与交付

## 5. 可以先并行开始什么

当前小范围试用以 P0 五步为准；以下是后续完整 v0.1 的并行方式。不要为了先做时间原型而提前实现整套 18 项任务。

1. 共同核对 P0/LM-003 的记忆规则样例，明确怎样算一次有效重温、怎样体现时间变化；完整版本的提取和巩固动作仍待后续扩展。
2. A 同时验证 LM-001 的本地部署/数据库，另一位有实际客户端的人完成 LM-002；没有客户端权限的开发者无需等待即可参与核心。
3. LM-004 契约和 fixtures 成形后，A 做导入/存储/规则，B 用 mock API 做内容回忆面板和图谱组件。
4. M1 联调优先演示完整学习证据与重启恢复，再增加场景、视觉表现和日常通道。

每个 PR 应说明对应 FR/AC、实际改变和验证证据；发现规则不合理时先修订领域契约和轨迹，再调整界面。不要让某个客户端保留另一套学习规则。
