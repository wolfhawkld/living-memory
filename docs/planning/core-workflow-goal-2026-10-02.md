# 核心记忆流程：实施与人工验收边界

2026-10-02，用户要求设置整体 goal，持续完成能够由开发和自动检查处理的工作，直到需要本人验收。主线沿用[个人记忆流程](../design/personal-memory-workflow.md)：保持概念关键理解，在工作中想起适用知识，再将应用经验和 insight 整理回知识库。

## 本轮范围

- 补齐旧工作场景的回访入口：只提供题目，提交当次回答后再选择概念和核对资料。新观察追加保存，不继承旧回答、信心或结果。
- 持久标明同场景回访。复用题目可能使答案更熟悉，不能据此认定能迁移到新的工作场景。
- 场景核对后主动进入应用 / 总结：预填可编辑的学习总结，不把错误原答复制为正确知识，不自动声称实际使用成功。
- 用合成知识源、隔离数据库和受控时间串联检查观察、总结、知识修正、资料刷新、延迟投影、重启与回访。
- 沿用单参数时间模型。观察和总结不自动重温，不改变 H；本人确认的长期保持只由手工解除。

不扩大本轮范围到个人参数拟合、自动评分、自动生成场景、语音通道、Obsidian、共享知识或新的开源收尾。已有功能的单点测试无需为了数量重复补写。

## 自动验证与交付

- [x] 场景题目接口遵守账号 / 知识源隔离、分页、只读和无答案提示。
- [x] 回访只复用题面，事前信心重新填写；保存重试保持同一个新事件编号。
- [x] 观察到总结的交接验证当前空间和资料版本，保存失败时不跳转；总结仍须人工编辑确认。
- [x] 同场景标记经过保存、历史、导出恢复后仍保留。
- [x] 完成合成串联测试及全套 Node 测试、构建与主题构建检查。
- [x] 更新本人测试服务与明确操作说明；开发交付沿用长期 `develop`。

开发和自动检查不读取个人知识内容，不写入真实学习记录，不运行本地浏览器视觉测试。

## 必须由本人验证

一次当前工作中的真实问题即可开始，无需先重学整库：

1. 从顶部「场景调用练习」写具体问题，先独立作答，之后查询并核对候选概念，保存线索与结果。
2. 用「保存观察并写应用 / 总结」补充适用条件、局限或 insight；只有真正用于工作才选择实际应用并注明辅助方式和结果。
3. 如发现知识源需要修正，主动选择交给 progressive-kg 的材料，按现有流程修改知识源并刷新；本人核对后确认建议是否纳入。
4. 隔一段实际时间后，从「回访已保存场景」重试。记录最近接触过资料与否，不将时间预览或合成测试当作真实延迟回忆。
5. 遇到一个新的相近问题时另建场景，观察是否更容易想到知识，以及记录流程是否给日常工作增加负担。

人工验收需要回答：旧答案是否保持隐藏；界面与保存是否顺手；核对内容及实际适用性是否正确；隔时回访和新场景是否更容易想到相关知识。软件检查通过只能证明流程和数据行为，记忆收益仍需上述真实使用证据。
