## 可行性与实现方向

可以在现有 React + Three.js / 3d-force-graph 应用内增加浅色主题，复用现有页面、图谱、账号与学习功能。推荐提供同一应用内的主题切换，避免维护两套界面。无需更换图谱框架或修改记忆计算模型。

首版建议提供「深色 / 浅色 / 跟随系统」，保持深色为无偏好时的默认值；浅色的具体配色和光效是待试用的设计建议，并非已经由用户确认。

下表为规划时的代码检查结果；第一项的迁移范围见[主题配色基础](../development/theme-palette.md)。

| 规划时的代码事实 | 对实施的影响 |
| --- | --- |
| [styles.css](../../src/web/styles.css) 已有部分 CSS 变量，但页面和各功能样式仍包含大量固定色值，`color-scheme` 固定为 dark | 先整理语义配色，再覆盖完整页面，不能只替换根背景 |

## 建议的视觉与交互

- 页面：浅灰白背景、白色面板、深蓝灰正文、蓝色交互强调；通过边框和轻阴影区分层次。
- 图谱：淡灰蓝背景，保持空间纵深、镜头聚焦和旋转；未选中节点与边清楚但克制，主动选择仍有明确高亮。
- 状态：`unknown / recent / revisit / stale / pending / retained` 含义不变；浅色主题使用更适合浅背景的同色系色阶。未知与待确认仍有区别，长期保持仍独立标注，选中反馈不覆盖记忆含义。
- 光效：首版优先降低或关闭浅色下的全场景 Bloom，以轮廓、材质和选中反馈保证可读性。现有「发光效果」仍可操作，主题默认光效与用户主动选择的优先级需在实现时统一；深色视觉保持兼容。
- 控件：主题入口使用明确的三选一下拉框，登录页和登录后的工作区均可访问；当前选项与实际主题一致。
- 偏好：匿名页面记住本机选择，登录后按用户 ID 记住此浏览器的选择；同一用户各知识域共用主题。未设置账号偏好时使用既有默认值，退出和切换账号按相应作用域恢复。
- 首版偏好保存在浏览器，不加入学习事件、图谱布局或学习数据导出；跨设备账号偏好同步后续再做。存储不可用时仍可在当前页面切换。

首版目标是覆盖整套应用的浅色外观；不同时增加自定义主题编辑器、定时换肤、每个知识域单独配色或用户上传主题文件。

## 实现约束

1. 主题变化仅更新展示。图谱节点 ID、知识关系、记忆时间、半衰参数、长期保持、答题信心和学习历史全部保持原值。
2. 主题不能加入 GraphView 的实例 key，不能通过重新挂载 App 或重新提交 graphData 来强制换色。以主题对象和专门的更新 effect 修改现有场景、材质与 DOM 标签；标签样式签名要包含主题，事件回调要读取当前配色，避免旧缓存和闭包留住深色。新增/替换的纹理或材质须释放旧资源，关闭浅色 Bloom 时仍要核对最终颜色空间输出。
3. 保留选中节点、相机位置、控制器目标、缩放、2D/3D 模式、领域与跨域展开。用户点击主题控件时沿用现有人工操作暂停旋转的规则，不重建旋转时钟。
4. 页面、列表、图例、曲线、模拟状态与节点使用一致的状态语义。必要文字和图形的对比度按[现有视觉规范](../design/visualization-spec.md#4-状态颜色与图例)核查，并保留文字/形状辅助标注。
5. Mermaid 初始化记录需区分当前有效主题或配置版本；每次渲染任务使用其提交时的主题。旧主题任务完成后不能覆盖新主题结果；主题变化不清空正在进行的回答或重置阅读缩放。现有严格安全配置、源码清理与 SVG 校验继续保留。
6. 普通图片、已发布 HTML 知识页和用户内容不自动反色或改写。本站主题覆盖阅读容器，外部页面保持其自身外观；如果图片自身底色导致不可读，可后续考虑单张图片的阅读底色选项。
7. 不增加第二个 WebGL 画布或额外常驻渲染循环。主题监听与渲染资源随组件生命周期释放，重复切换不能累积开销。
