# 练习卡方向调整：自动生成与维护

日期：2026-10-02。用户查看私人练习卡后指出，自己编写和维护题目、提示、参考答案的工作量过大；明确选择「以后做自动生成和维护，我只少量确认」。

## 当前决定

人工细节、概念比较和场景卡的软件已实现，但暂缓作为本人的日常流程；不再继续扩展手工维护功能，也不把创建一批题目或完成这部分验收作为后续开发的前置条件。代码、已有记录、历史与恢复能力保留，不批量暂停卡片或更改私人数据。

后续方向是自动设计和维护练习，用户主要做练习，并在需要时少量确认。自动化尚未实现，本次不启动新的实现 goal、不选择付费模型或接入外部服务。

近期主线继续是融入阅读、查询和工作，通过 progressive-kg 与既有记录通道外化知识、展示时间状态、保留实际回忆和应用证据；少量复习自愿进行。

## 自动化需要覆盖的完整流程

| 环节 | 系统责任 | 本人需要做什么 |
| --- | --- | --- |
| 选题 | 从新知识、实际查询 / 工作场景和已记录缺口选少量候选，去重并给出选择理由 | 必要时确认相关性；可跳过或关闭 |
| 设计 | 草拟细节 / 比较 / 场景问题、逐级提示、核对依据和来源版本 | 少量接受 / 拒绝；不要求从空白写完整题目 |
| 维护 | 来源变化后自动检测受影响题目、起草修订、归档旧版本，过滤重复与过时项 | 只处理无法可靠判断的变化，不逐题重写 |
| 练习 | 在日常流程里可选地提供少量题目，保存原答、提示条件与人工表现 | 作答、查阅、必要时简短确认结果 |

自动生成一批题目后继续让用户全面整理，不满足这个方向；模型无法支持的内容可以不出题，不靠积累待审核题目维持流程。

## 后续实现约束

- 优先评估复用 progressive-kg 现有 Agent 工作流，在知识生成 / 查询成功后的边界提供候选任务。当前纯代码 hook 只刷新 / 记录既有触发，不能描述成已经具备自动出题能力。
- 模型生成是草案，与人工已核对状态分开。不得用现有 `sourceChecked: true` 冒充用户确认；需要明确草案、自动检查和少量人工确认各自的语义。
- 自动维护保留题目版本、资料版本和旧回答；来源改变不把旧成绩搬到新题，也不静默覆盖用户编辑。
- 生成、查阅、自动修订和模型评语不构成用户成功回忆的证据，不自动重温、改 H 或解除手动长期保持。
- 在设计时确定可使用的资料范围、模型执行方式、生成数量 / 成本上限、取消与失败重试。现有私人账号与知识空间隔离继续适用。

## 恢复开发时的验收重点

先选少量合成概念验证从输入到维护的完整链路，随后本人只需体验少量自动候选与练习。验收重点是题目和依据可核对、来源变化能维护、无需大量手工修补、确认和练习负担可接受；自动软件检查不能替代真实记忆收益验证。

这是后续方向与约束，不代表自动化已经排期或完成。原人工功能的交付和检查记录见[练习卡 goal](practice-cards-goal-2026-10-02.md)与[场景卡 goal](scenario-cards-goal-2026-10-02.md)。
