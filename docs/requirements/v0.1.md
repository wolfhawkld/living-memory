# Living Memory v0.1 需求分析

日期：2026-09-16。状态：**首版开发提案，尚未实现或验收**。本文把此前研究与用户偏好收敛为可拆分的范围；新增工程选择是设计建议，不等同于用户已经确认。

推进方式更新：先实现 [P0 时间驱动原型](../design/time-first-prototype.md)，以单参数曲线、重温时间和少量反馈减少变量。本文的完整 v0.1 范围保留为后续目标；P0 不要求同时实现四类记忆目标、复杂评分、任务调度或原生语音。先行原型的通过不等同于完整 v0.1 通过。

配套：[技术设计](../design/technical-design-v0.1.md) · [开发任务](../planning/development-tasks-v0.1.md) · [验收用例](acceptance-v0.1.md)。研究依据见[共研总结](../research/consolidated-findings.md)与[记忆强化流程](../design/personal-memory-workflow.md)。

## 1. 首版要验证的价值

让已经学过 AI、数学及其他概念的人，在正常阅读、查询和工作中，看见已有知识的联系与需要重新确认的部分，并用少量主动回忆改善两种不同的能力：

1. 给出概念名称，能够重建原理、关键细节、前提与边界。
2. 只给真实问题的结构和条件，能够主动想到相关概念，并解释为什么适用。

用户举出的 orchestrator 例子说明第二种痛点；本项目不负责解决那个系统的架构。图谱数量、查询次数和漂亮动画均不能替代上述能力的观察。

首版交付闭环：**知识与记忆目标 → 编码/组织 → 主动提取或实际使用 → 来源反馈与知识修正 → 更新记忆和遗忘估计 → 选择巩固动作 → 延迟后再次检验。** 动态图谱是观察和操作这个闭环的界面。ChatGPT 原生语音需要接入同一份真实资源，是首版完整验收的一部分。

用户在本次设计中再次明确：核心是同时管理个人知识库与自己的记忆，记忆和遗忘理论应主导开发，而不是给可视化附加几个属性。以下需求及任务排序据此制定。

### 2.1 记忆理论如何主导系统行为

| 研究认识 | 必须进入领域模型的属性 | 驱动的行为 |
| --- | --- | --- |
| 即时表现、延迟保持与迁移不同 | 目标维度、任务类型、距接触/上次尝试的时间、场景族 | 刚看完的正确回答不能充当延迟保持；同案例熟练不能充当新场景迁移 |
| 提取取决于线索与条件 | 允许线索、实际提示级别、查阅、回答来源、先后顺序 | 记录提示依赖，逐步减少帮助；图谱在场景检验中主动隐藏 |
| 遗忘随时间变化但因材料和个体而异 | 最近证据、再访窗口、估计依据、未知项、规则/模型版本 | 无新行为也按时间重算；决定何时值得重新检验；不采用所有人统一的真实遗忘百分比 |
| 提取练习与反馈 | 原始回答、遗漏/误解、纠错、独立性、评价依据 | 先尝试后核对，反馈产生具体巩固动作，随后延迟检验 |
| 间隔练习 | 分目标的档位、下一次时间、有效延迟成功次数 | 有效独立证据才支持延长；访问次数和即时重做不支持延长 |
| 组织、精细加工与自我解释 | 前提、例子、反例、概念关系、自己的解释 | 从具体缺口返回知识库，补来源/关系或记录修正，建立更多可用提取线索 |
| 相似概念干扰与条件辨别 | 混淆对象、适用/不适用条件、误用类型 | 提供一对概念或边界反例的比较任务，分别评价“想到”和“选对” |
| 元认知校准 | 作答前可选信心、实际表现、提示依赖 | 展示自己以为会与实际能做到的差距，不用信心替代成绩 |

首版必须同时保留**观测证据、记忆状态估计、遗忘/再访过程和下一步行动**。知识成熟度不等于记忆强度；学习频率不等于巩固程度。具体属性、投影规则与算法升级边界在技术设计中定义。

## 3. 用户与典型流程

首版为单人本地学习使用；同事参与代码协作不意味着共享私人学习库。每位使用者配置自己的知识根目录和数据目录，不依赖仓库作者的账户或文件路径。

| 入口 | 用户操作与系统行为 | 需要保留的区别 |
| --- | --- | --- |
| 快速查询 | 搜索术语/别名/正文，读到来源和关系，可打开原笔记 | 可以直接查，不强制先答题；查阅不延长复习间隔 |
| 阅读/视频停顿 | 选择一个核心解释或细节目标，先用自己的话回答，再核对来源 | 刚看完后的重建与延迟回忆分开 |
| 工作中想不起 | 可选“先想一下”，写问题结构和候选；提交后再展开图谱/检索结果 | 结果出现前后的回答、提示条件分开 |
| 场景小任务 | 先看人工整理的场景，尝试想到概念和条件，按需逐级提示 | 名称、邻居节点和相关推荐不得提前泄题 |
| 实际应用/总结 | 从节点保存场景、选择依据、使用结果或理解修正，并关联来源 | 使用和总结是独立记录；不能批量点亮所有相关概念 |
| 语音查询/解释 | 在可访问本机项目的 ChatGPT 语音会话中查询或提交一次自愿尝试 | 模型复述不能代替用户回答，未确认播报范围记为未知 |
| 几天后重开 | 自动按当前时间重算；可选一个到期目标，也可以不练 | 不要求每日后台作业，不形成必须清空的复习债务 |

## 4. 功能范围

以下 FR 项是本次建议的 v0.1 完整范围。先做少量端到端能力，每项均有独立验收依据。

| 编号 | 功能与必要行为 | 验收依据 |
| --- | --- | --- |
| FR-01 | 配置并只读接入 progressive-kg；解析概念、别名、章节、来源与有类型的关系；报告坏链接；维护稳定身份与内容版本 | AC-06、AC-11、AC-15 |
| FR-02 | 真实 3D 图谱：旋转/缩放、点击聚焦、邻居高亮、搜索定位、关系说明、中文详情；布局可恢复 | AC-16、AC-17 |
| FR-03 | 核心记忆模型：内容保持、场景提取、适用判断分目标；保存提示依赖、延迟表现和巩固依据，动态估计再访状态并解释未知与不确定性 | AC-03、AC-06、AC-16、AC-22 |
| FR-04 | 查询与生成流程接入：操作成功后刷新索引/状态，区分内部读取与实际呈现；查询不因学习记录故障丢失结果 | AC-01～AC-04、AC-10 |
| FR-05 | 核心解释/选定细节的最小回忆流程：可选信心预测、作答、提示、来源反馈、自评与争议纠正；按遗漏/误解选择巩固动作 | AC-05、AC-07、AC-11、AC-12、AC-23 |
| FR-06 | 场景调用流程：隐藏答案与图谱，先记录结构和候选，再判断条件；接受合理替代答案；区分同案例与新场景；支持相似概念/反例的条件辨别 | AC-05、AC-07～AC-09、AC-23 |
| FR-07 | 学习事件追加保存、重试去重、反馈更正、重启恢复、可解释投影；不同通道使用同一规则 | AC-01～AC-03、AC-11～AC-14、AC-18 |
| FR-08 | 少量复习队列：选择关心的目标、分别安排内容/场景任务，可暂停、跳过、设置预算为零 | AC-08、AC-12、AC-19 |
| FR-09 | CLI 查询/取子图/读状态/记事件接口；ChatGPT 原生语音访问真实数据、引用与最新版本，并能走同一事件通道 | AC-01、AC-13、AC-14 |
| FR-10 | 从概念保存工作应用与总结/洞见记录，关联概念、来源、提示依赖和结果；知识内容修改仍走已有 KG 流程 | AC-10、AC-20 |
| FR-11 | 私人学习数据与共享代码分离；可导出/恢复/清除；错误、待保存和索引过期可见 | AC-02、AC-18、AC-21 |
| FR-12 | 平面阅读、文字列表与键盘入口，减少动态效果、光效降档；视图生命周期不拖累笔记编辑 | AC-16、AC-17 |

首版搜索采用可解释的文本检索与关系展开。生成自然语言答案可继续利用用户现有 Agent 通道；基础查询、练习与状态展示不依赖新增 AI 服务或 API Key。

## 5. 页面与交互结构

- **图谱页**：中央空间图谱；顶部搜索、视角（内容/场景）和阅读模式；右侧概念、关系、来源与状态依据；轻量入口“先想一下”“记一次使用”“复习一个”。
- **尝试面板**：题干、用户回答、提示按钮、提交后反馈；场景任务期间隐藏图谱和候选。始终允许退出并继续查询。
- **记录与安排页**：最近证据、当前目标、下一次建议、暂停项；能查看并更正自己的评分，不追求打卡和清空到期数。
- **设置页**：知识根目录、服务连接、数据目录、动画/光效、练习预算、导出与清除。

状态色只表示当前选定维度。近期搜索、节点选中和路径高亮采用外圈/线条等独立表达。核心解释有证据不代表所有细节有证据；多目标时展示覆盖数量和缺少记录的范围。

## 6. 质量、数据与发布门槛

| 方面 | 首版目标 |
| --- | --- |
| 可解释性 | 每个非未知状态可以追溯到目标、内容版本、事件、规则版本和计算时间 |
| 正确性 | 事件重试不重复计分；固定输入与时间的投影相同；看资料、跳过、评分争议不伪造独立回忆 |
| 性能 | 初拟 300 节点/1,000 边、1080p、内部 DPR≤1.5、中档连续操作中位 FPS≥30；LM-001 记录目标设备，LM-016 实测与调优 |
| 资源 | 隐藏暂停渲染、恢复可操作；关闭清理视图、订阅、渲染循环和 GPU 资源，反复开关不持续累积 |
| 可用性 | 中文长文本/公式在详情区可读；颜色配文字/图例；无 WebGL 时仍可使用列表、查询与学习流程 |
| 数据 | 未知知识目录不扫描其他私人目录；学习库不进 Git；默认不存音频，主动保存的回答片段可查看与清除 |
| 可迁移性 | 导出含稳定身份、内容引用、事件、任务、配置与版本；在新数据目录恢复后同一时刻结果一致 |

性能数字是待验证的工程目标，不是已经取得的结果。约 216 个现有概念页也不等于图谱节点总数。更大规模只做探索，不作为首版同时实现大图引擎的理由。

## 7. 首版暂不包含

自动判定“掌握概率”、全库自动出题和 AI 自动评分、重建完整 RAG/知识生成系统、社交排行与公开学习档案、多人共享学习状态、账号系统、云同步、移动端、内置实时语音引擎、通用插件市场、完整知识编辑器。

保留接口并不意味着同时实现这些扩展。Obsidian 插件属于后续宿主适配，不是 Web 首版的交付条件。

## 8. 验证价值的方法

工程完成与学习有效是两种结论，分别记录。

1. **工程验收**：按 [AC-01～AC-23](acceptance-v0.1.md) 优先验证记忆目标、证据、遗忘估计与学习行动的闭环，再验证导入、真实 3D、保存/重放、CLI/语音一致性与生命周期。语音只能在真实客户端和可访问的真实资源上通过，模拟 CLI 不替代语音验收。
2. **小范围试用**：自选约 10–20 个目标，先保存基线，再观察延迟后的解释与不同场景中的提取；记录提示级别、适用条件、个人信心与实际表现。
3. **负担观察**：实际增加了多少主动练习时间、查询是否被打断、是否愿意继续使用。允许减少目标或完全暂停额外练习。

小样本试用用于改善任务和体验，不据此宣称通用记忆力或认知能力得到因果提升。任务质量与合适间隔仍需继续迭代。

## 9. 开发前优先关闭的风险

| 风险 | 首先验证什么 | 不成立时的处理 |
| --- | --- | --- |
| 浏览器、CLI 与知识文件运行环境不同 | 本地 Web 服务的实际桌面/WSL 路径、网络、启动与重启流程 | 调整服务所在环境与路径配置，保留同一接口；不要求读者搬动原知识库 |
| ChatGPT 语音未获资源访问 | 账户/客户端/host 能力，真实引用、更新后内容、事件写入 | 标记该验收阻塞；可继续核心开发，但不能宣称完整 v0.1 已完成 |
| 概念/章节重命名歧义 | 身份映射是否能可靠保留，无法识别时是否暂停旧任务 | 采用显式人工映射，不凭标题猜测继承表现 |
| 任务和提示污染 | 同题、同批次、刚查阅的回答是否被误算延迟迁移 | 先用少量人工维护任务和保守评分 |
| 3D 对编辑体验的影响 | 目标设备的帧率、中文阅读、隐藏/关闭资源 | 减少光效/标签/可见子图；保留列表与阅读模式 |

运行时/SQLite 驱动与语音连接的验证结果写入 LM-001/LM-002 的决策记录后，再锁定对应实现。记忆估计的操作定义由 LM-003 优先确定，其余模块按公共契约和合成数据并行推进。
