# progressive-kg：首批材料与使用场景

日期：2026-09-15。本文依据目标使用者已确认的偏好，以及一份知识源结构检查。仅作 Living Memory 需求研究；未同步或改写知识库，未执行导入。

## 已明确的起点

目标使用者倾向直接使用已有知识源中各领域已经接触、可能已会应用的概念。日常融入阅读、查询和工作，附带少量复习；视觉目标为深色、有动画的立体图谱（可先 2D），每个概念/实体用清晰颜色标注当前遗忘曲线阶段。

因此，首个场景需要利用已有知识和关系，逐步观察当前回忆与应用表现。已有知识背景作为需求输入；每个概念当前能否解释、如何使用、上次何时学习，则仍需保留未知或自述来源。

## 知识源结构依据

以只读方式检查结构。当前公开文档不列库存统计、分类数量和具体笔记清单；原始数据文件未随源码分发，旧文档描述仍在历史。详见[公开内容复核记录](../releases/public-content-review-2026-10-01.md)。

结构契约包含：

- 导航：Home → Domain MOC → Subdomain MOC → Note。
- 内容披露：L1 定义（`summary` 与正文定义框）、L2 子主题概览、L3 深入细节。
- 概念关系：人工维护在 `## 关系网络`，带“前置、组成、对比、扩展、应用、相关”等标签和说明。
- 目标引用：使用真实文件名，允许指向章节；标题与别名用于显示和搜索。
- 内容来源：frontmatter `sources` 与正文参考资料；`raw/` 是不可变来源层。
- 展示：概念页使用 Obsidian Markdown，动态 MOC 与仪表盘依赖 Dataview；CSS 用于视觉增强。

结构抽查覆盖概念页的导航、内容层级、关系、来源和展示约定；数学、模型、生物、文化历史、语言和技能等领域都可用同一契约表达。

## 内容状态与学习状态的边界

| 现有字段 | Schema 中的含义 | Living Memory 需要另外研究的记录 |
| --- | --- | --- |
| `maturity` | seed/growing/evergreen 内容生命周期 | 用户对某一具体任务的当前表现 |
| `confidence` | 知识证据置信度 | 用户答题信心、评分依据与估计不确定性 |
| `created` / `updated` | 笔记形成或内容修改日期 | 实际学习、提取和使用时间 |
| `verified` | 事实与来源核验日期 | 回忆或应用任务完成记录 |
| `review_due` | 根据知识波动性确定的事实复核日期 | 根据个人目标与表现产生的复习建议 |

基于 schema 与代表性抽查，尚未见这些页面提供个人提取结果、延迟或应用情境字段；这不是对整个库中所有日志与正文记录的穷尽结论。

**产品假设**：学习记录引用原有知识项，同时保留内容和学习两套含义。引用标识、内容版本变化后的题目适用性、记录放在哪里、如何同步，均待接入原型研究，不在本轮增加字段。

## 一个贴近日常使用的候选过程

以工作中需要查询一个已有概念为例：

1. 从搜索进入该概念和相邻关系，直接查看需要的知识层级。
2. 根据当下意愿，选择一个简短任务，例如解释某条关系，或说明当前问题为什么需要这个概念；也可直接继续工作。
3. 记录是否查看定义、是否请求提示，以及回答或应用情境；查看后的解释与查看前的回忆分开处理。
4. 查询路径与关系展开可以产生短暂动画；当新的任务证据足以改变估计时，节点阶段色按其含义更新，并可查看理由。
5. 后续在相关阅读/工作或少量复习中再次遇到该概念，逐步获得延迟表现。

这是一份体验假设。初始接入不要求用户先完成整个知识源的测验；可通过相关任务逐步积累证据。已有内容缺少学习记录时，显示证据不足，具体中性色或其他编码尚未确定。

## 接下来需要解决的研究问题

- 对已有知识，如何以较低负担开始估计当前状态，并保留未知的历史？
- 一个概念包含多个子主题、关系和应用能力时，节点阶段色如何汇总，又如何展开差异？
- 日常查询、带资料的使用、自评和无答案提示的回忆，分别能为哪些估计提供依据？
- 阶段色如何在深色、动画与立体光照下保持清晰，且不与领域分类或临时选中状态混淆？
- 如何复用已有文件、章节链接和关系说明，避免另建需要重复维护的知识内容？

这些问题连接[记忆科学研究](memory-science.md)、[视觉与使用需求](../vision-and-questions.md)以及[验证计划](validation-plan.md)。
