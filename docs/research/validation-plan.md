# 研究与验证计划

日期：2026-09-15。阶段按决策依赖排序，不承诺未经评估的工期。

当前已有[共研结果总结](consolidated-findings.md)和[个人记忆强化流程 v0.1](../design/personal-memory-workflow.md)。可按流程的入口、反馈分支和验收条件开始阶段 2 的纸面模拟；其中的示例间隔与时间预算是待验证设置，不等于效果已获验证。

## 阶段 1：建立科学与需求基础

阅读记忆科学证据，分别记录研究对象、材料、操作、测试延迟、结果、限制，以及产品推论。结合用户的真实知识材料，确定首个场景和视觉偏好。

已确定材料方向为自建 progressive-kg 中的已学概念。研究要补充“已有知识的重新提取、先前学习经历与真实应用”的情境；既有文献中首次学习短材料的结果，需要单独讨论其适用性。

已确定体验方向为深色动态立体图谱（允许先 2D），节点色对应当前遗忘曲线阶段；日常融入阅读、查询和工作，附带少量复习。阶段估计、视觉映射和低负担使用应作为相互关联的研究问题。

用户已进一步明确：AI 与数学为学习主线，原理大意仍有保留而细节模糊；业务/数据建模时难以主动想到适用概念。研究优先区分细节保持、由场景提取候选、适用性判断和实际建模。仍需讨论哪些内容值得随时提取，哪些可在需要时查阅恢复。

产出：可追溯的证据表、首个使用场景、视觉参考与约束、尚未解决的问题。首轮笔记已建立，文献覆盖仍需随场景加深。

## 阶段 2：验证任务与视觉表达

从 progressive-kg 选择一小组已有概念及其真实关系，用纸面或轻量交互原型模拟一次完整体验。选样时兼顾领域、内容深度、用户自述熟悉程度和是否曾应用；样例规模由内容决定，不设为产品容量限制。内容 maturity 与用户熟悉度分别记录。

分别验证：

- 能否复用已有概念、来源与关系，并低成本追加自己的理解或修正。
- 能否用图谱完成一次查找和一次无答案提示的回忆。
- 是否能区分“近期访问”“有回忆证据”“应用尚未验证”等状态。
- 是否能看懂一次任务引发的变化，并追溯到具体记录。
- 能否保留旧观点、添加反例、修正解释。
- 用户是否愿意在自己的学习节奏中再次使用。
- 能否在深色与动画条件下清楚辨认遗忘阶段，区分证据不足，并解释颜色为何改变。
- 可选小练习是否与当前阅读/工作有关；跳过后能否继续任务，额外负担是否可接受。

比较视觉方案时尽量使用同一组内容和任务。记录查找时间、误解的状态、阅读与编辑困难、主观偏好；审美偏好与任务表现分别保留。

允许先在 2D 中验证阶段色、文字、关系与交互，再研究立体化。3D 目标保留；后续比较应额外检查遮挡、定位、镜头移动和深度效果下的颜色辨认。若用模拟状态演示变化，明确标记为演示数据，不写入个人学习记录。

每类回忆任务要预先注明可见信息：哪些节点名、邻居、关系、空间位置和源文可见，何时可以请求提示。图谱本身可能构成线索，带线索表现应单独记录；预设要点与关系的评分标准。查找成功、回忆表现、关系解释和操作负担分别评价。

针对场景调用，先给业务目标、数据特点与约束，记录尚未出现候选名称时的思路和候选；随后才按需给结构提示、候选概念或来源。候选是否由用户主动提出、提示后是否理解联系、能否判断适用和落实到模型，要分开记录。同一题逐步提示仅用于探查与学习，后续阶段会受前面提示影响，不能当成相互独立的能力测量。

进入下一阶段的条件：用户认可一个可理解、愿意使用的任务闭环，明确首要平台约束。静态效果图无法回答全部交互问题。

本阶段的再次使用意愿仅作为可用性与接受度证据，不能替代学习收益评价。

## 阶段 3：验证载体和数据边界

针对候选载体做短小的技术原型，输入使用同一份知识与任务记录。优先检查自定义视图、持久化、重新打开后状态、导出恢复，以及目标设备体验。

开源可用性通过可复现安装、普通用户可理解的数据、可替换的模型和存储边界来评审。若选择 Obsidian，还要验证插件生命周期、主题样式、移动端适配与同步情境。检查项详见[技术载体研究](platform-options.md)。

进入实现的条件：关键约束经过原型检验，记录选择理由和代价，再形成正式架构决策。此阶段之前不固定图数据库、前端框架或复习调度器。

## 阶段 4：个人试用与学习收益评估

先观察日常使用是否成立，再检验更复杂的自适应调度与社交。首次试用侧重可行性，不从少量个人数据宣称普遍教育效果。

| 目标 | 可观察指标 | 解释时的限制 |
| --- | --- | --- |
| 记得住 | 延迟后的无提示回忆、提示次数、概念要点正确性 | 题目与测试本身影响记忆；需记录延迟与练习次数 |
| 讲得清 | 解释中的关键关系、适用条件、反例 | 文采、篇幅与信心不能替代正确性 |
| 用得上 | 未练过的案例中的方法选择、理由与结果 | 熟悉领域的近迁移不能证明普遍远迁移 |
| 想得到 | 未显示候选名称时，提出相关概念的用时、理由与遗漏 | 案例本身是线索；候选数量多不等于质量高，合理路径可能有多条 |
| 选得准 | 对候选前提、反例、约束和验证方式的判断 | 给出候选后的成功不计为自发调用；不默认每个业务问题只有一个正确概念 |
| 会修正 | 有依据的观点更新与后续验证记录 | 更新次数与图谱增长并不自动表示认知改善 |
| 用得久 | 录入与维护时间、任务负担、实际自愿使用 | 连续打卡只能说明行为，不直接测量学习收益 |
| 估计可信 | 预测回忆表现与后续实际结果的一致程度 | 数据少时应呈现证据不足，不能假定已完成个体校准 |

可以预设一周与数周后的观察窗口，具体时间要匹配用户目标。这是评估安排的例子，不是通用最佳复习间隔。

使用遗忘可视化或自适应建议时，需要标明它们是模型估计。验证前预设延迟窗口、题目与提示条件，保存预测，再比较实际结果；数据不足时呈现依据缺口。探索性试用可以采用初始安排，但只有验证后的证据才能支持关于预测准确性或学习改善的结论，不称其为最佳间隔。

## 把不同贡献分开验证

需要分别检验“主动练习有用”“图谱界面有用”“自适应安排有用”，避免一次加入所有功能后无法解释结果。

候选比较：

1. 常规笔记工作流与加入提取任务的工作流：观察加入任务的实际收益和成本。
2. 同样的提取任务、不同呈现方式：观察图谱相对于文字列表是否额外帮助关系理解、定位或使用意愿。
3. 在任务已成立后，再比较简单安排与自适应安排。

如果进行比较，应尽可能使用难度相近的不同知识项，随机或平衡分配，记录先前熟悉程度、学习时间、题目形式和反馈条件。避免把同一知识重复用于多个条件而忽略练习累积；保留预先约定的延迟测试与新案例。

对 progressive-kg 的初始评估应保留“不记得上次何时学过”等未知值，不能用文件 created/updated/verified 日期替代用户学习时间。先收集自述与少量任务表现，不默认全部已掌握或全部从零开始。初测也是一次练习，应计入后续比较；已非常熟悉的材料需要考虑成绩接近满分时难以观察改善的问题。

真实生活很难完全控制。首轮个人试用应保留原始表现和主观体验，将结论限制在观察范围内；需要对外声称学习效果时，再设计更充分的研究。

## 需要通过试用回答的产品假设

- 图谱重建是否比直接文字回忆更适合这个用户和这类知识？
- 在工作中记录真实应用，是否有足够收益抵消操作负担？
- 多维状态能否帮助选择下一步任务，还是增加理解成本？
- 关系与反例任务能否发现单概念问答遗漏的理解问题？
- 比较表面不同但结构相同的案例，是否帮助后续自发想到相关概念？
- 加入表面相似但不适用的案例，是否改善适用条件与边界的判断？
- 长期变化的视觉表达是否促成适量练习，同时允许自然暂停？
- 同伴讲解和反馈是否值得增加分享与协作复杂度？

先记录否定结果与误解，再修改设计。研究的价值包括帮助排除看起来吸引人但不适合实际使用的方案。
