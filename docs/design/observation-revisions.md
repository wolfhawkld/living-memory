# 回忆自评更正与撤销设计

日期：2026-10-18。状态：OR-01 设计、OR-02 纯逻辑与 OR-03A 独立内部账本已实现，当前服务及产品入口尚未接通。适用于概念解释、场景调用和飞书脑中回忆已经保存的 `Observation`；私人练习卡保持原安排。以下迁移、接口及 v2 兼容规则仍是后续实施目标。

用户可以纠正误点的自评、暂不采用一条不可靠的证据，再恢复采用。每次决定单独追加，原回答与当时条件保留。接通后，统计将读取有效判断，历史仍能说明最初如何记录、后来为何更正。这些操作不改变 `time-only-v0`、重温起点、H 或手工长期保持。

## 用户操作

从节点的已保存观察历史进入操作，原答默认折叠。界面并列显示原始评分、当前有效评分和本次拟提交评分；原因必选，补充说明可空。

| 操作 | 可执行状态 | 结果 |
| --- | --- | --- |
| 更正自评 | 当前采用，评分确有变化 | 新判断替代当前评分参与统计，原始评分不改写 |
| 暂不计入统计 | 当前采用 | 本条不再参与有效证据统计，历史保留并标记原因 |
| 恢复采用 | 暂不计入统计 | 恢复撤销前最后采用的判断；从未更正时恢复原评分 |

例如，原记录误选「清楚」，可以更正为「部分」；若后来发现当时的提示条件不可靠，可以暂不计入统计。恢复采用不会擦除中间的决定。要撤回一次更正，应明确更正回原值。

尚未同步成功的原观察不能修订。正在作答或进行查询前回忆时不开放此入口，防止历史原答影响当前任务。更正旧版本或已移除概念的历史，不要求当前知识正文仍存在；评分仍属于原观察的版本。

## 可以更正的内容

| 内容 | 首版处理 |
| --- | --- |
| `rating` | 允许在 `clear / partial / blank` 中重新选择 |
| 已有 `learning.outcome / basis` | 成对提交新的判断，沿用现有枚举及校验；明确结果必须有非 `unknown` 的依据 |
| 没有 `learning` 的旧观察 | 只允许更正 rating，不补造 learning |
| 原答、作答方式、概念及版本、任务、场景、回访标记、适用性说明 | 冻结，不能把后来的理解改成当时的原答 |
| 提示、曝光、事前信心及其时间、作答时间、原模型与起点、冻结衰减值 | 冻结，不能事后升级为独立回忆或重新预测 |

`rating` 是自报清晰程度，`outcome` 是核对原回答后的判断，两者不强制互相映射。飞书脑中回忆的「清楚 + 未核对」仍合法；修改自评不能把 `mental` 变成书面原答或校准样本。核对依据针对当时的原回答；后来成功应用，应另存应用记录。

## 追加决定契约

新增独立的 `ObservationRevision`，与知识内容的 `corrections` 分开。请求结构为：

```ts
interface ObservationRevisionRequest {
  eventId: string;
  observationEventId: string;
  previousEventId: string | null;
  occurredAt: string;
  action: 'revise' | 'withdraw' | 'reinstate';
  reason: 'input-error' | 'rechecked-original' | 'unreliable-evidence' | 'other';
  note?: string; // 最多 1000 字符，可空。
  assessment?: {
    rating: 'clear' | 'partial' | 'blank';
    learning: null | {
      outcome: 'success' | 'partial' | 'failure' | 'unverified';
      basis: 'self-check' | 'application' | 'unknown';
    };
  };
}
```

请求按字段白名单严格解析，未知字段及客户端另传的归属、原答或提示条件直接拒绝。只有 `revise` 携带完整 `assessment`，不用任意字段 patch。原观察有 learning 时必须带 outcome / basis，无 learning 时必须为 null。`withdraw / reinstate` 不接受 assessment，由服务器按已有链计算结果。

服务器从认证命名空间内的原观察派生 conceptId 和 sourceRevision，并增加服务端 recordedAt；客户端不能指定其他归属。独立表保存原请求、前驱、动作、原因及审计时间，事件 ID 加入该命名空间的全局幂等检查。

事务内先检查同 ID 同规范载荷，返回原 duplicate 回执；即使链已前进，也不把已成功的重试误判成新冲突。同 ID 不同载荷拒绝，再校验原观察已持久化、前驱等于唯一当前尾，以及动作符合当前状态。新 revise 若与当前有效 assessment 完全相同，由服务器拒绝，不只依赖界面禁用。两个页面同时修改时只接受一个后继，冲突不能自动改前驱重发。

occurredAt 在确认时冻结，不早于原 observedAt 或前一决定的 occurredAt，不得伪造未来时间。recordedAt 由服务端保存并保持链上的接收时间单调；重试不生成新的接收时间。原观察和其 request_payload 永不被修订请求改写，旧观察重试仍只确认原请求。

## 原始记录与有效判断

保留 `getObservations()` 的原始读取语义，新增纯函数 `projectObservationAssessments(rawObservations, revisions, asOf)`，返回采用中的派生证据、每条原观察的当前状态和审计摘要。有效对象明确标为派生结果，不混入原始导出。

投影只采用 recordedAt 不晚于 asOf 的合法链前缀，原观察仍沿用既有时间与资料版本过滤。排序使用原 observedAt；今天修正一条旧记录，不变成今天新做了一次练习。坏链、分叉或缺少父记录时，受影响证据标为待核对并排除，不回退采用原评分；正常写入和导入提前拒绝这些结构。

| 读取用途 | 数据依据 |
| --- | --- |
| 信心校准、场景结果、前后观察、时间与表现对照、薄弱点汇总 | 采用中的有效判断，继续保留原提示、曝光、信心和时间条件 |
| 历史主列表 | 原观察与独立的当前状态、修订审计；正文继续默认折叠 |
| 原观察总数、每日已尝试概念、预算及复习续做 | 原始提交事实，不因更正扣除或返还预算 |
| 场景回访题面 | 原始场景仍存在，撤销评分不等于删除题目 |
| 学习导出与完整备份 | 原观察和完整修订链，不把有效评分覆盖回原记录 |
| 飞书旧操作回执及批次总结 | 保留当时提交的自报；当前有效统计在 Web 查看 |

界面区分原记录总数、有效样本数、暂不采用数及待核对数。撤销不产生补做义务，不重开旧会话、不重发卡片，也不撤销另行确认的重温事件。

## 接口与保存反馈

使用 `GET /api/observations/:observationEventId/revisions` 读取原观察、当前状态、尾 ID 和有界审计分页；`POST` 同一路径追加决定。路径与请求中的父观察 ID 必须一致。接口沿用认证、来源、CSRF 与实例保护，不接受其他账号的原观察或修订。

节点历史的原 entries 保持原义，另附每父观察的有效状态及 `observationRevisionCount` 水位。新增决定时使全部已载历史分页失效，不能因为主历史 total 不变而继续展示旧评分。沿用 `observation` 变化通知，客户端重新读取完整投影，不在本地累加评分变化。

服务确认后才更新汇总。离线或超时保留固定 eventId、前驱、动作、评分和发生时间，显示待同步或保存结果未知；不可乐观显示为已保存。冲突保留原请求，重新读取当前链后由本人确认新的决定。首版在 Web 提供入口，飞书继续保存原始自评，不新增编辑命令。

## 导入和完整迁移

学习 JSON 新导出统一使用 `schemaVersion: 2`，即使没有修订也不再导出 v1。文件包含原 observations 和完整 `observationRevisions`，不提供去掉修订链的 v1 降级导出。新版可读取已知 v1，将其传入修订集合视为空；合并导入时，空集合不删除当前已有的修订。

原观察和修订使用同一概念映射，父事件与前驱事件 ID 保持不变。预览、冲突检测、token、计数、写前备份和提交事务必须覆盖修订链：父记录须存在且归属相符，链必须无环、无分叉、前缀与当前已保存事件一致。新节点只能接当前尾；缺父、错归属或分叉阻止整次导入，不按时间挑选胜者。新修订使旧预览失效，精确重复导入仍幂等。

完整 bundle 升为 `version: 2` 并声明 `learningSchemaVersion: 2`。新版验证已知 v1 bundle 后，只在新的恢复目录迁移；旧工具应在创建目标目录前拒绝 v2。恢复继续保持新实例、凭据撤销和连接器隔离规则，原始观察与修订链都必须往返保持。

SQLite 增加学习 schema 与最低读取版本标记及修订表。已知旧库在离线租约、升级前备份和事务保护下迁移；部分升级、标记与实际结构不符或未知未来版本拒绝。发布时同步软件版本，但软件包版本不能代替 JSON、bundle 和数据库各自的兼容校验。

现有旧程序不会读取新增的数据库标记，因此这些标记不能阻止所有旧二进制直接打开新库。**已升级目录不支持原地降级**；回退只能把升级前完整备份恢复到另一个新目录，再配套旧程序运行。

## 客户端协议与待同步

新增学习 HTTP 协议 v2，阻止旧客户端忽略有效判断、仍把原评分当当前结果：

| 入口 | 契约 |
| --- | --- |
| `GET /api/session` | 保留握手能力，返回 `learningProtocolVersion: 2` |
| 需要认证的应用数据读取、写入、导入和导出 | 新 Web／CLI 完成握手后统一发送 `X-LM-Learning-Protocol: 2` |
| 缺失或不支持的协议 | 返回 `426 LEARNING_PROTOCOL_REQUIRED`，不执行数据操作，不退回原始评分 |
| 登录、会话、健康检查和静态资源 | 豁免学习协议检查，保留升级和重新登录入口 |
| 原生 SSE | 使用非秘密参数 `learningProtocol=2`，仅此明列入口允许查询参数；其他路由不能以查询参数替代 header |

新客户端连接不声明协议的旧服务时，明确要求升级，不静默回退兼容写入。协议校验与既有认证、来源、实例及 CORS 边界一同测试。旧客户端已经显示的内容不能被追溯抹除，升级后仍需刷新页面；不能只靠变化通知让旧代码正确解释新证据。

修订待同步使用独立版本的存储 key，按账号、知识源和实例隔离，复用已有协调锁与重试引擎。原学习队列字节保持不变，旧页面不能把不认识的修订项当成普通学习请求消费。修订请求的显式清除或冲突归档不删除已经保存的审计；服务端拒绝不改变前驱，不自动另造事件绕过冲突。

## 纯逻辑基础的实现范围

OR-02 新增[共用契约](../../src/shared/observation-revisions.ts)与[纯投影](../../src/core/observation-revisions.ts)。请求解析严格区分三种动作、评分白名单及服务端归属，输出重新构造并冻结。投影按 recordedAt 截断，再验证当前可见链；不可归父的损坏记录使整个计算拒绝，能归父的坏链只排除对应证据。无序或重复输入、循环和 ID 冲突有确定的处理结果。

`projectObservationAssessments` 接收同一已授权命名空间的原始观察与完整修订集合，返回带 `derived-observation-assessment` 标记的派生条目，以及各父观察状态和无原答／说明的审计摘要。它不读取当前知识库或系统时钟。`prepareObservationRevision` 只准备候选事件或确认输入链中的重复请求；两个写入方仍可能分别准备出候选，真正的全局幂等、数据库事务和前驱比较由 OR-03 实现。

[契约测试](../../tests/observation-revisions-contract.test.ts)、[投影轨迹](../../tests/observation-revisions-projection.test.ts)及[统计串联](../../tests/observation-revision-evidence.test.ts)覆盖三动作、未来记录、坏链隔离、重试、输入保持、校准与原始时间顺序。已有学习汇总、历史、预算、导出和飞书代码尚未调用这些模块；合成测试不代表服务已经保存修订，也不代表后续 12 条端到端要求全部通过。

## 内部账本与启用前的剩余工作

OR-03A 新增[服务端账本](../../src/server/observation-revision-store.ts)与[有界历史契约](../../src/shared/observation-revision-history.ts)。账本接收已有 SQLite 连接和命名空间；父观察、其他学习事件的读取回调必须绑定同一连接和命名空间，在本次事务内读取，不能外连或写入。命名空间不得含首尾空白或控制字符，UTF-8 不超过 256 字节，以保证分页游标可往返。构造器只检查所需结构，不打开或关闭数据库，也不自动建表、迁移或提交调用者事务。显式建表函数只提供未来升级事务所需的 DDL，本轮仅在临时合成库内调用。

追加使用 `BEGIN IMMEDIATE`，在锁内确认原成功重试、其他事件 ID、原父与完整链，核对尾部后插入并提交；失败只回滚自身已成功开始的事务。精确重试返回原接收时间，评分与原观察分表保存。读取历史以独立保存点形成一致快照，按尾至根分页；状态不夹带完整审计数组。父链变化使旧游标失效，其他父的新增只更新命名空间水位。机器时钟倒退不会隐藏已经保存的决定，损坏记录拒绝读取，不恢复采用原评分。

[账本单测](../../tests/observation-revision-store.test.ts)与[合成集成测试](../../tests/observation-revision-store-integration.test.ts)分别核对契约和真实 SQLite 事务，包括两个进程从同一前驱并发提交、锁冲突、外层事务及写入失败，以及原学习表、预算和重温起点保持原样。这些是临时库中的模块验证，不表示真实服务已经接受修订。

当前 `Store`、HTTP、统计、Web／CLI、导入导出及完整备份均未调用账本；学习 JSON 和 bundle 仍为原格式，当前数据库也未升级。账本自己的追加可以检查其他事件，现有写入方尚不会反向检查修订 ID，因而不能把本子项当作全产品的全局幂等。接入前还须把原写入方的全局查重放进各自写事务。

OR-03 后续按以下依赖顺序推进：严格结构识别与离线升级前备份；学习 JSON／bundle v2 的导入恢复；现有 Store 的双向查重、有效统计与历史分页失效；协议 v2 及 Web／CLI 最小握手。全部门禁具备后才注册可写接口，OR-04 再提供操作按钮和独立待同步。OR-03A 完成不代表 OR-03 整体完成，也不触发私人库升级或服务部署。

## 必须覆盖的验收轨迹

以下是整个功能实现后的验收要求，OR-02 的纯逻辑覆盖不能替代存储、恢复与客户端路径：

1. 事前信心 80% 的原答被记为 success，复核后更正为 failure：当前校准成功率和 Brier 等随有效判断变化，原答、信心、observedAt、H、起点、长期保持和预算不改。
2. 暂不采用使该条离开有效样本，但历史和真实完成数不减；恢复采用回到同一旧样本，不新增一次练习。
3. 脑中回忆或已曝光记录即使改为 success，仍不能进入独立校准；无 learning 的旧观察不补造 learning。
4. 原本合法但 rating 与 outcome 不对应的记录不因升级被拒绝或自动改写；两者的判断语义分别保留。
5. 同 ID 同载荷重试返回 duplicate，异载荷冲突；相同前驱的并发只接受一个，超时保留原请求而不自动重建前驱。
6. asOf 只采用当时已接收的决定，修订时间不改变原观察的排序、间隔或所属自然日。
7. 当前资料已改版或缺失时仍能修订原存档观察；旧表现不被搬到新的概念或版本。
8. v1 导入不删除现有链，v2 往返保留原观察与全链；错父、环、分叉回滚，过期预览要求重读。
9. 使用实际旧 b16 解析器验证 JSON／bundle v2 被拒绝；新程序拒绝未知 schema。数据库直接原地降级不列为支持路径，另验升级前备份的隔离回退。
10. 旧 Web／CLI 无协议请求被 426 拒绝且零写入；新客户端同协议可用，SSE 查询参数例外不能扩散到其他数据路由。
11. 历史旧页已加载后，另一页面追加决定，水位使所有已载页及汇总更新；作答期间不能打开更正历史泄露原答。
12. 飞书旧操作重放仍为原观察的 duplicate，不重开批次、不退回预算，也不撤销独立重温。

首版 UI 只覆盖节点历史里已经能够定位的持久化观察。孤立或未定位记录保留在导出中，API 按原事件 ID 处理；本项不再扩成全库审计工作台。暂不计入统计也不是隐私删除，永久清除原回答属于另一个数据控制需求。
