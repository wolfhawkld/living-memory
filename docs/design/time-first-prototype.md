# 时间驱动的先行原型

日期：2026-09-16。状态：根据用户“先减少变量、以时间维度验证，再扩展”的建议收敛的开发提案；P0 已可运行并进入小范围试用。33 项模型/模拟数据/KG/服务测试与 7 条真实 Chromium 交互检查已通过，实际 GPU 性能和真实延迟试用仍待验证。它先于完整 v0.1，替代将四类记忆目标、复杂评分和调度同时作为起步条件的安排。

关联：[LM-003 与开发顺序](../planning/development-tasks-v0.1.md) · [P0 运行与联调](../development/p0-running.md) · [P0 验证记录](../development/p0-validation.md) · [完整需求](../requirements/v0.1.md) · [后续技术设计](technical-design-v0.1.md)。独立 Web、progressive-kg、3d-force-graph + Three.js 的方向保持不变。

## 1. 首先验证什么

**一组真实概念，在明确学习/重温后建立时间起点，按统一曲线随时间改变展示；用户可以查看、重温并留下少量体验记录。**

先检验三件事：时间变化能否帮助发现久未重温的知识；查看和重温是否顺手；粗略提示与实际回忆是否经常相悖。这个实验能够检验使用体验和时间基线的局限，不能单独证明已经提高记忆或拟合了个人遗忘曲线。

## 2. 最小模型：时间输入、一个全局参数

建议使用单参数指数衰减作为工程基线：

```text
Δt = 当前时间 − 最近一次用户确认学习/重温的时间
D(Δt) = 2 ^ (−Δt / H)
```

- `D` 是 0–1 的**时间衰减指标**，用于驱动曲线、颜色和重温排序；不是回忆正确率或“脑中剩余知识比例”。界面标为“重温时间指标”，不显示“记忆度/遗忘百分比”；`D=0.5` 只表示经过一个设定的 H。
- `H` 为全局半衰时间，所有概念暂用同一个值。建议试运行先取 7 天，仅为便于观察的产品参数，不是研究确定的最佳值。首次观察期固定参数，不边用边自动拟合。
- 其他量均固定：曲线起点归一为 1，复习后只重新设置时间起点；先不根据次数、答题结果或概念难度改变斜率。
- 该函数的绝对下降速度前快后慢，但它只是一种简洁的函数选择，不能称为艾宾浩斯原始公式。经典实验使用的材料、测量指标和不同拟合函数与本项目的概念知识并不等同。[Murre & Dros, 2015](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0120644)

这样实际变化的模型输入只有 `Δt`，需要试定的模型参数只有 `H`。多维记忆属性仍是后续解释误差的候选，不要求首轮一起实现。

## 3. 时间起点与最少记录

| 数据 | 起步处理 |
| --- | --- |
| 知识引用 | 保留概念 ID、相对来源、内容版本和关系；原 KG 只读 |
| 学习/重温事件 | 事件 ID、概念 ID、发生时间、来源版本、用户确认的行为类型；重复递送不重复写入 |
| 模型配置 | `model_version = time-only-v0`、全局 H、配置版本 |
| 可选观察 | 概念/版本、回答时间、当时 Δt/D/配置版本、用户原话或自评、是否先看了资料 |

已有知识没有可靠学习日期时显示**未知**。可填写自己记得的日期并标注为用户估计；不知道就保持未知，下一次真正学习/重温时开始计时。不能使用文件创建、修改或 `verified` 日期代替。分析观察结果时，估计日期与系统记录的确认事件分组呈现，不把两者视为同样精确的延迟。

“确认已学习/重温”只表示发生了一次用户确认的行为。曲线从 1 重启是归一化约定，不表示完全掌握。复习次数不自动增大 H，避免在最初版本引入未经检验的巩固公式。

普通搜索、打开节点、Agent 读取、生成完成仅触发按当前时间刷新，**不重置时间起点**。用户完成重温后主动确认才产生事件；未来可让通道提交同样的明确确认事件。

若来源内容发生实质修改、身份映射不明或时间落在未来，显示待确认，保留旧记录，不静默套用新版本。少量原型材料出现歧义时允许人工重新关联，无需先实现通用拆分/合并系统。

## 4. 最小交互闭环

1. 只读接入一组自选真实概念，例如 10–20 个及其关系；无日期为未知。
2. 展示深色 3D 图谱，保留点击聚焦、来源详情与时间图例；无需先实现全部光效和大图优化。
3. 节点显示最近重温时间、经过时长、模型曲线；按经过时间/指标排序提供一个轻量“值得重温”列表。
4. 用户可以直接读资料并确认重温，也可以自愿先用一句话解释核心意思，再对照来源。
5. 保存事件，按新时间起点重新展示；关闭后重开自动计算，无需后台持续运行。

默认图例可以固定为：`D > 0.5`“近期重温”、`0.25 < D ≤ 0.5`“建议再看”、`D ≤ 0.25`“较久未重温”；未知独立显示。边界只用于首轮交互实验，不能称为生物学阶段或实测遗忘。这里的珊瑚色不代表观察到回忆失败，必须与后续 `rules-v1` 的“需巩固”图例区分。P0 只有未知和三个时间区间；版本待确认、估计日期等以中性标记说明，不增加失败颜色。

增加一个开发/演示用时间滑块，快速预览一天、一周之后的变化；明确标记模拟时间，滑动只改变只读投影的 `as_of`，不能写学习事件或覆盖真实时钟。模拟期间禁用确认重温和保存回忆观察，返回真实时间后才能保存。日常打开或查询按真实时间计算。

## 5. 少量观察，暂不增加模型输入

自愿检验只采用一种固定条件：给出概念名、收起定义/详情，先解释核心意思，再核对资料并自评“能解释／有些模糊／想不起”；允许跳过。先记录当时曲线值和回答，再展示资料。若近期看过资料，标明受提示，不能当作纯延迟回忆。

记录用户自述的“未先查资料／查过资料／不确定”；应用已知的详情/答案曝光优先保留，不能被自述未查覆盖。系统无法观察全部外部阅读，不将自述等同于实验控制。查过或不确定的记录仍可保存，但不纳入未查资料组的比较。

观察结果暂不改变 H、曲线或颜色，只用于检查模型。这样保持少变量，又能看到“显示久未重温但仍解释得很好”“刚重温却说不清”等误差。反馈是自评，不冒充客观评分；一次结果不诊断遗忘原因。

检验本身也可能成为一次新的接触。若用户只是测试而没有确认学习/重温，保留观察时间，不自动重置曲线；分析时区分第一次检验和已多次检验的条目，不把反复测试后的表现解释成未经干预的自然遗忘。

可先运行约一周，观察不同时间段的少量概念；不要求每日答题或完整实验设计。没有回忆观察时，只能报告交互体验，不能声称曲线准确。没有对照条件时，也不宣称记忆改善由系统导致。

## 6. 先做与后做

| 本轮保留 | 后续扩展，不阻塞原型 |
| --- | --- |
| 概念/关系最小导入、可追溯来源 | 全库增量解析、复杂重命名/拆分映射 |
| 一个时间函数、一个全局参数、明确学习起点 | 分概念参数、个体化拟合、复习次数强化 |
| 记录重温、重启恢复、基础导出 | 完整评分修订、复杂迁移、自动任务调度 |
| 动态图谱、详情、可选一句话回忆观察 | 四类独立目标、场景库、分级提示、元认知面板 |
| 本地 Web 与最小本地服务 | CLI 全流程接入、原生语音、Obsidian |

语音仍是完整 v0.1 的既定目标，但不作为这个先行实验的门槛。时间基线也不解决用户“场景里想不起概念”的全部痛点，后续根据试用结果继续补场景线索与检索能力。

## 8. 如何决定增加哪个变量

- 同样久未重温的概念差异明显：先考虑分概念 H，而不是同时增加所有维度。
- 多次有效重温后明显更耐久：考虑 H 的更新规则，并明确什么事件支持更新。
- 名称提示下解释很好，工作场景仍想不起：加入场景提取目标；仅调曲线无法解决线索问题。
- 自评和实际解释经常不一致：再完善评价要点与反馈。

原始时间事件、模型版本和可选观察保留，后续可用相同记录比较模型；前期未采集的提示或场景信息保持未知，不回填猜测。
