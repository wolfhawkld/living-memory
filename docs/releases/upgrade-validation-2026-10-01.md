# 版本准备与合成恢复验证（2026-10-01）

本记录属于 OSS-08。源码检查基线为 `e6c5ac7`；本轮将项目元数据准备为 `0.0.1-preview.1`，应用、数据库、JSON 格式、依赖解析和记忆规则没有变化。操作步骤见[升级与恢复](upgrade-and-recovery.md)，契约见[兼容约定](versioning-and-compatibility.md)。

以下“未创建 tag/release”及准备状态记录产生于发行前；实际发行结果以[版本说明](v0.0.1-preview.1.md)关联的 GitHub 发布为准。

## 环境与范围

- WSL2/Linux x86_64，Node 22.23.1、npm 10.9.8。
- 公开 `fixtures/demo-kg` 复制到新建 `/tmp` 目录，另建独立数据、备份与故障后保留目录；两名合成账号，未读取个人数据、真实知识源或私密配置。
- 一次性演练脚本直接创建当前 `createApp`，通过隔离的回环 HTTP 端口请求；不使用日常服务端口，不启动浏览器。
- 2026-10-01 查询 GitHub 时，tag 和 release 列表均为空。此前文档提交 `e6c5ac7` 的 [CI](https://github.com/wolfhawkld/living-memory/actions/runs/36846175655) 全部通过；这不是未来最终发行提交的验证结果。

## 完整复制与原路径恢复

| 阶段 | 操作与结果 |
| --- | --- |
| 初始化 | 合成管理员载入 16 个概念、32 条关系，初始全部未知；创建独立成员及其一篇合成笔记 |
| 写入样本 | 管理员确认重温、保存观察、将当前 H 从 7 改为 10、设置另一节点长期保持、布局和每日预算 3；成员确认自己的重温 |
| 备份 | 停止 HTTP 服务并关闭 Store/Accounts；完整复制数据目录，另复制外部知识源，逐文件 SHA-256 与原目录一致 |
| 模拟后续变化 | 重启后新增重温、把 H 改为 17，并修改合成知识正文；确认这些变化与备份不同，再停止 |
| 恢复 | 将变化后的目录另存，使用原备份完整恢复到原数据/知识路径；启动前逐文件校验一致，未覆盖原备份 |
| 核对 | 两个账号重新登录，namespace 保持，逐项比较恢复前后的学习导出（仅排除导出时刻）；原事件、配置历史、观察、保持、计划与布局一致 |
| 重试与身份 | 原重温请求返回幂等重复回执，不新增事件；恢复后旧 CLI 设备 token 被拒绝，服务按既有行为轮换凭据 |

恢复后的观察仍冻结 H=7，当前配置仍为 H=10；长期保持与原起点保留。原备份目录在整个恢复和启动过程后，逐文件摘要仍与备份时一致。成员数据未混入管理员导出，独立账号登录与知识空间保留。

这证明当前实现的停止后复制、原路径恢复和重启行为；没有模拟一个改变数据库结构的新版本，也不证明任意跨版本、跨根路径或跨机器迁移可用。浏览器草稿、CLI review 回执文件、导入/身份备份以及应用/修正等全部事件类型未在本次演练逐项构造；它们的范围仍按完整目录和专项测试说明，不能从本次结果扩大推断。
