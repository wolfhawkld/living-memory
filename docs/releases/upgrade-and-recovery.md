# 完整备份、升级与恢复

更新：2026-10-01。适用于本机部署；目前已用合成数据验证停止服务后的完整复制与原路径恢复，见[演练记录](upgrade-validation-2026-10-01.md)。数据库迁移能力和版本边界见[兼容约定](versioning-and-compatibility.md)。

## 先确认备份范围

| 范围 | 要保留什么 | 页面导出能否覆盖 |
| --- | --- | --- |
| 完整数据目录 | 两个 SQLite 库、可能存在的 sidecar 文件、成员知识与附件、目录内的设备文件、导入/身份备份等 | 不能；学习 JSON 只覆盖当前登录空间的支持内容 |
| 外部管理员知识源 | Markdown 正文、关系、附件及源目录结构 | 不能；使用自有知识源时单独备份 |
| 浏览器本机状态 | 待同步、复习续做与未保存输入，界面偏好等 | 不能；服务器目录备份也不包含 |
| 目录外 CLI 状态 | 单独配置或默认仓库内的 review 回执、自定义设备文件 | 不能；位置需另外核对 |

默认数据目录是 `data/local`，管理员默认知识是仓库合成 fixture。使用 `LM_DATA_DIR`、`LM_KG_ROOT` 时，以实际配置为准；嵌入服务传入自定义 `dbPath` 时还需保留数据库所在目录。按启动时的参数核对位置，不将本机配置作为公开复现材料。

CLI review 回执默认固定为仓库的 `data/local/cli`，不随 `LM_DATA_DIR` 改变；指定 `LM_CLI_STATE_DIR` / `--state-dir` 时保留对应目录。设备文件默认跟随 `LM_DATA_DIR/cli-session.json`，指定 `LM_CLI_SESSION_FILE` 时另行保留。自定义数据目录的完整备份可能不包含这些 CLI 路径。

## 1. 收拢当前写入

先用当前版本完成“待同步”重试，确认没有未入账记录；超时结果未知的请求保留原 ID 与内容，按[待同步规则](../development/pending-sync.md)核对。无法同步时先保存需要保留的内容并处理错误，不用清队列代替同步。有效列表可能过滤未知旧条目；有损坏/存储警告时，即使计数为 0 也应保留并核查当前来源的原始浏览器存储，不清空它。

保存应用、场景和修正等未保存文本；少量复习可按当前功能完成、结束或保留续做。需要额外交换备份时，可按账号分别导出学习 JSON，注明来源与日期。保留当前浏览器数据；复制服务器目录不能恢复这些草稿，也没有通用浏览器草稿迁移工具。

暂停会写入的 CLI/Agent/KG 触发，关闭项目页面，再用 Ctrl+C 停止 API 与开发服务。`npm run dev` 需同时停止 API 和 Vite；确认你自己的实例已退出，不终止其他项目进程。

## 2. 完整复制到独立备份目录

服务关闭后，复制整个实际数据目录到新建的独立备份位置，再单独复制外部知识根目录和目录外 CLI 状态。不要只复制一个运行中的 `.sqlite`，不要把备份放进知识扫描目录，也不要把两份不同时间的备份混在同一恢复目录。

在本地保留一份记录：日期、源码完整 SHA/版本、Node/npm、系统/架构、原数据目录和规范化知识根路径、启动参数，以及复制了哪些目录。文件清单或 SHA-256 可帮助确认复制完整；备份包含私人知识与凭据，存于本机备份位置，不纳入 Git、Issue 或公开 release。

成员知识在数据目录的 `users/<账号 ID>/knowledge` 中，跟随完整目录保留。管理员外部知识源不会因此自动包含。服务恢复后会轮换 CLI 设备凭据，这是正常行为，不代表学习记录丢失。

## 3. 更新同一运行环境

核对目标版本的[更新记录](../../CHANGELOG.md)、兼容说明及支持平台。已有开发分支使用者沿用干净的 `develop` 工作区：

```bash
git pull --ff-only origin develop
npm ci
npm run build
```

使用预览 release 时，选定其固定 tag/提交，按同一安装流程运行，见[版本说明](v0.0.1-preview.1.md)。保留本地源码修改时先自行保存，避免升级操作覆盖它们。

沿用原 `LM_DATA_DIR`、规范化知识根路径和端口，再执行 `npm start`。切换源码目录时，默认相对数据目录和 fixture 路径可能一起改变；先显式指向原数据/知识位置。管理员与成员的知识空间依赖路径和身份，不把搬根目录当作自动历史迁移。

页面重新登录并加载新构建；所有项目标签页都应刷新到同一版本。CLI 使用当前数据目录生成的设备文件。先核对记录，再恢复自动触发与日常写入。

## 4. 核对后再继续使用

- 原账号能登录，管理员/成员的来源和概念各自正确，成员未看到其他人的知识。
- 已有重温事件的 ID、发生时间和资料版本保持；未知节点没有凭文件时间获得虚构起点。
- 已有观察的回答、曝光、冻结 H/时间指标、应用与处理历史保留；修改当前 H 不应覆盖旧观察。
- 本人固定长期保持仍有效；配置、复习计划、布局及需要恢复的身份绑定符合原记录。
- CLI 与待同步可以使用当前身份；原事件重放不产生第二条学习事件。
- 自建练习卡、题目 / 来源版本和旧回答保留；有场景卡时检查各阶段提示、原答与召回 / 适用理由自评，不能只核对卡片数量。

可将升级前后各账号 JSON 作对照，但 `exportedAt` 会变化；完整目录恢复还要核对 JSON 不能覆盖的账号、知识正文和本机绑定。检查期间不以“重新确认重温”修复缺失状态，因为这会制造新的学习起点。

## 5. 需要回退时恢复匹配的一套

停止新版及所有触发；把故障后的数据和知识另存，保留排查及后来新增记录。不要将旧数据库覆盖到仍运行的服务。

使用备份时对应的源码版本与 Node 环境，把完整数据目录和配套知识源恢复到**原路径**，从一套备份完整恢复，避免把旧目录与当前文件混合。启动旧版本、重新登录，再执行上面的记录核对；旧 CLI token 可能失效，使用重启后当前凭据。

回退会回到备份时刻，备份之后新增的记录不会自动合并。它们是否能经 JSON 恢复，必须先由该目标版本预览和校验；不承诺旧程序能够读取新版格式，也不直接拿旧程序打开已经迁移过的新库。

**跨机器或改变根目录：** 即使复制了数据库，新的规范化路径也可能对应不同 namespace。当前没有完整的跨根路径迁移工具；不能保证仅复制目录就保持原学习空间。学习 JSON 可按支持的唯一相对路径＋revision 映射预览恢复，但不重建账号密码或本机身份绑定授权；单篇概念改名/移动另按[人工身份衔接](../development/concept-identity.md)操作。

## 自动的导入前备份覆盖较小

导入与身份确认前，服务把当前空间的学习 JSON 写到数据库目录内的 `import-backups` 或 `identity-backups`。备份失败就不执行写入；事务失败则回滚，已经生成的备份文件可能保留。相同提交重复请求返回持久化回执，不再次生成备份。

这些自动备份不包含整套账号、知识正文、浏览器状态或完整身份登记，不能代替升级前的完整复制。不要仅凭出现备份标识就认为多账号与知识库已经全部可恢复。
