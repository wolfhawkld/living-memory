# 项目愿景与待澄清问题

日期：2026-09-15。本文是可修订的研究起点，不是已经确认的产品规格。

2026-09-16 更新：用户强调记忆与遗忘机制主导系统开发，并选择先独立 Web、后接 Obsidian。当前开发范围以[首版需求](requirements/v0.1.md)、[技术设计](design/technical-design-v0.1.md)和[开发任务](planning/development-tasks-v0.1.md)为准；下文保留早期研究背景。

进展：用户已要求总结研究并设计系统流程。已形成[共研结果总结](research/consolidated-findings.md)与[个人记忆强化流程 v0.1](design/personal-memory-workflow.md)；其中的时间预算、任务安排和状态表达是本轮设计建议，尚未通过试用确认。

最新进展：用户认可流程大方向并要求分析可视化选型，明确选择**突出空间纵深、较明显发光与镜头运动，桌面优先**。用户查看官方 `3d-force-graph` 示例后确认桌面 3D 原型采用 **`3d-force-graph` + Three.js**，并保留镜头聚焦与关系高亮作为交互方向。据此形成[可视化体验](design/visualization-spec.md)与[技术选型](research/visualization-options.md)，平面阅读模式仍作为配套阅读入口；具体实现细节、组件版本、配色和动画参数仍待原型验证，尚未完成引擎、性能或宿主集成测试。

## 用户已经明确的目标

- 研究人类记忆与遗忘的原理、记忆方法，再做具体实现决策。
- 以可视化知识图谱持续外化、集成、巩固所学知识与个人 insights。
- 通过记忆、查询、使用、总结等任务动态展示并维护状态。
- 视觉表达与审美是核心需求：整体深色背景、有动画的立体图谱，可以先做 2D 版；每个概念/实体用清晰颜色标记当前记忆遗忘曲线阶段。
- 考虑开源供其他人使用，仔细研究架构与扩展性；Obsidian 插件是候选载体。
- 探索促进人脑记忆质量与认知迭代的任务；社交仍是候选方向，尚未确认纳入实现范围。
- 首批材料倾向直接使用自建的 progressive-kg：跨领域、已经学过、部分可能已经会应用的概念知识。
- 日常使用以融入阅读、查询和工作为主，附带少量复习。
- 借助 progressive-kg 的图谱生成与查询通道，隐式完成记忆图谱展示的衰减计算；首阶段在 ChatGPT 中语音交流，要求实际访问图谱资源，未来按 Codex CLI 语音的实际可用性优化入口。首阶段不采用自建 API 语音；具体客户端/host 与资源访问仍待验证，见[事件触发与语音设计](design/event-triggers-and-voice.md)。
- 当前学习主线是 AI 与数学，大量阅读相关概念，随空闲时间不定期观看在线视频以系统理解原理与应用，同时补充其他兴趣领域。
- 用户自述：不少概念仍记得名称、全称和部分原理，但详细内容模糊；工作和研究中面对业务场景与数据建模，常难以快速、准确地想起适用的已学概念。需要专门研究应用场景如何触发知识提取。

## 工作性定义

这里的“知识图谱”暂指带有可解释关系的个人知识网络；是否采用形式化本体、RDF 或图数据库，需要后续研究。

建议将产品价值分为三个可以分别评价的方面：

| 方面 | 用户希望得到什么 | 可观察的结果 |
| --- | --- | --- |
| 外化与整合 | 保存知识、来源和个人理解，找到与旧知识的联系 | 能找回来源；关系可以解释；新旧观点可以比较 |
| 记忆与使用 | 在需要时想起、讲清楚、用得上 | 延迟回忆；无提示解释；新情境中的应用 |
| 认知迭代 | 发现矛盾、修正边界、形成可检验的新洞见 | 记录观点如何变化、为何变化，以及后续验证结果 |

当前首个场景以 progressive-kg 已有概念为材料，保留用户已有的知识投入与跨领域关系。用户对每个概念的当前掌握程度尚未逐项评估；“系统尚无表现记录”只说明证据缺口。

首批材料的结构与接入研究见[progressive-kg 使用场景](research/progressive-kg-context.md)。其他知识类型仍可在后续扩展。

## 当前学习困扰与研究方向

用户报告的表现需要分别观察：

| 任务 | 当前已知情况 | 待研究的问题 |
| --- | --- | --- |
| 由名称解释概念大意 | 不少概念仍能做到一定程度 | 各概念的具体表现与提示条件 |
| 还原细节、推导与边界 | 许多细节逐渐模糊 | 哪些需随时掌握，哪些可借助资料恢复 |
| 由真实场景主动想到相关概念 | 用户明确的困难 | 问题表征、线索匹配、候选提取分别起什么作用 |
| 在候选间判断适用性并建模 | 用户需要的能力；尚未单独观察 | 能否说明前提、排除相似但不适用的方法，并验证结果 |

以上是任务区分，不构成统一的能力等级。将“细节保持”与“场景触发、适用判断”分别研究，有助于识别需要怎样的学习与反馈。理论讨论见[共研 02：从概念记忆到场景调用](research/knowledge-retrieval-and-transfer.md)。

用户提供的具体例子是：设计 multi-agent orchestrator 的意图识别、规则校验与上下文记忆功能时，难以想到用于抽象建模的数学模型/算法。规则校验特指请求是否属于系统服务范围、是否存在安全风险的强制校验。用户明确：举例是为了具象化记忆痛点，不需要解决该工程问题。这个实例已回答，继续作为系统设计的需求背景，不重复索取，也不展开其工程方案。

## 一条待验证的使用闭环

采集材料 → 写下自己的理解 → 连接已有知识 → 在回忆或实际问题中调用 → 对照反馈 → 更新理解与学习记录 → 在合适时机再次遇到。

针对已有概念，更贴近当前需求的候选入口是：选择一个实际问题或主题 → 尝试调用相关概念 → 按需查看 progressive-kg → 解释关系或应用 → 记录发现与表现 → 后续再访。新材料采集是可选入口；先研究怎样利用现有积累。

同一条知识可以有多种任务入口，不必每次都走完整流程。以下是设计假设，尚未做用户验证。

| 任务 | 可能的体验 | 可以记录什么 | 单凭该行为不能判断什么 |
| --- | --- | --- | --- |
| 外化 | 记录一个观点、出处和自己的解释 | 内容版本、来源、待解问题 | 已经理解或记住 |
| 查询 | 找一个答案、来源或相关概念；允许直接查看 | 查询情境、打开的内容、使用目的 | 在无提示条件下能回忆 |
| 回忆 | 隐藏答案后解释概念，或重建一小片图谱 | 题目、提示、回答、反馈、耗时、信心 | 已掌握整个主题 |
| 使用 | 用概念解决问题、分析案例或做决策 | 应用情境、产物、借助的资料、结果 | 能迁移到所有领域 |
| 总结 | 先回忆再对照资料，写出联系与遗漏 | 闭卷部分与查阅部分、修正内容 | 文字流畅就代表理解正确 |
| 认知修正 | 添加反例，限定适用条件，修改旧洞见 | 旧观点、新证据、修改理由、未决问题 | 新版本必然为真 |

真实工作中的快速查找与学习练习都应有入口。是否先尝试回忆，可由用户当下目标决定。

## 状态表达需要先区分的对象

以下是概念边界，用于评审，并非数据库设计：

1. **知识内容与依据**：这一论点是什么，来自哪里，与哪些观点支持、冲突或依赖？
2. **任务表现**：何时、在什么题目和提示条件下，用户完成了怎样的回忆、解释或应用？
3. **模型估计**：根据这些记录，系统预计何时值得复习；估计依赖哪些数据，有哪些缺口？
4. **用户目标**：这条知识是否值得熟记，还是只需要容易查到？当前项目是否需要它？

例如，“读过三次”“昨天无提示解释成功”“在新案例中尚未验证”可以同时成立。应让用户看见这些区别，而不是合并成无法解释的一个掌握分数。

节点关系还需要区分“资料链接”“语义相关”“因果解释”“个人推测”等含义。节点相连本身不构成掌握或因果关系的证据。

知识内容与个人学习记录有不同的生命周期：遗忘趋势不应自动删除笔记，重新理解一个概念也不应抹掉旧版本和修改原因。

## 视觉探索清单

大方向已明确：深色、动态、立体，允许先从 2D 开始；进一步偏好是明显空间纵深、发光与镜头运动，桌面优先。具体配色、布局、动画节奏和操作方式已提出首版方案，仍需在样例中验证；研究原型可以用同一小片真实知识比较以下表达：

| 探索方向 | 想验证的体验 | 需要观察的问题 |
| --- | --- | --- |
| 稳定布局与局部展开 | 在深色背景中保持节点位置和文字可读，逐步展开关系 | 查找、阅读、编辑是否顺畅；展开后能否找回原位置 |
| 空间纵深 | 通过立体布局、分层或镜头聚焦感受知识结构；可先在 2D 验证定位任务 | 遮挡和远近是否影响标签与阶段色；是否容易迷失方向 |
| 任务与状态动画 | 看见查询路径、关系展开及练习后状态变化 | 是否能够区分一次使用事件与长期记忆估计变化；复杂后是否仍可读 |

它们可以组合。先讨论用户希望看见什么变化，再选择表现手段：

- 单次任务：选择了哪些知识，调用了什么关系，哪里需要提示，最后修正了什么。
- 长期变化：哪些知识最近被使用，哪些缺乏回忆证据，哪些洞见出现了新的支持或反例。
- 回忆练习：暂时隐藏标签或关系，请用户补全；练习结束后展示差异。

**颜色的首要语义已确定为遗忘曲线阶段。** 具体阶段名称、数量、阈值和色值尚未决定；它们应来自可解释的估计对象，而不是先画几种颜色再补含义。主题领域、选中状态与临时活动需要研究其他视觉通道，避免覆盖阶段色。2D 与后续 3D 应保持一致的状态语义。

建议将“证据不足/尚未评估”作为独立显示情况。已有概念不应仅因缺少本系统记录就显示为遗忘；同一节点可能包含多项能力，节点整体颜色如何汇总、如何展开细节，需要单独研究。

尤其要检验：名字能触发解释、真实场景却不能触发概念时，一个节点颜色应该表达什么。定义/细节的保持与场景调用可能需要分别查看；具体呈现方式仍未决定。

可读性评审要覆盖中文长标签、色觉差异、减少动态效果、键盘操作，以及大图中的局部聚焦。阶段色应配有图例或可读标签；立体光照、深度渐隐与动画高亮不能让同一阶段难以辨认。动画表现任务与估计变化，不解释为实测神经活动。

## 日常任务与社交候选

用户已选择融入阅读、查询和工作，附带少量复习。候选设计以当前任务相关、可跳过的小练习为主，快速查找保持直接可用；具体时间预算和提醒频率仍待试用。以下丰富使用方式按实际收益与负担决定是否纳入首版：

- 随手捕捉：一句洞见，加一个来源或当前疑问，之后再整理。
- 小片段回忆：讲清一个概念、重建两三个概念间的关系。
- 对比练习：区分两个容易混淆的概念，并各举适用场景。
- 项目使用：把知识关联到正在解决的问题，记录应用结果。
- 周期反思：本周哪些观点变化了？什么证据促成变化？
- 向别人讲解：分享一小片图谱，请对方追问前提、边界和反例。
- 同题讨论：先各自形成解释，再比较分歧与证据。

社交模式需要把共享知识内容、个人回忆表现、公开讨论分开考虑。候选起点是主动分享的主题片段与同伴反馈；公开排名、信息流、团队协作、账号系统是否有价值，仍需验证。

## 待澄清的问题

第一轮已得到的偏好：

- 优先材料：直接使用自建 progressive-kg 中各领域已学过、可能已会应用的概念。
- 视觉方向：整体深色背景、有动画的立体图谱，可先 2D；节点颜色明确对应当前遗忘曲线阶段。
- 使用节奏：融入阅读、查询和工作，附带少量复习。
- 本轮补充：突出空间纵深、较明显的发光与镜头运动，桌面优先。

第一轮三个问题均已答复。下一阶段结合研究和样例逐步细化：

- 具体配色与艺术参考、镜头和光效的舒适程度、立体空间操作方式，以及可接受的少量复习负担。
- progressive-kg 已有 Obsidian 结构；需要进一步了解实际阅读、查询与维护方式，以及希望保留的工作流。其他工具使用情况尚待确认。
- 桌面优先已经确认；具体桌面设备、离线与同步要求、未来手机使用范围仍待细化。
- 主要需要记住哪些内容，哪些只需可查？如何处理价值降低的旧知识？
- 接受多少整理与练习成本？提醒、逾期和暂缓怎样表达才合适？
- 希望社交对象是朋友、学习小组、公开社区，还是暂时以个人使用为主？
- AI 希望参与采集、关联、出题、反馈中的哪些环节？哪些必须自己完成？

上述剩余问题尚未得到答案，不将候选项写成用户已确认的要求。
